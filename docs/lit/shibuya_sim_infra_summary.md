# 渋谷エージェントシミュレーション：インフラ設計 確定事項

> Gemini との議論で確定済み。以下は再検討・再リサーチ不要の前提として扱ってください。

## 1. GPU配置（7× RTX A5000 + RTX 5070）
- **推論ワーカー：A5000 × 6機** — NVLink/PCIe帯域のボトルネックとvLLMの並列制約を避けるため、複数枚を連結せず「1枚＝1モデルインスタンス（独立APIサーバー）」として計6インスタンスを非同期並列稼働。
- **データ処理・DB・RAG：A5000 × 1機** — 行動ログ、タイムラインルーティング、長期記憶のベクトル検索（RAG）、ソーシャルグラフ処理を集約。推論機とは明確に分離。
- **メインPC：RTX 5070** — バックエンドの重い処理はさせず、サーバーとの通信遅延を避けるため「フロントエンド（可視化ダッシュボード・GUI）」専用に割り当て。

## 2. 時間スケール
- **1ステップ＝10分**（人間の最小行動単位：移動・SNS閲覧など）
- 現実30秒＝1ステップ換算 → 現実72分でシミュレーション内1日（144ステップ）が完結。

## 3. 物理層×インターネット層の統合プロンプト
- Redis/ベクトルDBからエージェントIDに基づき「物理状態」「デジタル（SNS）状態」「心理状態」を明確なセクションに分けて取得し、1つのプロンプトにブレンドしてLLMに渡す。

## 4. エージェント自律性
- **IDベースの自発的DBアクセス**：記憶を最初から与えず、思考の第一段階でエージェント自身がTool Use/関数呼び出しでIDを使い外部DBから記憶を掘り起こす方式。高速DB利用のため速度ボトルネックにはならない。
- **非対称「ソロ内省モード」**：単独行動ステップでは、会話時（短トークン制限）と異なり、長文・複数回思考ループ（LOD最高値）を許可した特別な内省プロンプトを実行し、信念（ペルソナ）をDBに直接書き戻す。世界観の変容・大きな意思決定はこのモードで発生する設計。

## 5. VRAM節約・スループット防衛
- **個別睡眠**：エージェントごとに睡眠時間をずらし、「1日の要約」という重い処理を24時間に分散。一斉睡眠によるVRAMあふれを回避。
- **限定APC（自動プレフィックスキャッシュ）**：システム共通のメタ指示部分のみキャッシュ対象とし、ペルソナ・事象データはキャッシュしない（意味論的多様性を潰さないため）。
- **VRAMあふれ対策（速度15〜35倍低下ペナルティの完全防衛）**：出力トークン数制限＋個別睡眠による分散＋Chunked Prefill有効化＋スワップスペース0＋vLLM連続バッチ／待機キューの組み合わせ。

## 6. 採用モデル
- **Qwen3.6-27B-MTP（または3.5）のFP8/4bit量子化版**
  - 高い指示追従性・ペルソナ吸着力
  - MTP（マルチトークン予測）による高速出力
  - 「短トークン制限でテンポよく投稿させる」戦略とMTPが好相性
