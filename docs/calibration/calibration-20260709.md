# 現実整合キャリブレーション(2026-07-09 未明・第13バッチ)

ユーザー依頼: 「シミュレーションを朝7時まで回して、現状のセットアップで現実を正しく再現
できているかを検証し、細かなパラメータをいじりながらキャリブレーションしてほしい。」

体制: 本番プロファイル(conf/production.yaml・100体・mock)30日ランで機械系を測定 →
現実の一次統計バンドと照合(scripts/calibrate_report.py を新設)→ パラメータ較正 →
同一シード再ラン比較。LLM 依存の行動分布は実LLM(ollama qwen3:4b・15体1日)で別途判定。

## 方法

- 測定器: `python scripts/calibrate_report.py runs/<name>`(読み出し専用。L1/L2/agents.json
  から睡眠・労働・交通・経済・事件率・状態を集計し、現実バンド(出典付き近似)と照合)
- 現実バンドは公表統計の**近似**(NHK国民生活時間調査・社会生活基本調査・毎月勤労統計・
  雇用動向調査・労働力調査・家計調査・東京PT調査・渋谷区の刑法犯認知件数など。精密値の
  捏造はしない)。バンド外=即誤りではなく「調律候補」。
- 較正原則: **1シム日=1実日**(calendar 実日開始)なので日次確率は現実の日次値に合わせる。
  ただし件数が 100人×100日 でゼロに退化する機構は、観測性のため**明記した圧縮倍率**
  (≤10倍)だけ現実より高く許す。
- ゴールデン保護: 基底 conf/config.yaml は不変。較正はすべて conf/production.yaml の
  重ね書きのみ。

## 構造所見(パラメータでは直らない・要ユーザー判断)
1. **鉄道が域内移動に使われない**(ride イベント=タクシー/バス専用の設計)。地図が徒歩圏
   2.0×2.0km で住民の通勤は徒歩、電車は来街者の到着タイミングと可視化に効く。現実の
   渋谷住民はトリップの~30%を鉄道で域外へ出るが、シミュ世界は閉じている=スコープ境界。
   将来案: 「域外勤務」ペルソナ+駅への通勤トリップで鉄道乗車を内生化。
2. **夜型シフト+40-60分**(起床中央値7:40-7:45・就寝24:20)。personas の bedtime_min 分布
   由来。roster を一律 -60分すれば 23:20/6:40 に寄るが、データ再生成が要るため今回は
   見送り(渋谷の若年人口構成なら現状も擁護可能)。
3. **地位ジニ 0.16-0.17 は現実の所得ジニ(0.38)より低い**。100日でも 0.164(30日 0.162)と
   **横ばい=mock 下ではマタイ効果の集中が育たない**(地位の入力=主催・売上・被フォロー等が
   mock の行動循環では拡散するため)。実LLM長期ランで再判定すべきで、hierarchy の gain 強化は
   k 実験の統制を汚しうるため要ユーザー判断。

## 見送り判断(現状維持の理由)
- nuisance_prob 0.005: 遭遇 0.15-0.17件/人日は渋谷中心部の体感としてリアル。
- health.onset_prob 0.02: 実測発症 0.0107/人日(年3.9回)=バンド内(罹患中は再発しない
  力学で実効値が下がる)。
- disaster / delay / outage: 強制プローブ(disaster.days=[0]・delay_prob=1)で配線正常を
  確認済み。30日ゼロは seed 運(3系統同時ゼロの確率~9%)。100日での発現期待値=災害1・
  遅延5日・停電2 → 100日ランで確認。
- 賃金・家賃比・エンゲル係数・固定費・降雨頻度: すべてバンド内。
- 立退き30日/破産60日等の制度圧縮: ユーザー既決の観測用圧縮(現実の3ヶ月滞納解除を
  100日ランに合わせたもの)。据え置き。
