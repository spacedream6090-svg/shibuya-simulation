# エンジン群アーキテクチャ計画 — 4層仮説の検証と実装優先度(第32バッチ 2026-07-14・計画のみ・実装なし)

体制: Fable計画 → Opus調査2本([engine-coverage-map.md](../research/engine-coverage-map.md)=リポジトリ全数照合 /
[engine-lit-review.md](../research/engine-lit-review.md)=文献・外部実装)→ Fable統合(本書)。
元依頼: 「人の行動=①知覚→②思考→③意思決定→④行動の4層。LLMに②③を任せ、環境が情報を与える

不足を足し、文献で検証し、効くか・既存実装があるかを判定し、実装不要層を含む優先度計画を出す。
SUMO導入の提案も検討。計画のみ」。

## 0. 結論(5行)
1. **4層分離はトレンドに強く合致**(CoALA・Concordia・AgentSociety・PIANO が同型の分離を採用)し、
   **本シミュは既にその形で実装済み**。ユーザーの言う2モジュールは実在する: 「環境が情報を与える」=
   build_prompt(知覚の器)、「思考→行動の取り出し」= parse_action+routine後退。
2. 61エンジン全数照合の結果 **◎34・○21・△5・×1(90%が実装済み)**。足りないのはエンジンの「数」でなく
   個別の「深さ」。「将来枠」とされた Political は実際には最も厚い(3ルート制度改変+議会+供託金)。
3. 最難関とされた行動取り出しは「厳格JSON」でなく**寛容な正規化+非LLM後退(D16)**で解決済み
   (fallback率 実測0% @ qwen3:4b/8b/ablit)。残るリスクはモデル交換時=制約付きデコードのノブで保険を掛ける。
4. **SUMO は本体不採用**(歩行者に不向き=stripingモデルは渋谷スクランブルの高密度双方向を表現できない)。
   正しい分業は「LLMが目的地・意図、専用群衆エンジンが物理移動」= Social Force 系を将来デモ用に差す。
5. 優先度は P0(済み)/P1(本選前に効く)/P2(本選後・長期動態)/**P3(実装不要層)** の4段(§4)。

## 1. 4層仮説の検証結果(文献 × 現実装)

| 4層 | 文献の対応(lit-review §1) | 現実装(coverage-map §13) |
|---|---|---|
| ①知覚 | Concordia=GMが観測を配信 / OASIS=環境サーバ+推薦が「見えるもの」を制御 | scheduler の知覚組み立て(hearers_of・feed・retrieve・日付/天気/世界観行)→ build_prompt。**入力解像度LODはこの層の個体差**(今夜I3検証中) |
| ②思考 | LLM 中核(全システム共通) | drive発火(いつ考えるか)→ deliberate=LLM生成。夜は reflect(k=研究主軸) |
| ③意思決定 | AgentSociety=**Tool層が行動抽出を専任** / CoALA=構造化行動空間 | parse_action(寛容正規化: 別名キー吸収・数値クリップ・途中切れJSON修復)→ 失敗時 routine.decide(非LLM) |
| ④行動 | Concordia=GMがNL行動を検証し具体効果へ翻訳(接地) | _apply(move/speak/post/tools)→ factors/update(経験→状態)→ L1記録 |

- 効きの証拠: Generative Agents の ablation(反省を除くと48時間で反復に退化・「記憶の有無の差は
  LLMバックボーンの差より大」)= **モジュール分離そのものが結果に効く**。
- **MobiVerse**(2025)=「非LLM日課生成+LLM修正」ハイブリッドが両極端に勝つ — 本シミュの
  routine+発火LOD 構造の直接の実証文献。設計は偶然でなくトレンドの本流にいる。

## 2. 層の再構成(提案・採否はユーザー)
ユーザー提示の9層は照合に十分機能した。恒久の整理としては、文献(CoALA/Concordia)と実装の実態に
合わせた **5層** を推奨する(7層案・4層抽象案とも互換=対応を併記):

| 提案5層 | 含むもの(元の層) | 4抽象への対応 |
|---|---|---|
| **Agent層** | Human(知覚・記憶・思考・感情・人格・健康…) | State+Decision |
| **World層** | City+Environment+Space(舞台: 地図・交通・天気・災害) | State(環境側) |
| **Society層** | Economy+Information+Organization+Society+将来枠(制度・市場・情報・文化) | Interaction |
| **Dynamics層** | Integration+Time(行動反映・波及・時間進行・世界モデル) | Evolution |
| **Meta層** | 観測・再現性・実験マニフェスト・較正(研究基盤・Fable追加) | (研究者frame=系外) |

「社会=情報遷移システム」(Environment/Entity/State/Behavior/Interaction)の読み替えは、
**現実装が既にそのモデル**: Entity=agents/orgs/POI、State=agent状態+L3スナップ、Behavior=routine/deliberate、
Interaction=hear/transmission/opinion/市場、Environment=world/。名前の張り替えはコストのみが実なので、
**コード再編はせずドキュメントの対応表として固定**するのが最小コスト(docs/module-map.md に1節追記)。

## 3. 最難関「思考→行動の取り出し」の強化計画
- 現状の解: プロンプトで JSON 契約(キー厳守・行動語彙 speak/post/dm/coin_label/wander+装備節)→
  parse_action の寛容正規化 → None なら fallback イベント+routine 後退(**世界は必ず進む**)。
  実測 fallback 0%(qwen3:4b/8b・ablit 4b-v2、今夜のスモーク含む)。
- 文献の警告: 4B級のスキーマ遵守は一般に不安定(Llama3.2-3B でパース率47.8–56.5%、Gemma3-4B は
  スキーマ遵守87%)。我々の0%は「フラットで小さい行動空間+寛容正規化」の成果だが、**モデルを
  替えた瞬間に壊れうる**(マルチLLM対応・router導入済みの今こそ保険が要る)。
- **計画A(推奨・小)**: `model.format_json` ノブ(既定OFF)で ollama の `format`(構造化出力強制)を
  有効化できるようにする。router の子ごとに指定可。既定OFF=ゴールデンL1バイト一致は不変。
- 計画B(本選): vLLM 艦隊では `guided_json` を同じノブから配線(multi-model-lod M系と同じ波で)。
- **計画C(不採用と明記)**: 「自由記述の思考→別LLM呼び出しで行動抽出」の2段方式は、呼数2倍=
  R1(k-blind)違反+レイテンシ倍で棄却。Concordia型のGM集約も規模(数百体)でボトルネック。
  思考の可観測性が欲しくなったら「JSONに thought キーを足す」(1呼のまま)が正道。

## 4. 実装優先度(効くか × 既存実装 × 本選価値)
判定基準: (a) 研究課題 R²(k)/k* への直結度 (b) 文献の ablation 証拠 (c) 本選デモ価値
(d) 100日ランで動態が発現するか。

### P0 — 既に在る(34エンジン◎)=追加実装不要
Integration層4/4・Meta層4/4・Human層8・Political/Reputation/Governance(名目「将来枠」)ほか。
詳細は coverage-map §14。**「エンジンが足りない」問題は存在しない**。

### P1 — 本選前に効く(小さく・要ユーザー承認)
1. **行動取り出しの制約付きデコード**(§3 計画A)— 0.5日。マルチLLM時代の保険。
2. **群衆物理(Social Force)**— スクランブル交差点の歩行者流をデモ品質に上げる唯一の欠け。
   PySocialForce / 学習型 ShibuyaSocial(実軌跡・位置誤差0.07m)を lit-review §3 から検証。
   LLM=意図・群衆エンジン=物理の分業で R1 非抵触。ライセンス・計算量の検証込み 1-2日。
   ※研究(k*)には効かない・デモ(視覚忠実度)に効く、と正直に位置づける。
3. **Skill(技能蓄積)**— △の中で唯一 Human層の穴。ただし「生得 vs 機会」に第3軸(蓄積)を
   足すことになり **R²(k) の解釈を変えるため研究設計との整合を先に討議**(実装は簡単、意味が重い)。

### P2 — 効くが本選後(長期動態系・100日で発現しない)
Urban Development(再開発)・Demography動態(出生死亡)・Migration(住居移転)・住宅市場・
金融市場・Supply Chain。共通項=「状態が時間で構造的に変わる長期動態」。1年以上の
シミュ or 10万体スケールで初めて観測に乗る。SUMO(背景車両の高度化)もここ(限定オプション)。

### P3 — 実装不要層(作らないと決める)
- **Ecology(生物生態系)**: 唯一の×。渋谷都心の人工社会という研究対象に効かず、都市LLM-ABMでの
  採用例も未確認。**作らない**。
- **深さを足しても観測が無いもの**: 医療の治療転帰・警察の捜査プロセス・メディア産業の内部構造・
  原材料/エネルギー収支・企業間投入産出の精緻化。イベントとして観測されない深さはK計測に寄与しない。
- **2段行動抽出・GM集約**(§3 計画C): R1違反のため機構として不採用。

## 5. SUMO・群衆モデル・ゲームAI・RL の採否所見(lit-review §3)
- **SUMO**: EPL2.0・車両/信号は有力だが歩行者は striping モデル(歩道拘束)で渋谷の主役=歩行者流に不向き。
  TraCI はソケット往復がスケール時のボトルネック。**本体不採用・背景車両の将来オプションのみ**。
- **群衆モデル**: Social Force(Helbing)系が第一候補(P1-2)。ORCA/RVO2 は回避特化で補助。
- **ゲームAI(GOAP/BT/utility)**: routine.decide の高度化に将来使える(非LLM日課の質)。ただし現 routine
  は較正済みで壊す理由がない=**必要が出るまで見送り**。経路探索は実装済み(routing.py)。
- **RL**: LLM併用の行動学習は研究として面白いが、決定論・再現性(CRN/ゴールデン)と根本的に相性が悪く、
  ハッカソン内では**不採用**(本選後の別トラック)。
