## 1. 設計の主軸(リサーチの結論)

**形成=LLMの判断(A案)+観測=ログからの独立導出(C案併設)のハイブリッド。**

- **A案の直接前例=OASIS**(camel-ai・100万体Twitterシム・vLLM): エージェント活性化1回=
  LLM呼1回の構造化出力に、投稿・いいね・**follow**等の行動選択を同居させる。追加呼ゼロで
  「LLMが関係を決める」が100万体規模で実運用済み。
- 構造化出力への**二値判定フィールド追加は最も劣化に強いカテゴリ**(文献)。緩和策=
  「本文が先・判定が後」のフィールド順序。1-2フィールド追加でparse率が落ちる定量報告は無し。
- **明示判定呼(B案)は非推奨**: 前例薄+cap制下で数千呼/日の純増(バッチ判定で1/10-25に
  圧縮しても)。判定精度を独立最大化したい将来の予備として記録。
- **C案併設が独自価値**: 対話ログの4信号(新規話題・承認・往復性・感情トーン)+半減期減衰から
  関係強度を**観測側で独立導出**(Learning to Make Friends 2025=実SNS網統計に最合致)。
  **LLMの宣言と、ログ由来の関係強度の突合そのものが検証データ**になる(シム不触・事後スクリプト)。
- **警告(文献)**: LLMに「誰と繋がるか」を選ばせると名前トークンバイアスで網が歪む
  → 本設計は判定対象が**対話相手に固定**(候補選択なし)なので構造的に回避。

## 2. 機構仕様 v2

### 知り合い(contacts=DM可・双方向)
| ch | 形成 | 文献根拠 |
|---|---|---|
| C1 | **対話成立ペアのみ**: 返答者のreply呼の構造化出力に `relate`(この相手と知り合いになるか・二値)を追加(本文の後)。true→双方向contacts。傍聴者は形成ゼロ(記憶のみ=伝播不変) | OASIS方式・会話当事者限定はMilgram(会話1.5人 vs 顔見知り4人)と整合 |
| C2 | 同居・同僚: 現行(1人最大3人・有界) | 既存 |
| C3 | 顔なじみ昇格: 同一相手と**5回目の遭遇**で挨拶級のcontacts(Moreland-Beach 5回で有意・Bornstein 10-20回飽和・Milgram平均4人) | 中 |
| 上限 | **200**(アクティブ関係150-250帯・closeness最弱を押し出し) | Dunbar帯+Killworth 290/会話維持100-200 |

### フォロー(follows=タイムライン購読・片方向)
| ch | 形成 | 文献根拠 |
|---|---|---|
| F1 | 初期k=6(現行。対数正規化はv2プール再生成と同窓の別件) | — |
| F2 | C1と同じreply呼に `follow`(二値・本文の後)。**宣言した側だけ**が片方向フォロー(相互化は自動にしない=全網相互率22.1%を事後検算アンカーに) | Kwak 22.1% |
| F3 | タイムライン発見: いいね時に確率 p_d で著者をフォロー。**p_d初期値0.02**・較正目標=**新規フォロー0.03-0.3件/日/人**の現実バンド(TRF実測: 露出あたり7×10⁻⁵-2.4×10⁻³・新規フォローの17-42%が露出由来) | 中 |
| 上限 | 名目500(重い尾は許容・安全弁)・アンフォローは本選後(OASISも減衰なし・10日では影響小) | Myers-Leskovec(形成:削除≈3:1) |

### 消すもの・変えないもの
- scheduler.py:3852「hearer全員add_contact」→ C1へ置換。
- `hearer.remember`(聞いた内容の記憶)は**不変**=新語・情報の対面伝播は死なない。
- 第116 follower_count O(1)逆索引・5経路不変条件は維持。

### 観測(C案併設・シム不触)
- L1に `follow`/`relate` イベント(kind追加=schema+causalityの2箇所作法)=随時記録。
- 事後スクリプト: ログ由来の関係強度(4信号+半減期)を導出し**LLM宣言との突合表**を出す
  (SNC-4・本番後解析でも間に合う=クリティカルパス外)。

## 3. 事後検算アンカー(A/Bと本番で見る)
1. 新規フォロー **0.03-0.3件/日/人**(超過=過密化サイン。Generative Agentsの密度0.167→0.74が反面教師)
2. 相互フォロー率 ≈**22%帯**
3. フォロー分布に重い尾(完全グラフ化しない)・contacts中央値が数十
4. RAM: SNS層が250k外挿で10GB級

## 4. mock検証の作法
mockバックエンドは `relate`/`follow` フィールドを出さない→パーサは欠落=false(安全側)。
容量A/BのためmockにC1/F2相当を演習させる場合は、mock応答生成に決定論ハッシュで
低確率のtrueを混ぜる(専用conf・実LLM経路には無関係)。

## 5. コスト
追加呼ゼロ。reply出力+2フィールド≈+20-40tok/呼(全体の~2%出力増)。プロンプト変更は
prompts.p1系(reply用途ヘッダ)に判定の説明2行=P1トグル配下。
