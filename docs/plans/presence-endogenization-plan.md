# 在場内生化計画(PRES) — 「世界のアルゴリズムがエージェント量を決めない」の実装

> 入力: ユーザー原理(2026-08-12)「範囲内にいる人の数もこちらが指定するものではない…エージェントの移動についてもエージェントの推論で決めたり、もしくは予定に従って行動し、範囲内に存在するのか判別…世界のアルゴリズムによって結果が左右されたり、エージェントの量が決まったりすることはなく、エージェントの行動や思考、推論によって結果が現れるような状態にしたい」+職業多様性の指摘。
> リサーチ正典: [presence-endogenization.md](../research/presence-endogenization.md)(URL約30本・プール100万全数集計)。**実装はユーザー承認後**。

## 0. 現状の違反点(実測)

1. **cap切り**: 平日資格者306,716人を cap 250,000 に収めるため**18.5%を日替わり決定論くじで落とす**([presence.py:196-222](../../src/society/world/presence.py))=従業員が理由なく欠勤する・その理由が本人の状態でなく世界の抽選。
2. **stochastic層の単純抽選**: 定期でない来街者は `visit_rate × 乱数draw`=個人の目的・習慣の関数ではない。
3. **★バグ(リサーチ発見)**: `_days_match` の未知仕様フォールバックで、名簿が「mon-sat」勤務と宣言する **44,486人が土曜に出勤資格を失っている**(名簿の意図と機構のズレ=週末在場が実測比0.59に落ちる一因)。
4. **職業5種問題**: L2通勤者224,240人の職業名が5種(エンジニア/デザイナー/PM/営業/コーポレート)のみ。台帳は業種コード・sector_detailを実在で持つのに生成器が読んでいない。

## 1. 設計原理(リサーチの結論)

- 学術正統は**活動ベース需要**(MATSim/ActivitySim/TASHA/CEMDAP・日本ではPseudo-PFLOW=1.3億人実証): 「人口合成→**個人の活動スケジュール**→トリップと在場が創発」。トリップ発生をレート表やcapで与えるのは前世代(four-step)の作法。
- 100万人へのLLM推論は呼数の物理で不可能 → **「本人の予定・習慣・状態の決定論関数」=行動由来**が現実解(勤務表方式は既にこの形)。在場中の圏外判別は境界計画(Wave 2)が既に個人の計画で行う。
- 日次の揺らぎは乱数でなく**天候・曜日・イベント**(実測: 雨で来街−5〜−29%)で入るのが原理適合。
- 較正はCadyts流=観測とのズレを**個人の習慣パラメタ**へ帰す(世界側のノブに帰さない)。
