## 1. 大枠の結論(業界調査から)

1. **結合の一般則**: DT×社会シムの結合は「**一方向・事後**」(DTから幾何を取り込む/DTへ結果を書き出す)なら
   本プロジェクトの不変原則(決定論・観測がシムを変えない・L1事後観測)と全て整合する。業界の花形である
   「**双方向・リアルタイム同化**」は全て壊す。→ 我々が取るのは前者に限定。これは制約ではなく差別化
   (再現可能な社会実験は、リアルタイム同化型DTには原理的に作れない)。
2. **業界の空白**: 商用DTのエージェントは (a)ロボット/車両 (b)映像解釈の運用支援AI のみで、
   「**なぜその人がそこへ行くか」を内生的に決める層は商用DTの外側**にある(AUDiTs, Urban Informatics 2026 も
   「既存都市DTは社会的複雑性を過小表現」と明記)。我々はその層そのもの。
3. **相互運用の現実**: 幾何(CityGML/3D Tiles)と軌跡は標準があるが、**社会的エージェント状態を交換する標準は
   世界に存在しない**(USD/IFC/CityGML/3D Tiles/DTDL/FMI のいずれにも無い)。よって提出物・論文では
   「Digital Twin」を安易に名乗らず「**Digital Model(一方向・事後結合)である**」と正確に言う方が強い
   (Kritzinger 2018 の DT 分類)。
4. **国内接点**: PLATEAU 配信サービス(3D Tiles/MVT/CityGML 無償API・ただし「試験的運用・SLA無し」明記=
   **決定論維持には事前スナップショット固定が必須**)・富士通ソーシャルデジタルツイン(行動経済学ベース=
   LLM ではない=競合でなく補完)・東京都点群(商用可)。人流商用データ(モバイル空間統計等・125〜500m格子)は
   較正/検証用途のみ有効。
5. **戦略的空白=合成データ**: 我々の L1 ログは「決定論で再生成できる・内生的な OD と会話に駆動された
   人間行動データ」であり、産業側(Cosmos/Metropolis 系)が自前で作れない種類の合成データ。
   3D Tiles/USD で吐ければ「DT エコシステムへのデータ供給側」に立てる。

## 2. 結合類型と採否(詳細は dt-landscape.md §5-6)

| 類型 | 内容 | 採否 |
|---|---|---|
| ① 可視化/リプレイ層としての DT | L1→3D 再生(既存路線) | **採用・強化**(P0/P6/P1/P2) |
| ② 幾何/環境データ源としての DT | PLATEAU 取り込み(既存・A1 で実高さ済) | **採用済・継続**(道路 LOD3 歩道が次) |
| ③ 物理エンジンとしての DT | SUMO 連成(既存・決定論条件つき) | **採用済・深化**(P5)。商用(Vissim/Aimsun)は非決定論制御不能のため不採用 |
| ④ センサー実データ同化 | リアルタイム流し込み | **状態同化(シム状態の書き換え)はラン中不採用**。較正フェーズは P7。**一方向強制(天候等・状態非書き換え)は journal 等級で採用しうる**=[dt-snapshot-integration-proposal.md](dt-snapshot-integration-proposal.md) §2(2026-07-31 訂正) |
| ⑤ リアルタイム双方向連成 | 業界の花形 | **不採用**(決定論と R1 を壊す) |
| ⑥ 合成データ生成側に立つ | L1→3D Tiles/USD 供出 | **採用**(P1'/P4'・安価) |
