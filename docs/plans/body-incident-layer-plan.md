> 入力: ユーザー指示(2026-08-11)「救急はエージェントが倒れ周囲が通報して動く形に。エージェントの思考に関係ない事件・病気の実装も視野に。検討→Webサーチ→計画」。
> リサーチ3本(疾病/EMS実数・事件モデル・リポシーム監査)統合。**2026-08-11ユーザー承認済み(§6)=H1〜H5全レーン実装**。
> 規律: 全て既定OFF・goldenバイト一致・新乱数は新stream・LLM呼数増分ゼロ(身体は物理・選択は既存認知)・凍結14本不触。

## 0. 設計原理 — 三層の因果

```
身体(physics)     : 発症・悪化・回復・倒れる — 思考と無関係に起きる(cause_type: physics)
行為(agent)       : 通報する・介抱する・受診する・拾って届ける・出勤を強行する(presenteeism)
応答(agent/device): 救急隊・病院・警察・保守会社 — 通報に応答して動く(スケジュールでは動かない)
```
既存の因果台帳語彙(physics/agent/device/natural)がそのまま受け皿になる。「運(chance)」だけが原理の外に残っており、本計画で溶解する(§4)。

## 1. 身体レイヤー H1: 重症度の状態機械(healthの世代交代)

**S0 健康 → S1 軽症 → S2 中等 → S3 重症 → S4 心停止 → {回復, 死亡(承認済み・現実量較正=§6-1)}**

- 現行 `sick: bool` を置換(illness イベント契約に**未使用の `kind?` フィールドが最初から予約されている**=スキーマ無風)。既定OFFでは現行ブールと完全同値の互換写像。
- **発症チャネル**(各=独立ハザード×共変量・全て新stream・実数較正):
  - 急病(風邪/インフル系): 現行onset_probの後継。S1-S2帯。回復3-7日。
  - **熱中症**: λ(WBGT)閾値関数(32°C以上で急峻・都の日次搬送データで外部検証可能)。`sim.today_weather["wbgt"]` が**既に存在し誰も読んでいない**=シーム敷設済み。屋外・高齢で増幅。
  - **急性アルコール**: 飲酒活動(nightlife滞在)でのみ活性・20代ピーク・金土夜/12月増幅。74%軽症。
  - 外傷(転倒): 高齢重み・混雑/夜間で増幅。
  - 心停止/脳卒中: 極低率(渋谷実測 OHCA≈0.5-0.7件/日)・年齢帯レート必須(全国率の直適用は禁忌=渋谷の街頭人口は20-40代)。
- **frailty**: 年齢帯の通院者率(65+=70%)から導出するseed純関数スカラーが全ハザードを乗算。**ageを健康が読むのは初**(監査でグリーンフィールド確認済み)。
- **sick-role**: S1は**予定を守って出勤**(日本の実測=45%が病気でも出勤・presenteeism優勢)+性能デバフ。S2で受診/停留の選択(既存 `_sick_home` プリミティブ=災害と共用済み)。S3+で行動不能。
- **EMSトリガの世代交代**: city_opsの `_collapse_gate`(ハッシュゲート)を「S3/S4への遷移そのもの」に置換 — city_opsのdocstringが**最初からこの置換を本筋と宣言している**。通報チェーン(倒れる→近くの人が通報→出動)は完成済みで、トリガだけが本物になる。
- **傍観者モデルの較正**: 集団レベル P(誰かが行動)≈0.85-0.95(実CCTV研究=介入が規範・91%)。曖昧な軽微状況のみDarley-Latané型の人数減衰(α≈0.4)、危険事態はα≈0(メタ分析根拠)。関係者(家族・同僚)は倍率>1。通話時刻分布: 46%<1分/29% 1-5分/25%>5分。
- **重症度は搬送先で確定**(東京実測=搬送の52.8%が軽症)。「通報は不確実性から生まれる」を再現=全通報が重病ではない。
- **修正同梱バグ**: `sick_until` がプール回転の dehydrate/hydrate に不搭載=住民が回転で病気を忘れる(監査発見)。severityと同時に搬送リストへ。

## 4. chance_event の溶解(懸案OPEN#5への原理的回答)

- windfall → **「拾得者になる」**(届ければ報労金・着服なら犯罪=行為の分岐)。★拾得金は必ず誰かのdropから=貨幣保存則(IF-Eゼロ和検査)と整合。
- loss → **「遺失・盗難の被害者になる」**。★監査の発見: 現行chance lossは未較正で**theftの約26倍の頻度**(theftは実測較正済み2.8e-5/人日)=溶解はバランス是正でもある。
- encounter → 既存の共在イベントで代替(causality.pyに「ユーザー判断待ち」注記が既に刻まれている箇所)。
- 結果: **「運」カテゴリの廃止**。chance.pyはfeature-flag期間を経て退役。

## 6. ユーザー決定(2026-08-11回答・全4件確定)

1. **死の表現=実装する。ただし「シミュレーションの範囲内で起こる現実的な量」のみ**。→ mortalityはH1トグル配下に含め(別オプトインにしない)、量は較正で担保: 搬送の1.3%死亡・OHCA生存退院≈10%・火災死1人/年スケール(10日ラン期待値=数件)。死=境界despawnと同型の永続退場+L1 1行+causality(cause_type=physics)。尊厳規約=中立語彙・演出ゼロ・重度分布と同時較正(§7の災害映画化防止がそのまま適用)。
2. **chance_event廃止=承認**。ユーザー原理(原文): 「あらゆることに運は見出せると思うし、それは世界のアルゴリズムがそうであったからではなくて、人の行動によってそのほとんどが引き起こされていると思う。なので運をコードで表現、作成するのではなくて、エージェントの行動であったりによってたまたま発生するようにしたい」— §0三層因果の完全な追認。§4の溶解を実行する。
3. **フェーズ配置=全部実装**(案A/Bの二択を超えて「多分全部の実装できると思う」)。**H4はエージェントドリブンで設計**(=RAT収束: 加害者の動機状態×標的×監視者不在の共在=全てエージェント状態から。レート抽選の残滓を残さない)。H1〜H5全レーン起動・全て既定OFF着地・ONセット合成は縦煙時に判断。
4. **保険=命名RoWチャネル方式=承認**(「多分OK」)。

## 7. リスク(要点)

- **事件インフレ=災害映画化**: 多くの族は「今日は何も起きない」が正しい日が多い(火災0.66件/日・ほぼぼや)。重度分布を頻度と同時に較正・面白さのための増量は較正破壊。
- **分母の罠**: 区の遭遇率は夜間人口分母。犯罪・事故は人口比でなく**共在機会比**で較正(来街ピークで事件過剰になる)。
- **年齢構造**: 全国レートは75+支配。年齢帯レートなしの直適用は脳卒中過剰・外傷過少。
- **管轄混同**: 渋谷署≠渋谷区(3署)・消防も同様=3倍ズレの源。較正表で署/区/都を明記。
