# 混合モデル運用計画(MIX)— 14B思考層+会話への個体単位ランダム割当

> 2026-08-17作成。ユーザー指示「案Aベース+余剰があれば会話にも14Bをランダムもしくは何かしらのいい方法で。
> 一旦webリサーチして結果と計画を提示」への回答。リサーチ2本(学術+運用)の統合。
> 前提: chat経路化(第138)済み・A8三モデル同一束採点済み(parse全員100%・JSD微小・実効 8B≈4.0/14B≈2.3呼/秒)。

## リサーチの結論(要点)

### 学術レーン
1. **直接前例は1件**: AgentScope大規模シム(arXiv:2407.17789)§4.6が100万体・3モデル混在を実施。
   結果=**モデル別に行動がクラスタ化**(混在は中立ではなく「処置」として振る舞う)。
   主要社会シム(Generative Agents/OASIS/AgentSociety/Project Sid)は**全て単一モデル**。
   Voyager(コード生成のみGPT-4)・AgentTorch(代表個体のみLLM)=機能・重要度splitの先行。
2. **「モデルサイズ異質性が情報伝播・規範形成に与える影響」を主目的に測った研究は空白**
   =事前登録つきランダム混在なら、この空白自体を副次的な研究成果にできる。
3. **割当方式の実験設計**:
   - ランダム割当=外生的。処置効果(14Bが個体の社会的軌跡に与える効果)が推定可能な唯一の方式。
   - 重要度ベース(焦点個体)・文脈トリガ(会話の深さで昇格)は**内生的=k*主張を直接汚染**
     (「世界を変える個体が創発した」vs「大モデルを引いただけ」が分離不能になる)。
   - **呼単位でなく個体単位**が正: 呼単位だと同一個体の行動一貫性を処置が壊し、効果も蓄積しない。
     個体単位=ABMのbounded rationality異質性文献に直結する自然な解釈+14B群/8B群の層別比較が成立。
   - ルータ/カスケード文献(RouteLLM/FrugalGPT/Hybrid LLM)の難易度推定は「正解のあるクエリ」前提
     =会話に教師信号がなく転用不可。転用するのは「**閾値1つ(比率p)で余剰に追随**」の機構のみ。

### 運用レーン
1. 1GPU=1モデル=1 vLLMプロセス+アプリ側sticky=定石(vLLM #13633=複数モデル/GPUはnot planned)。
   24GBでの2モデル同居はKV(=prefix cache実体)が消滅するため不採用。
2. **14B-AWQは高並列でほぼ伸びない**(vLLM #20469: 並列10以降頭打ち=AWQ Marlinカーネル)。
   実測2.3呼/秒は理論比(重み1.75倍)どおり=妥当。並列64-128で劇的改善の報告なし。
3. **投機的デコード=不採用**(高並列でEAGLE 1.96倍→batch128で1.21倍・32+並列で逆効果。
   AWQ併用はバグ帯 #23464/#25883/#28940。低並列レイテンシ用途が生じたときのみ再検討)。
4. prefix cacheはモデル(サーバ)間で完全独立。14B集約側はeviction圧が高くヒット率低下前提。
5. OASIS等も「purpose別エンドポイント+アプリ側割当」=現行設計は業界標準と同型。

## 決定済み(ユーザー)/ 提案(承認待ち)

- **決定済み**: 案Aベース=14B=reflect/plan tier。余剰があれば会話にも14B。
- **提案1(割当方式)**: **個体単位・決定論ランダム割当**
  `blake2b(agent_id, salt=mix) < p` の個体の deliberate 系呼を14Bプールへ。ラン中固定・
  外生・manifestに規則+saltを記録(=事前登録)。層別の明示バランスはしない
  (25万体ではハッシュの大数近似で職業・地区の偏りは微小)。
  k*分析は14B群/8B群を層別報告(処置ランダム化された自然実験)。U-10承認時に割当規則を同梱。
- **提案2(GPU配分)**: **会話=8B×5(GPU0-4)+思考=14B×2(GPU5-6)**
  思考需要(呼7%×速度比1.74≈会話換算12%)は14B×1でも覆えるが、2本目が
  (i)会話ランダム割当の容量 (ii)AWQ高並列頭打ちへのヘッジ (iii)eviction緩和 (iv)片系冗長。
  会話が飽和するなら「8B×6+14B×1・p縮小」へ縮退(conf 1行)。
- **提案3(比率p)**: リハーサル実測から保守側で確定(仮置き p=0.10-0.15)。
  静的見積: 14B×2=4.6呼/秒−思考需要≈1.5呼/秒=余剰≈3.1呼/秒 → p上限≈0.2。
  **pはラン中固定**(外生性の保持。「余剰に動的追随」はしない=割当が負荷と相関すると内生化するため)。

## 6+1 vs 5+2 の所要時間比較(ユーザー要求・2026-08-17概算)

前提: T10=1,440step・呼数はcap拘束(cap×1,440=総呼数)・purpose比=会話93%/思考7%・
単GPU実効=8B 4.0(楽観)/2.5(保守)呼/秒・14B 2.33/1.5。レーン並行なのでstep壁時計=遅い方。

**LLM成分(cap=1,500)**:

| 構成 | 楽観 | 保守 | 朝plan バースト耐性 |
|---|---:|---:|---|
| 6+1(p=0) | 23.2h | 37.2h | 弱(朝step思考30%なら14B×1が律速=最大+11h) |
| 5+2(p=0.10) | 25.1h | 40.2h | 強(+5h程度で吸収) |
| 5+2(p=0.15) | 27.0h | 41.9h | 強 |

cap=2,500は×1.67。エンジン成分27.6-52.2hを加えた総T10はどの構成も51-92h(cap1,500)/
66-120h(cap2,500)=**GO線140h以内**。**時間差は総T10の2-4%で決着がつかない**。
決め手は「会話ランダム割当(=混在実験)をやるかどうか」そのもの。実測はMIX-3で。

## 見送り(理由の記録)

- 重要度・文脈トリガ割当: 内生的=k*汚染。採るなら別ラン別腕として事前登録(本選はやらない)。
- Swallow: parse同点・速度1.8倍・JSD最大・接地ムラ・非AWQ=3系統運用の重さに見合わない。
  日本語らしさの導入は本選後にreply tier限定で再検討可。
- 投機的デコード・1GPU2モデル同居: 運用レーンの知見どおり不採用。
