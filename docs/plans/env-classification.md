# 環境要素の分類 — 共通基盤/共有参照/環境固有 × 地理/抽象(第35バッチ 2026-07-17)

体制: Fable設計 → Opus棚卸し([env-asset-inventory.md](../research/env-asset-inventory.md))→ 実装(D1→D2)。
元依頼: 「環境自動生成は地理だけでなく**精度などの抽象的なもの**も含めたい。**共通化できる要素は
なるべく共通化**したい。実装前に、共通要素と自動生成すべき要素を分け、その中で地理的なものと
制度・職などの抽象的なものに分けてほしい(分類の仕方は任せる)」。

## 0. 分類の設計(結論)

2分類(共通/生成)では「共通化をなるべく広く」の要請に応えられない。**3層**にする:

| 層 | 中身 | 実体 | 共有範囲 |
|---|---|---|---|
| **①共通基盤(Foundation)** | 機構=コード。場所の知識を含まない | src/society(認知・人格・社会・経済・制度・観測・エンジン・LLM抽象) | 全環境 |
| **②共有参照(Shared Reference)** | 国・言語スコープの共通テーブル=**一度作れば全環境で使い回す値** | ref/ (新設): 47都道府県制度表・祝日暦・全国較正バンド・言語既定語彙 | 同一国・言語の全環境 |
| **③環境固有(EnvPack)** | 場所ごとに生成するデータ+値 | env/<place>/(env.yaml+データ束) | その環境のみ |

鍵: 従来計画(foundation-extraction.md)の「機構=基盤・値=環境」を一歩進め、**値の中にも共通化
できる層(②)がある**と認める。例: 最低賃金1,226円は「渋谷の値」ではなく「東京都の値」であり、
47都道府県表(②)+ env.yaml の `pref: tokyo` という**セレクタ1行(③)**に分解できる。
これで環境パックは薄くなり、自動生成の対象は「本当にその場所でしか決まらないもの」に絞られる。

## 1. 全要素の分類表(③環境固有の内訳は 地理⇔抽象 の2軸)

### ③-A 地理層(具象・座標を持つもの)
| 要素 | 生成方法 | 自動化 | 既存資産 |
|---|---|---|---|
| 道路網・建物・POI・フロア(map.json) | OSM Overpass → build_map | 容易 | build_map.py(bbox汎用化が必要) |
| 交通ダイヤ(transit.json) | ODPT/GTFS → build_transit | 中(無ければ「徒歩の街」縮退) | fetch_odpt/build_transit_odpt(駅名フィルタ汎用化) |
| 注目原点(origin=群集・観測の中心) | 地図から最大交差点/広場を機械選定+人手確認 | 中 | annual.gathering_node(現状スクランブル直書き) |
| 広告スポット(ads) | POI から大型ビジョン相当を抽出 | 中 | conf ads(QFRONT等直書き) |
| ゲートウェイ・駅接続 | 地図から自動導出 | 容易 | 実装済み(場所非依存) |

### ③-B 抽象層(座標を持たない・場所/文化/精度)
| サブ層 | 要素 | 生成方法 | 自動化 |
|---|---|---|---|
| **人口・社会** | ペルソナ分布(年齢×職業×世帯)→名簿 | e-Stat 小地域→IPF→gen_personas | 中 |
| | 組織・職場・配属 | 生成地図の POI 構成から導出 | 容易(ほぼ場所非依存) |
| **制度(値)** | 最賃・家賃相場・議会定数・供託金 | **②の47都道府県表から pref セレクタで引く** | 容易(②整備後) |
| | 地域独自条例・行政区分 | LLM候補+人手確認 | 高(捏造ガード) |
| **文化** | 地域行事・群集イベント(ハロウィン等) | LLM候補+**人手確認キュー**(未確認は入れない) | 高 |
| | 地名語彙・ランドマーク lexicon | 地図 POI から機械抽出+LLM整形 | 中 |
| | メディア局名・番組枠 | ②の全国既定+地域局を人手確認 | 中 |
| **精度(fidelity)** | 場所固有の較正アンカー(例: スクランブル1青1,000人・渋谷区犯罪認知件数・昼夜間人口比) | 公的統計から手動採録(出典必須) | 中〜高 |
| | 規模プリセット(体数・日数・LOD水準・リアリズムノブの推奨ON集合) | 環境の用途宣言(demo/実験/較正)から機械導出 | 容易 |
| | 再現度スコアの重み(env_report の判定項目選択) | 汎用バンド(②)+場所アンカーの合成 | 容易 |

### ②共有参照(今回新設・「なるべく共通化」の受け皿)
| 要素 | 中身 | 出典 |
|---|---|---|
| 制度テーブル | 47都道府県: 最低賃金・住民税按分・供託金等(全国一律値は1行) | 厚労省表等・出典必須 |
| 祝日暦 | 祝日法による機械生成(年指定) | カレンダー法 |
| **汎用較正バンド** | 睡眠7-8h・労働時間・失業率・転職率・犯罪率の全国標準帯(現 conf コメントの較正値を表に昇格) | 既存 docs/calibration の出典 |
| 言語・文化既定 | ja-JP の敬語/口語プロンプト語彙・通貨単位・メディア全国局 | 既存プロンプトから抽出 |

### ①共通基盤(参考=変更しない)
認知(deliberate/reflection/planning/memory/drive+LOD)・人格機構・社会(relations/status/net)・
経済機構・制度機構(rules DSL/routes/assembly/enforcement)・因子・観測(L1-L3/CRN/ゴールデン)・
エンジン・LLM抽象。**レビュー規約: ここに場所の知識を新たに入れない**(W2完了後、契約テストに
地名禁止ガードを追加)。

## 2. 「精度=抽象要素」の位置づけ(ユーザー要望への回答)
精度は1つの値でなく3層に分かれて住む:
- **汎用バンド(②)**: どの街でも成り立つ人間の生活の帯(睡眠・労働)= env_report の共通判定。
- **場所アンカー(③-B)**: その街でしか測れない値(群集規模・犯罪件数)= 街の個性の検収基準。
- **用途プリセット(③-B)**: demo/実験/較正で要る忠実度・規模・ノブ集合が違う= env.yaml の
  `purpose:` 宣言から run プロファイルを導出する(新規要素・D2 stage7 と接続)。
