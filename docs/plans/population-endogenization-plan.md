## 1. 設計の核 — 全て「域内状態への応答」として起こす

ユーザー原理の適用: レート表は**駆動に使わず検証目標にする**(発火は行動・集計が実測と合うかを較正で確認=H3遺失物の返還率方式と同型)。

| イベント | 行動由来の表現 | 実数アンカー(bbox常住3万按分) |
|---|---|---|
| **恒久転出** | Wolpert閾値型=居住ストレスの蓄積(家賃滞納・立退き・失業・関係喪失・過密)が閾値を超えたら転出を決断(既存状態の純関数・LLM記憶に事後1行) | 7.8人/日 |
| **転入** | ★原理的に域外の決断=完全には閉じない(ILUTE/SVERIGEも外生)。**妥協の最小化=域内状態への応答としてのみ発生**: 求人の空き定員(org台帳)×空き住戸(assets O1登記簿)×既存関係(呼び寄せ)が揃ったときだけ到着 | 8.4人/日 |
| **出生** | 世帯(form_partners既存)の決断(年齢×世帯状態の純関数)→新生児=世帯に誕生・成長はライフステージ | 0.59人/日 |
| **死(慢性)** | H1のfrailty×年齢の長期ハザード(急性S4と同じ despawn 同型・相続=O3接続済み) | 0.65人/日との差分 |

**転入者ペルソナの2案**(ユーザー判断): 案A=**L4来街者70.8万からの「定着」昇格**(常連来街者が住民になる=名簿不変・最軽量・「街に通ううちに住む」の自然な物語)/案B=真の新レコード追記(上京者等・生成パイプライン拡張・名簿が成長)。推奨=**案A先行・案Bは長期ラン運用で追加**。

保存則: 人(存在イベントは因果台帳の新kind=転入/転出はboundary・出生/死はphysics+agent)・金(転入者はRoWから財産携行・転出者はRoWへ持ち出し=IF-E整合)・資産(登記簿の own 移転=O1接続)。

## 2. タイムスケールの正直な申告

渋谷区2024実数: 転入23,456・転出21,898・出生1,669・死亡1,821(社会増+1,558)。**10日ランでは転入84・転出78=在場25万の0.03%でほぼ不動**。1年ランで常住の約1割が入れ替わる(純増+0.6%)。→ **本選(10日)には入れず、本選後の長期ラン設計として実装**が正直な位置づけ。初期条件(現在の較正済み25万)が「産み落とし」に相当し、長期ランで人口が現実に沿って呼吸する。

## 3. 実装スライス(本選後・承認後)

1. **POP-1 恒久転出**(Wolpert閾値・既存ストレス状態の接続・despawn同型)
2. **POP-2 転入=応答**(求人×空き住戸×関係のゲート・案A定着昇格・RoW財産携行)
3. **POP-3 出生**(世帯決断・新生児ペルソナ・ライフステージ)
4. **POP-4 慢性死**(frailty長期ハザード・相続接続)
5. 検証=年間レートが実測帯に入るか(駆動でなく検証・H3方式)
