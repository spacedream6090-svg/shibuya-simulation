# 所有権レイヤー計画 — 「所有されるもの」を世界の第一級オブジェクトにする

> 入力: ユーザー構想(2026-08-12)「エージェントが所有しているものもエージェントの活動によって流通したり、所有権が移り変わるような状態にしたい。…実存するもの(不動産・家電)も権利など目に見えないものも。個人所有と組織所有。範囲内のあらゆるものを実装できればしたい。**所有されているもの自体にタグをつけて観察、管理をするような方式でいいかな?**」
> リサーチ正典: [ownership-asset-models.md](../research/ownership-asset-models.md)(文献・制度22件+リポ棚卸し実測)。**実装はユーザー承認後・構想段階**。

## 0. タグ案への回答(結論)

**タグ案の核心=「所有されるもの自体にidと属性を持たせて観察・管理する」は正しい**。全先行例(住宅ABMの住宅個体・地籍標準LADM・本リポのlost_property)が支持します。ただし「タグを**どこに**持つか」で長期費用が分かれます:

- **物やagentの属性に分散して貼る(純粋タグ方式)**の費用: ①逆引き(この住戸は誰の物?)が全走査 ②保存則検査が分散 ③OFF時の不侵襲性(属性はcheckpointに載る) ④BIM標準IFCが「全オブジェクトに所有タグ」を必須→任意→廃止提案と辿った実運用の轍。
- **推奨=ハイブリッド「タグ付きレコードを登記簿に置く」**: タグ(資産レコードのowner/right属性)はそのまま採り、**置き場と書き手を中央台帳1つに限定**(現実の不動産登記=Torrens「台帳が真実」と同構図)。★実は本リポのlost_propertyが既にこの形で実働しています(ownerタグ付きitemを中央dictに格納)=その一般化であり、リポの流儀(単一の書き手・Σ不変量・未分類監視装置)と完全に噛み合う。

## 1. 設計の核

### 1-1 AssetLedger(登記簿・`world.assets.enabled:false`既定)
- 行 = **権利行** `(asset_id, party_id, right_kind, since, until)` + 資産レコード(カテゴリ・属性・状態)。
- **「所有」ではなく「権利」を行にする**のが一般解(地籍標準LADMのRRR/権利の束理論): own(所有)/lease(賃借)/permit(許認可)/lien(担保)/custody(占有=拾得者・在院)。「賃貸中」=同じ資産にown(家主)とlease(借主)が並ぶ。venture の permitted bool・遺失物の hold・入院の病床占有が全てこのスキーマの特殊例に収まる。
- **既定ONの最小核は own 1種だけ**(right_kindの列挙はconf/registryに宣言して段階拡張=IF-Bの3水準conf化と同じ流儀)。
- party = agent / org / RoW(域外の家主・本社)= IF-E2 の部門語彙をそのまま使う。個人所有と組織所有はparty型の違いだけ=同一機構。

### 1-2 資産保存則(貨幣保存則IF-Eの完全な双対)
「台帳の行はRoW(製造・輸入)からのみ生まれ、K5(廃棄・滅失)でのみ消え、それ以外の全変化はpartyの付け替えである」。
Σ検査 = Σ(所有者別保有数)+K5累積−RoW累積 = 初期ストック(カテゴリ別・IF-Eの雛形コピーでテスト固定)。移転語彙は9種に正規化: 売買・贈与・相続・貸借・担保・遺失/拾得(既存)・窃盗(own不変でcustodyだけ移る=法的に正確)・製造/輸入・廃棄。

### 1-3 規模=階層LoD(25万×家財=最大750万レコードは全個体不成立)
| 層 | 資産 | 表現 |
|---|---|---|
| **L-full 全個体=登記簿の行** | 不動産(住戸・建物)・事業持分・車両・自転車 | 合計**数万行=既存org台帳と同じ桁**=現行流儀で足りる |
| **L-agg 世帯集計** | 家電・家具・家財 | 世帯×カテゴリの計数+寿命。**イベントが触れた瞬間だけ個体に実体化**(遺失・売却・災害)=lost_propertyの「落ちた物だけレコード化」の既存流儀そのまま |
| **L-flow フローのみ** | 食料・消耗品 | 現行spendのまま(SNAも消耗品は資産境界の外) |

「範囲内のあらゆるもの」は「**あらゆるものが観測に応答できる**」ことで満たす(常時個体では満たさない=MATSimの粒度原則)。将来全個体が要るならsoa.pyのSoA列へ**格納だけ**差し替え(意味論不変)。

### 1-4 自然主義との整合
売買・贈与を**勧めない**。既存の行為(spend・転居・出店・遺失・死亡)が台帳に写像されるだけ=挙動1バイト不変の「分類の追加」(IF-E2 UNCOVERED方式)から始める。「自分の持ち物」をプロンプトに見せる段は独立トグル(affects_k再評価つき)で後回し。

## 3. この層が可能にする観測(価値)

- **総資産Gini・Lorenz**(現金のみ→現金+不動産+事業持分。住宅資産は家計資産の過半=現状の資産格差観測は原理的に歪んでいる)
- **所有ネットワーク**(agent–asset–orgの二部グラフ・ファウンダー観察に「創業者が何を所有して始めたか」の軸)
- **保有期間分布・流通速度**(住み替え頻度・買い替え周期=実測統計に較正アンカーが取れる)
- **相続=富格差の世代間持続**・**所有の地理**(空き住戸率・持ち家/賃貸比×traces)
- **会計検査の二重化**(金と物のΣ検査が対になり、b2b等「金と物が同時に動く」整合が初めて機械検証可能)
- **事件レイヤの拡張**(自転車盗=現実の刑法犯最大品目が扱える・返還率検証の品目一般化)

## 4. タイミングと規律

- 8/12-14フリーズ=新機能禁止・本選中は観察優先 → **実装は本選後が本線**(O1は本選中ブランチも可能だが推奨しない)。本計画はその設計凍結。

## 5. OPEN(ユーザー判断)

1. **住戸の初期所有者**: 現実の渋谷は賃貸過半=大半の家主は「域外の不動産会社」が自然。推奨=**持ち家率だけ実測に較正し、賃貸住戸のownはRoW(不在家主)から始める**(家主エージェントの生成は必要になってから)。
2. **相続(O3)を入れるか**: 第107で死が実装されたため受け皿は自然に繋がる。推奨=O1と同時(小さく・観測価値が大きい)。
3. **スライス範囲の承認**: 推奨=本選後にO1→O3→O2→O4の順(O5は独立判断)。
