## 1. 指標の定義(数式)

すべて `<run>/l1_events.parquet` のみから計算する。sim 日は **d = ⌊sim_min / 1440⌋**(0 始まり)。

**完全日 / 部分日**: 日 d の sim_min の張り出しを span(d) = max(sim_min|d) − min(sim_min|d) とし、
span(d) ≥ 0.9 · max_{d'} span(d') かつイベント数 > 0 の日を**完全日**とする。ラン開始/終了で切れた
部分日は、ノイズ床・lag 構造・後半窓・既定ペアから除外する(日次系列には残す)。

### 1.1 新規語彙出現率

イベント源: `label_coin` / `vocab_coin`(造語)・`label_adopt`(複雑接触 adopt_threshold=2 での採用)・
`vocab_use`(使用)。item の同定は payload の `item_id`。

- 新語数 **N_coin(d)** = |{ i : i の最初の coin イベントが日 d }|
- 新規採用数 **N_adopt(d)** = |{ i : i の最初の `label_adopt` が日 d }|
- 日 d の使用語彙の台集合 S(d) = { i : 日 d に `vocab_use` された i }
- **新規性シェア** ν(d) = |{ i ∈ S(d) : i ∉ ∪_{d′<d} S(d′) }| / |S(d)|   (S(d)=∅ のとき未定義)

**データ品質除外(第70バッチ追記 2026-07-31)**: L2 `echo_max == 1.000` のラン(=発話が完全な自己反復に
崩壊している)は、語彙系指標が LLM の反復癖のみを測ってしまうため **k* 推定の母集団から除外し「崩壊ラン」として
別掲**する(除外数・条件を必ず報告)。判定は L2 常設の echo 5 列(`src/society/observer/echo.py`)による。
- 使用語彙エントロピー H_V(d) = − Σ_{i∈S(d)} p_i log₂ p_i,  p_i = (日 d の i の使用回数)/(日 d の総使用回数)
- 語彙 Jaccard  J_V(d) = |S(d) ∩ S(d−1)| / |S(d) ∪ S(d−1)|

> **ν(d) が主指標**。「その日交わされた語のうち初めて出た語の割合」。反復する世界では ν → 0。

### 1.2 関係グラフ構造

接触グラフ G_d = (V_d, E_d) は無向・**累積**(日 d の終わりまで)。辺は
`speak`(speaker → payload.hearers の各人)と `dm`(sender → payload.to)から張る
= `scripts/analyze_weak_ties.py:62 build_weighted_graph` と**同一チャネル**(単一の源)。

- 新規紐帯数 **Δ E(d)** = |E_d \ E_{d−1}|
- **新規紐帯率** ρ(d) = Δ E(d) / |E_d|
- 平均次数 k̄(d) = 2|E_d| / |V_d|
- クラスタ係数 C(d) = mean_{v: deg(v)≥2} [ 2 L_v / (k_v (k_v − 1)) ]  (L_v = v の隣接どうしの実辺数。Watts & Strogatz 1998)
- 直径 Diam(d) = 最大連結成分内の全点対最短路の最大値(タイは最小 id で決定論解決)
- 補助: `relation_tier` のペア初出数・`relation_break` の件数(relations が ON のランでのみ非ゼロ)

> C(d) と Diam(d) の定義・実装は `scripts/analyze_weak_ties.py:85 clustering_and_diameter`(第64バッチ)からの
> **コピー**であり、`diagnose_stationarity.py` に純 Python 版として複製した(既存ファイルは変更しない)。
> N ≤ 1500 では等価な numpy 高速路を使い、両者の一致を単体テストで固定している。

### 1.3 行動反復度(ペルソナ逸脱の逆数)

イベント源: `arrive`(payload = `{node, first_visit, name}`)。

- **回帰率** r(d) = 1 − (日 d の `first_visit=true` の arrive 数) / (日 d の arrive 総数)
  = **EPR の優先的回帰が実際に起きた割合**。`first_visit` はシム側が
  `agent.visits[node] == 0` で立てる真値(`scheduler.py:1038-1046`)。
- 訪問エントロピー H_P(d) = − Σ_n q_n log₂ q_n,  q_n = (日 d の ノード n への arrive 数)/(日 d の arrive 総数)
  正規化 Ĥ_P(d) = H_P(d) / log₂ V,  V = ラン全体で到着されたノードの種類数(固定台で日間比較可能にする)
- **日次 Jaccard** J(d) = mean_{a ∈ A(d)∩A(d−1)} |S_a(d) ∩ S_a(d−1)| / |S_a(d) ∪ S_a(d−1)|,
  S_a(d) = エージェント a が日 d に到着したノードの集合

### 1.4 日次自己相似性(**主判定**)

エージェント a・日 d の特徴ベクトルを 2 ブロックで作る。

- **kind ブロック** p^K_{a,d}(κ) = n_{a,d,κ} / Σ_{κ′} n_{a,d,κ′}   (n = イベント種別 κ の件数)
- **visit ブロック** p^V_{a,d}(n) = (a が日 d に n へ到着した回数)/(a の日 d の arrive 総数)
  次元はラン全体の到着回数上位 M=64 ノード + `_other` の 65 次元
- **combined** v_{a,d} = ( ½ · p^K_{a,d} , ½ · p^V_{a,d} )   ⇒ 両ブロックが非空なら ‖v‖₁ = 1

日ペア (t, t′) について、**両日に在席したエージェント** a = 1..n の対応のある差
D_a = v_{a,t} − v_{a,t′} を取り、統計量を

> **TVD(t, t′) = ½ · Σ_j | (1/n) Σ_a D_{a,j} |**

とする(= 平均プロフィール間の全変動距離 ∈ [0,1])。
**「平均的なエージェントの 1 日の活動プロフィールのうち何割が入れ替わったか」**と読める。

**検定**: 帰無仮説「各エージェントにとって日ラベルは情報を持たない」の下では D_a → −D_a が
交換可能。符号 s ∈ {−1,+1}^n に対し T(s) = ½‖(1/n) Σ_a s_a D_a‖₁ とし、両側 p = P( T(s) ≥ T_obs )。

- n ≤ 12: 2ⁿ 全列挙(厳密)
- n > 12: モンテカルロ 10,000 回・**p = (b+1)/(m+1)**(Phipson & Smyth 2010, doi:10.2202/1544-6115.1585)
- 乱数は `numpy.random.default_rng(0)` 固定(シムの `RngHub` は使わない=シム外ツール)
- **交換単位はエージェント**であり、グラフのノード/辺の置換はしない
  (ネットワーク内の非独立性による過大有意を避ける。Farine & Carter 2022, doi:10.1111/2041-210X.13741)
- 実装作法は `scripts/analyze_endo_treatment.py:203 sign_flip_test` を踏襲した多変量版

**補助効果量**: 次元ごとの対応のある Cohen's dz = mean_a(D_{a,j}) / sd_a(D_{a,j}) の |·| 平均・最大。

**ノイズ床**: F = median{ TVD(d, d+1) : d, d+1 とも完全日 }。
**比** R(t,t′) = TVD(t,t′) / F(= 隣接日どうしの揺らぎの何倍離れているか。スケールフリー)。

**lag 構造**: 完全日どうしの全ペアを lag = |t − t′| で束ね、lag ごとの平均 TVD と、
lag に対する OLS 傾き **lag_slope** を出す。定常なら平坦(slope ≈ 0)、ドリフトがあれば正。
lag 2..14 で平均 TVD が最小になる **lag_min** は周期構造の指紋(7 なら週次リズム)。

**立ち上がり(burn-in)の終端推定** burn_in_end = max( 各指標が飽和側へ入りきる最初の完全日 )
(ν < ν_min / ρ < ρ_min / r > r_max の 3 本すべてが到達した場合のみ定義)。

**過渡 vs 常態の切り分け(late_same_lag)**: 主判定ペアと**同じ lag** を、完全日の後ろ 40% の中で
取り直したペア。主判定が PASS でこちらが FAIL なら、非定常性の正体は**蓄積の過渡**であって
日常の非反復性ではない。

### 2.3 実測から得た設計上の教訓(閾値に反映済み)

1. **F は N に強く依存**(N=300 で 0.049 / N=60 で 0.123)→ 主軸は絶対 TVD ではなく **比 R**。
2. **n が数百あると p はほぼ必ず 0.05 を切る**(daily300 の隣接日ですら p=0.0011)
   → **p 単独では判定に使えない**。p と効果量の**連言**が必須。
3. **burn-in(蓄積の過渡)と常態を分けないと 10 日ランは自明に「非定常」になる**
   → `late_same_lag` 条件を判定式に入れる(§4-B)。
4. **周期構造(lag_min=7)は非定常性ではない** → 判定時に必ず併読する。

## 3. 閾値の提案(ドラフト)

すべて `scripts/diagnose_stationarity.py` の `DRAFT_THRESHOLDS` に同値で埋め込んである
(CLI 実行で機械判定が出る)。**承認までは変更自由・承認後は変更禁止**。

### A. 主判定(日次自己相似性・combined ブロック・主判定ペア = Day 2 vs Day 5)

| # | 条件 | 閾値 | 根拠 |
|---|---|---|---|
| A1 | 置換検定 **p < 0.05** | 0.05 | 慣行。ただし単独では効かない(教訓2) |
| A2 | 効果量 **TVD ≥ 0.05** | 0.05 | daily300 のノイズ床 0.049 とほぼ同値 = 「N=300 規模で少なくともノイズ床 1 個ぶんは動く」下限。F ≈ 0 の退化ケースへの保険 |

### B. 過渡切り分け(**burn-in 対策。10 日ランでは実質これが本体**)

| # | 条件 | 閾値 | 根拠 |
|---|---|---|---|

## 4. 判定式(合格/不合格 → D1 アフォーダンス ON 判断への接続)

```
primary  = (p(2,5) < 0.05) ∧ (TVD(2,5) ≥ 0.05) ∧ (R(2,5) ≥ 1.50)
sustained = (p(late) < 0.05) ∧ (TVD(late) ≥ 0.05) ∧ (R(late) ≥ 1.50)      # late = late_same_lag ペア

ラベル:
  primary ∧ sustained          → SUSTAINED_NONSTATIONARY   (持続的に非定常)
  primary ∧ ¬sustained         → TRANSIENT_ONLY            (非定常性は立ち上がりの過渡のみ)
  ¬primary                     → STATIONARY_LIKE           (Day t と Day t' が区別できない = 反復)
  primary ∧ (late ペアが取れない) → NONSTATIONARY_UNVERIFIED (過渡と分離できない)
  判定に必要な量が欠測          → INCONCLUSIVE
```

この判定式は `scripts/diagnose_stationarity.py` の `_verdict()` に**逐語で実装済み**
(`verdict.label` / `verdict.primary_pass` / `verdict.sustained_pass`)。文書と実装が食い違ったら
実装ではなく本文書が正典であり、実装を直す。

### D1(場所の意味づけ最小版・命名の場所束縛)の ON/OFF への接続

| ラベル | 本選 10 日ランでの D1 | 理由 |
|---|---|---|
| SUSTAINED_NONSTATIONARY | **OFF のまま** | 日常が反復に閉じていない = 構造的手当ての必要が示されていない。R1 ドクトリン(本線を汚さない)を優先 |
| TRANSIENT_ONLY | 本線は **OFF のまま**。D1 ON は**別条件ラン**として GPU 余剰時にのみ。**D1 の必要性は「あり」と記録する** | 常態は定常 = 原指示 D の危惧が(過渡の後に)当たっている。ただし 10 日ランはほぼ全部が過渡なので、本選内では D1 の効果を分離できない。本線は現実幾何 1 条件(H_real 基準点)を守る |
| STATIONARY_LIKE | **D1 ON を提案**(ユーザー最終判断)。ただし本線 10 日ランに入れるか別条件にするかは、コード凍結原則(計画書 §2 レーン2)と天秤 | 反復に収束している = 原指示 D の想定が現実化。ただし ON は本線の既定挙動変更なので、ゴールデン・呼数不変の検収を通したうえでユーザー承認が要る |
| NONSTATIONARY_UNVERIFIED | **OFF のまま** + 日数を伸ばして再測定 | 後期ペアが取れない(日数不足)= 過渡と常態を分離できていない。分離できないまま「非定常だから手当て不要」と結論しない |
| INCONCLUSIVE | OFF のまま + 診断の再設計 | 判定不能を「合格」に読み替えない |

> **mock 事前測定の時点で `daily300_100d` = TRANSIENT_ONLY**。この行がそのまま実 LLM でも出れば、
> 「D1 は必要だが本選の 10 日ランでは検証できない」= **本選後(レーン3)へ回す**という結論になる。

**このゲートは自動実行しない。** `scripts/diagnose_stationarity.py` は機械判定を出すだけで、
D1 の ON/OFF は必ずユーザーが決める(記憶則 `ask-before-extending`)。

1. **(済) mock 事前測定** — `daily300_100d` / `endo7_kfree_eoff_s11`(§2)。配線確認 + 構造系の基準値。

3. 本選 10 日ラン(8/16〜8/26)後に同じ CLI を再適用し、**本番ランそのものの非定常性**も報告する。

## 5. 「反復した」場合の報告条項(設計空間の上界として報告する)

判定が **STATIONARY_LIKE**(区別できない)または **TRANSIENT_ONLY**(立ち上がりの過渡だけで、
常態は定常)になった場合でも、それは失敗ではなく**測定された事実**として報告する。
mock 事前測定では `daily300_100d` が既に TRANSIENT_ONLY(day 18 以降は定常)なので、
実 LLM でも同じ形になる可能性は十分ある。具体的には次の形で書く:

> 「現行のアフォーダンス集合(受理動詞 21 型・世界改変 6 種・既定 OFF の反収束機構は OFF のまま)と
> 現実渋谷の幾何のもとで、N = ○○ 体 × D 日の日常過程は、lag L 日離れた 2 日を
> 日間ノイズ床(F = ○○)を超えて区別できなかった(TVD = ○○, R = ○○, p = ○○)。
> これは **この設計空間が生む多様性の上界**の測定であって、LLM 社会一般の上界ではない。」

**上界としての正しい読み方**(報告時に必ず添える):

- 上界を規定しているのは (i) 決定論日次予定の骨格、(ii) EPR の優先的回帰(正のフィードバック)、
  (iii) 反収束機構(退屈ループ `drive.boredom` / 価値飽和 / 閾値ドリフト `theta_drift` /
  Gumbel 確率的行き先選択)が**全部既定 OFF** であること — の 3 点であり、これらは**変更可能な設計選択**である。
- したがって「反復した」は「LLM エージェント社会は反復する」ではなく
  「**この構成では**反復する。反復を破る設計余地は少なくとも 3 つ特定されている」と述べる。
- 規模(N)を上げても同じ結論になるとは限らない。本測定は N=300 と N=60 の 2 点しかなく、
  ノイズ床 F が N に強く依存する(0.049 vs 0.123)ことは確認済みだが、
  **N を増やしたときに R がどう動くかは未測定**である(正直な限界)。
- 逆に **SUSTAINED_NONSTATIONARY** が出た場合も、それを「創発が起きた」と読み替えない。
  日次プロフィールが区別できることは、蓄積(語彙・関係・訪問履歴)が進行中であることを意味するだけで、
  質的な新規性の証明ではない。

## 6. 正直原則(mock 実測の限界)

**mock ランの語彙・発話は決定論である**(`src/society/llm/mock.py` = 決定論 JSON アクション)。したがって:

- **語彙系(§1.1)の水準は実 LLM と挙動が違う。** mock の造語は決定論テンプレートから出るので、
  新語の出方・尽き方が実 LLM の生成分布とは別物である。§2 の ν の絶対値
  (daily300 の後半 0.0019 など)を実 LLM ランの合否基準にそのまま使ってはならない。
  → **C1(ν の閾値)は実 LLM 診断ランで再較正する。**
- **§2 の mock 実測の位置づけは (a) 配線確認(ツールが 11.9M 行を捌けること・指標が動くこと)と
  (b) 構造系指標の基準値** である。構造系(関係グラフ・訪問・自己相似性)は移動と接触の機構が
  生むもので、これらは mock でも実 LLM でも**同じ非 LLM 経路**(routine + EPR + perception)が
  駆動する。よって A/B の閾値(TVD・R)は mock 基準値をそのまま初期値に採ってよいと判断した。
  ただし実 LLM では発話量が変わり `speak`/`hear` の kind 比が動くので、**ノイズ床 F は実 LLM で
  取り直す**(F はランごとに CLI が自動計算するので、閾値を触らずに追随する = R を主軸にした理由の一つ)。
- 実 LLM 診断ランで再較正するのは **C1(ν)のみ**を予定する。A/B(TVD・R)を再較正する場合は、
  それ自体が閾値変更なので §7 に記録し、変更前後の判定を両方報告する。
- `daily300_100d` は 2026-07-09 生成の既存ランであり、その後の第60-64バッチの変更は反映されていない
  (relations の内生化・gossip・quality 等は当時の既定のまま)。**時点の異なるランである**ことを明記する。
