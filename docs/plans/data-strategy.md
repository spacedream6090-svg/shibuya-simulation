# データ記録・処理戦略(第16バッチ 2026-07-10・計画のみ・実装なし)

体制: Fable計画 → Opusリサーチ(docs/research/data-pipeline-lit.md)→ Fable統合計画(本書)。
ユーザーの問い: 「生データは一番基礎的な事項のみ記録し、プロットでなく処理で有効なデータに
するべきでは。どちらの方式が良いか文献で調べ、処理方法も考えてほしい。」

## 結論(方針決定)
**「生=正準・最小・追記専用/指標=後処理で派生」方式を正式方針として採用する。**
文献(event sourcing、tidy data、HPC の in-situ/post-hoc、ABM の ODD・再現性ガイドライン、
シミュレーション出力解析の標準)は一貫してこの方式を支持し、ユーザーの直観は正しい。
ただし例外を明文化する: **イベントから再構成できない in-situ 量だけはシミュ内集計を残す**。

## 現状の判定(監査結果)
- 本プロジェクトは既にほぼこの構造: **L1(生イベント・schema登録制・因果つき state_update)
  が正準**で、observe/analyze/calibrate/flows は全て L1 を読む後処理 projection。
- **L2(毎step集計40列)の大半は L1 から再導出可能=論理的には冗長**。
- 真に非復元の in-situ 量は4つだけ: `drive` ゲージ・`theta_drift`(変化イベントを吐かない)・
  `status` 合成/rank_mobility・窓依存カウント(n_sns_posts 等)。

## 決定事項
1. **L1 正準原則**: 新しい状態変化は必ず L1 に「因果つきイベント」で残す(現行 _bump 流儀の維持)。
   新機能レビュー時のチェック項目に「この状態は L1 から再構成できるか」を追加する。
2. **L2 は凍結+選別**: 既存40列は互換性(ゴールデン・既存テスト・ビューワー)のため現状維持。
   **新指標は原則シミュ内に足さない**(後処理へ)。例外=非復元 in-situ 量のみ(上記4種と同型)。
3. **非復元量の将来解消(任意・低優先)**: theta_drift / drive は「日次1回の値スナップイベント」
   を既定OFFノブで L1 に吐けるようにすれば L1 完結になる(バイト増とのトレード。実装判断は保留)。
4. **生データの最小条項(what to keep)**: L1 parquet(全量)+ L1b(LLM台帳)+ llm_cache.jsonl
  (プロンプト監査)+ config.yaml + traits/agents.json + seed。これで全再現・全再導出が可能。
   summary.json とビューワーは便宜品(消えても再生成可)。

## 処理パイプライン設計(後日の実装対象・読み出し専用)
```
runs/<name>/l1_events.parquet(正準)
  → stage0 検証   : schema 完全性・欠落 step・決定論チェック(同seed再実行との照合は任意)
  → stage1 整形   : warm-up 除去 → tidy long-format の2枚のパネルへ
                    (a) agent-day パネル: 1行=agent×日(睡眠h・労働h・収支・発話数・被注意…)
                    (b) run-day パネル : 1行=run×日(較正指標・多様性・地位ジニ…)
  → stage2 統計   : 複数シードの平均±信頼区間(≥5 seed を主張の最低ライン)、シード対応づけ
                    (k条件間は同seedでペア比較=分散削減)
  → stage3 研究量 : R²(k)・EWS(Dakos)・seed発散・意味ドリフト・崩壊検知の多測度合致
  → stage4 出力   : experiments/<exp>/panel.parquet + report.md + 図
```
- **warm-up**: 較正で観測した過渡(資産の立ち上がり・関係網の形成)を踏まえ、定常指標は
  **最初の7日を除外**を既定とする(パネルに warmup フラグ列を持たせ、除外は解析側で選択)。
- 既存資産への接続: measure.ews() / r2_traits() / run_sweep.py / calibrate_report.py は
  stage1 のパネルを読む形に段階移行(sim 本体は無変更)。
- tidy 原則(Wickham): 1行=1観測単位、変数は列、値はセル。プロットは全て stage1 以降から。

## やらないこと
- L1 の削減(「基礎的な条項のみ」を「イベントを間引く」と解釈しない — 因果つき生イベントが
  正準であり、間引くと再導出が壊れる。「最小」とは**シミュ内で加工済みの値を増やさない**の意)。
- シミュ本体へのデータ処理ロジックの追加(処理は全て run 後の読み出し専用スクリプト)。

## 実装ロードマップ(別バッチ・要ユーザー承認)
1. scripts/build_panel.py(stage0-1: 検証+tidy パネル化)
2. scripts/panel_stats.py(stage2-3: シード統計+研究量。既存 measure を再利用)
3. calibrate_report / observe 系をパネル読みに移行(出力互換を保つ)
4. L2 新規追加の凍結をコードレビュー規約に明文化(CLAUDE.md 追記)
