# 旧・渋谷シム(shibuya-sim)からの移植計画(第21バッチ 2026-07-12・計画のみ・実装なし)

体制: Fable計画 → Opus全読レビュー([legacy-sim-review.md](../research/legacy-sim-review.md))→ Fable統合(本書)。
元依頼: 「以前の渋谷シミュレーション実装(shibuya-sim/)に目を通し、活かせる部分を実装案としてまとめる。実装はまだしない」。

## 結論
旧実装(MVP・7モジュール+スクリプト群)に対し現行は上位互換が大半(C判定11系統)だが、
**「観測を厚くする」層に本物の拾い物が3つ**ある。いずれもシミュ本体に触れない/触れても
None安全な追加のみ=決定論・R1・ゴールデンに非抵触で移植できる。

## 採用候補(優先度順・すべて要ユーザー承認)

### P1 — 創発の後付けテキスト検出(旧 detect_emergence.py)【本命・リスクゼロ】
既存L1のテキストだけを読む読み取り専用分析: ①**架空の場所・モノの析出**(発話中の固有名詞候補を
実在POI名と照合し、実在しないものを検出=虚構の創発の芽)②**規範発話**(「〜すべき/してはいけない/
〜が当たり前」の正規表現検出=制度・規範創発の直接観測)③**語の共伝播**(窓内で複数人が同語を使う
=注目の収束)。
- 研究主題(world-changer・規範創発)に最直結。現行の定量指標(採用数/カスケード)が測れない
  「**どんな種類の**発話が現れたか」の器を埋める。judge.py(LLM-judge)の入力候補としても機能。
- 第20バッチの worldview 分析(解釈の分岐・belief クラスタ)と合流させると「言語としての世界解釈」の
  観測が完成形に近づく。作話の接地率メトリクス(reality-levers P2)とも同じ骨格で相乗り可。
- 工数: 半日〜1日(現行L1ローダへの接続+日本語パターン調整)。scripts/detect_emergence.py 新規のみ。

### P2 — SNSが架橋した物理距離(旧 simulation.py:880-922)【A/B対照の被説明変数】
SNS/DM の transmission に**両当事者の物理距離を None 安全な任意キーで追記**(dist_m・near フラグ。
座標が取れない news/media 起点は付けない=既存出力不変)+ 集計(sns_far_frac・相互ペア指標)。
- 「インターネット層が物理的隔たりをどれだけ越えたか」= SNS有無A/B対照の筋の良い被説明変数。
- net/internet.py の送出箇所への局所編集が要る(agent-core ではないが要精査)。工数1日+テスト。

### P3 — ペルソナの深さ属性(旧 generate_pool.py の contradiction/past_setback)【条件付き】
「自覚した内的矛盾」「過去の小さな挫折」の1〜2文を Verbalized Sampling 生成に追加(IPF機構は現行のまま・
名簿=静的資産の差し替えのみ)。
- ★**緊張の明示**: 第20バッチの棚卸しで「ペルソナは薄く多様が正解(属性を盛ると manifold collapse で
  逆に均質化)」と診断済み。深さ属性は「属性の追加」でなく「動機のテクスチャ」なので同列ではないが、
  リッチ化には違いない。→ **全面採用せず、検証用サブ集団(例: 300名簿のうち50人)で A/B**
  (distinct-2・行動多様性・R²への影響)してから判断する。これは survey の「インタビュー接地の部分導入」
  (reality-levers P3)と同じ検証枠で相乗りできる。
- 工数: 半日(生成プロンプト+サブ名簿再生成)+検証ラン。

#### P3 判断(第22バッチ 2026-07-12・ユーザー委任による決定): **今回は導入しない**
現状実装(scripts/gen_personas.py + data/personas_300_civic.json)との比較:
現行は決定論テンプレ生成(LLM不使用・seed完全再現・自由文中央77字)+traits 3軸が「生得」側の実験変数。
旧方式(LLM enrich・contradiction/past_setback 2文+enum6種)を導入すると、
(a)第20バッチ棚卸しの診断「属性を盛るほど manifold collapse で行動が均質化」に正面から抵触、
(b)ペルソナ変更は既存較正(calib_tuned 系)と k 実験系列の比較可能性を壊す、
(c)全発火プロンプトに毎回 +200字 ≒ 本プロジェクトの核(最小推論量で現実再現)に逆行、
(d)生成の非決定化(LLM enrich)は決定論ドクトリンに逆行。
**再訪条件**(満たせば 50 人サブ集団 A/B で再検討): ①内省プロンプト改善(雛形復唱25%対策)後も
belief/発話の多様性指標が頭打ちのまま ②A/B設計で「深さ2文が distinct-2・行動多様性を悪化させない」
見込みが事前スモークで立つ。

## 保留(実装しない判断・理由つき)
- **宛先選択の重み付け(旧 conversation_prob.py)**: 発火後の hearer 優先度としてなら R1 安全に移植可能
  だが、効果が不確かで R1 検証に神経を使う。発話定型化対策(variety_hint)の効果を見てから再考。
- **icebreak 非対称化**: 関係初期値のリアリティ向上は「非対称性が結果に効く」証拠が出てから。
- **コスト事前見積り**: 旧の calls=steps×agents は LOD 前提の現行に合わない。本選のクラウド計画時に
  bench.py 拡張として実施(研究本体に寄与しないため後回し)。
- **C判定11系統**(needs 二層・timeline・geo・LLMクライアント等)は現行が上位互換=採用不要
  (詳細は legacy-sim-review.md §4。将来同じ問いを繰り返さないための記録)。
