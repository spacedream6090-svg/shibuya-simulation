# 計算量・推論量の削減計画(第18バッチ④ 2026-07-11・計画のみ・実装なし)

体制: Fable計画 → Opusリサーチ([docs/research/compute-efficiency.md](../research/compute-efficiency.md))→ Fable統合計画(本書)。
ユーザーの問い: 「**いかに少ない計算量・推論量で現実の人々を再現できるか**。実現できれば
エージェント数と回せる時間を大幅に増やせる。処理面の改善と観察情報の最適化の案を考えてほしい
(今回は計画のみ・実装しない)。」

## 結論(方針)
**「入力(情報量)を削る」のではなく「同じ意味の計算を安く回す」推論高速化を上限まで回収し、
呼数削減は"創発の材料を消さない・削減率がkと相関しない"範囲に限る。**

根拠(リサーチの3所見):
1. 我々のワークロードは **decode(出力生成)支配**。入力530〜1,040tokは律速でない
   → プロンプト圧縮(LLMLingua等)は効きが薄く、**reflect出力上限の右サイズ化が主レバー**。
2. 100万体級の先行例(OASIS/AgentScope)の中核=小モデル+確率的活性化+分散配線+vLLM は
   **我々のLOD(発火4.1〜11.4%=呼数1/12)とfleet(sticky+prefix cache)で既に踏襲済み**。
   未回収の「タダ飯」は **speculative decoding(無損失・最大2.8倍)のみ**。
3. 最大削減を謳う **archetype/群近似(42,000倍)・蒸留・noveltyルーティングは、個体の異質性と
   稀な逸脱(=世界改変者)を潰す**ため、k*研究の被説明変数そのものと正面衝突。採るなら
   「背景個体限定+前景との分布一致検証」が絶対条件。

### Phase E1 — タダ飯の回収(忠実度・決定論・R1に完全中立。本選前に完了させる)

|---|---|---|---|
| E1-1 | **speculative decoding 導入** | 実LLMラン最大2.8倍(無損失=目標モデルと同一分布) | vLLM起動フラグ+draftモデル選定(qwen系0.5B級)+bench.py実測 |
| E1-2 | prefix cache+sticky の実機疎通 | ヒット率~96%の確認(配線済み・未実測) | 本選機で bench.py 走行のみ |
| E1-3 | reflect出力上限の右サイズ化 | decode支配の主レバー(飢え8.7%の解消と両得) | daily.yaml の2048を本番プロファイルへ反映判断 |
| E1-4 | step内独立発火の一括発行 seam | 7GPUの充填率向上 | scheduler に順序非依存の集約点を1つ(決定論保持) |

### Phase E2 — 条件付き(効果大・忠実度検証が採用条件)
- **E2-1 INT4 AWQ の忠実度確定**: VRAM制約で事実上必須だが「標準ベンチが劣化を隠す」型のリスク
  → 創作・ペルソナ・多様性の**ブラインドA/B**(distinct-2・自己反復率・believability judge=オフライン限定)
  で INT4 vs 非量子化を比較してから本番固定。
- **E2-2 routine caching の限定導入**(「昨日と同じ日」のplan再利用。先行例 -50% token):
  採用条件=(a)再利用ゲートが決定論かつk非依存 (b)distinct-n・行動レパートリー曲線が痩せない。
  R1監査(呼数のk不変テスト)を通らない設計なら見送り。

### Phase E3 — 本選後の"桁"レバー(設計seamのみ意識・今は作らない)
- 階層化(前景=フルLLM少数でk*を測る/背景=蒸留・小モデル多数で街を充填)。
  前景/背景の割当はk非依存・決定論固定、**前景vs背景の分布一致検定が採用条件**。
- 蒸留・noveltyルーティングは「ロングテール=観測対象が最も削れる部分」なので同条件でのみ。

## 観察情報の最適化(ユーザーの問いへの直接回答)
- **トークン節約目的での観察削減はしない**(入力は律速でない+創発の材料を消すリスク)。
  AGA(トークン30〜43%でも believability 不変)は「これ以上盛らなくてよい」の**上限側の安全域**として使う。
- 投資先は「削る」でなく「**的確に選ぶ**」: 現行の想起(recency×importance×relevance)と
  要約階層化は先行例(Park/Lyfe)と同型で維持。**選別基準は固定=変えるならk*への影響を掃引で測る実験因子**。
- 第18バッチ③の新チャネル(街頭広告・群衆視覚)は本方針に沿い**発火時のみ+各1行**に抑制済み。

## やらないこと(明確に非推奨)
- **archetype/群近似**: マクロ予測用。個体レベルの創発(k*)には定義上不可。
- **プロンプト圧縮フレームワーク**: 短プロンプト+few-shotなしの我々では圧縮器の追加呼で相殺。
- **応答キャッシュのヒット率向上**: ヒット率を上げる=プロンプトを反復させる=現実性を捨てる。
  キャッシュは再現性の実体であり初回計算の節約ではない。
