## 2. 認知アーキテクチャ（発火機構）

### 2.1 基本思想

LLM は「いつ考えるか」を決めない。「何が起きると思うか」だけを述べ、それが外れたときにどれだけ動揺するかは履歴が決める。

人間もそうである。予測は言語化できるが、自分がどのチャンネルに過敏かは自分では設定できない。

### 2.2 監視仕様（watch spec）

エージェントが発火するたび、行動と一緒に次を出力する。次の発火まで有効。**有効期限は持たせない**（時間で失効させると時間軸が裏口から入る）。

1. **期待値 `ô_ic`** — 観測チャンネル c ごとの「こうなるはず」。**LLM が出力する。**
2. **名前付きトリガ** — 「X が起きたら起こせ」の宣言的条件。**制約付き DSL。自由文は不可。**

感度 `g_ic` は監視仕様に含めない（LLM は出力しない。2.4 参照）。

DSL は必ずホワイトリスト + 数値クランプで検証し、不正出力なら前回仕様を維持すること。

### 2.3 発火判定

毎 tick、コード側だけで計算する。LLM 呼び出しは発生しない。

```
S_i(t) = Σ_c  g_ic · |o_c(t) − ô_ic| / σ_c  +  Σ_j  w_ij · [trigger_j 成立]

発火 ⟺ S_i(t) > θ_i(t)
```

- `σ_c` はそのチャンネルの実測標準偏差。**これで割ることが必須。** 割らないと LLM が出す期待値に単位がなく、エージェント間・チャンネル間で g が比較できなくなる。
- σ_c は事前のパイロットランで実測して固定する（ラン中に更新すると決定論が壊れる）。

### 2.4 観測チャンネルの構成

驚きの源は 3 種類。これにより時間項なしで「静かな環境で凍る」問題を回避する。

| 源 | 内容 | 役割 |
|---|---|---|
| 外界 | 混雑度、遭遇、発話、サイネージ、遅延情報 | 環境駆動 |
| 身体 | 7 ニーズ（hunger/rest/connection/novelty/recognition/expression/comfort） | 単調ドリフトによる自発的発火 |
| 予測不成立 | 「誰かが来るはず」が起きないこと | 「暇だと思考が湧く」を時間項なしで表現 |

身体チャンネルがあるため、環境が静かでも空腹や疲労の偏差が閾値を超えて発火する。時計が鳴ったのではなく自分の状態が予測から外れた、という構造になる。

### 2.5 感度 g の更新則

**LLM は g を設定しない。** ペルソナが初期値と動き方を決め、履歴が動かす。

```
g_ic ← g_ic + η_ic·(r_ic − ρ·ē_ic) − λ_ic·(g_ic − g⁰_ic)
```

| 記号 | 意味 | 効果 |
|---|---|---|
| `ē_ic` | そのチャンネルの最近の平均誤差 | **慣れ**。誤差が繰り返し起きると鈍る（下げる） |
| `r_ic` | そのチャンネルの誤差が結果に効いた度合い | **感作**。効いたチャンネルに敏感になる（上げる） |
| `λ_ic` | ペルソナ基準値への引き戻し | 性格の永続性。**この項がないと履歴が性格を上書きして全員収束する** |
| `η_ic` | 可塑性 | ペルソナ由来。動きやすさ |

**重要な区別: 単なる反復は慣れ、結果を伴う反復は感作。** したがって更新を生の予測誤差だけで駆動してはならない。

`r_ic` の実装: 発火後の行動によるニーズ充足・ゴール進捗の改善分を、その発火の `S` への寄与比で各チャンネルに按分する（credit assignment）。コード側のみで完結し、LLM 呼び出しは不要。

**ペルソナが決めるのは `g⁰`、`η`、`λ` の 3 つ。** g そのものではなく「g の動き方」をペルソナが決める、という構造にする。

**将来拡張（MVP では既定 OFF）**: 会話相手の g に引かれる項（注意の伝染）。語彙専門化・噂の分岐と直結した観測が取れる。

### 2.6 閾値 θ と恒常性

絶対閾値方式を採るため、θ が発火率を直接決める。

- `θ_i` もペルソナ由来 + 履歴で動かす（g と同じ枠組みに乗せる）。
- **共通スケールの較正**: パイロットランで「1 日あたり平均発火数が目標値」になるよう θ の全体スケールのみを合わせる。個体差は `θ_i` の分散として残す。
- **ドリフト対策**: g は学習で上昇するため θ 固定だと発火率が単調増加する。恒常性項を入れる。

```
θ_i ← θ_i + μ·(f̄_i − f*)     f̄_i: 最近の発火率, f*: 目標発火率
```

**`μ` の時定数は日オーダーにすること。** 短くすると発火率が定数に張り付き、閾値方式を選んだ意味（発火数の変動を観測する）が消える。恒常性の時定数は日オーダー、観測したい変動は分〜時間オーダー、と分離する。

### 2.7 初期値の実験条件化

**フラット初期値は中立ではない。** 「全チャンネルに等しく注意を向ける人間がいる」という強く非人間的な仮説である。したがって初期値そのものを実験条件として記録する。

| 条件 | 内容 | 意味 |
|---|---|---|
| F | フラット | 純粋対照 |
| N | フラット + ノイズ（ペルソナと無関係なランダム初期値） | 異質性のみの効果 |
| P | ペルソナ由来初期値 | ペルソナ整合的な異質性の効果 |

**条件 N が鍵。** P と N を比較すると「初期の多様性そのものが効くのか、ペルソナと整合した多様性が効くのか」が分離できる。P ≈ N ならペルソナの中身は効いておらず異質性だけが効いている。どちらに転んでも主張になる。

**中核研究課題との接続**: 生まれつき = `g(0)`、創発 = `Δg`。最終的な影響力を「初期 g の分散」と「履歴で動いた分」に分散分解すれば、`world-changer は生まれつきか環境からの創発か` が数値で答えられる形になる。k 掃引より計算コストが低い。

実装要件:
- ノイズは専用乱数 stream から引き、seed をログする。
- ノイズ分散 `σ₀` 自体をパラメータ化する（σ₀ 掃引は k 掃引より GPU 予算的に現実的）。
- `g_i(0)` と g の全軌跡をログする。

### 2.8 責務分界（LLM とコードの境界）

| 対象 | 担当 | 理由 |
|---|---|---|
| いつ発火するか | **コード** | 予算の無限後退回避 / 測定器の独立性 / 再現性 |
| 何を考え何をするか | **LLM** | 内容の自由度こそが本研究の価値 |
| 期待値 `ô` | **LLM** | 予測は内容である |
| 感度 `g` | **コード**（履歴で更新） | 自分の過敏さは自分では設定できない |

**LLM をブラックボックス発火判定器にしない理由:**

1. **予算の無限後退** — 「考えるべきか」を LLM に聞くには全エージェント × 全 tick で LLM を呼ぶ必要がある。発火そのものよりコストが高い。
2. **測定器の独立性** — 観測対象が思考量の分布なのに判定器がブラックボックスだと、「配分が変わった」のか「判定 LLM の気分」なのかが分離できない。no-fingerprint と正面衝突する。
3. **再現性** — ゴールデン一致テストが不可能になる。

**ただし較正用途では使う（1 本のみ）**: 数十体 × 数日の小規模ランで毎 tick「今考えるべきか」を LLM に聞き続け、その判定を教師データにして閾値関数のパラメータ（ρ、θ、チャンネル重み）を合わせる。本番は定式化版で回す。これは人工オラクルの精神（装置を信じる前に別経路で確認する）に沿う。

## 3. 時間構造（三層）

### 3.1 クロック

| 層 | クロック | 責務 |
|---|---|---|
| 物理 | dt = 1/60 s、社会レイヤーと非同期 | 限定領域の群衆流のみ |
| 移動・遭遇 | Δt = 1 分（or 30 秒） | 位置更新、遭遇判定、視界内、混雑度、S 評価。純コード |
| 思考 | クロックなし | 驚き駆動、絶対閾値、同期バリア |

**社会的意思決定の解像度と、身体・移動の解像度は分ける。** 人の意思決定は 10 分単位でもそう間違っていないが、遭遇と移動は秒単位で起きる。

**社会レイヤーを秒オーダーにしてはいけない。** 1 step = 1 発話になり、それは社会レイヤーではなく行動レイヤーの話であり、物理層の管轄である。

### 3.2 境界インターフェース契約

層を分けること自体より、**境界で何を渡すか**が重要。ここを最初に固定する。

| 方向 | 渡すもの |
|---|---|
| 物理 → 移動層 | 要約統計のみ（密度場、平均待ち時間、通過時間、接触回数）。**生の粒子状態は渡さない** |
| 移動層 → 物理 | 出発時刻と目的地のみ。**経路は物理側が決める** |
| 移動層 → 思考 | 観測チャンネル値 `o_c(t)`、`S`、発話・イベントの生ログ |
| 思考 → 移動層 | 行動意図（目的地、同行者、滞在意図）、期待値 `ô` |

生の状態を双方向に流すと、どちらが何を決めたのか事後に分離できなくなる。**この境界仕様が「どこまでが LLM の判断でどこからがコードか」の答えそのものになる。**

### 3.3 同期バリア

**step を進める条件は、発火した全エージェントの推論完了。** 1 step あたりの実時間は発火数に依存して変動する。シミュレート内時間と実時間は完全に切り離される。

要件:

- **結果の適用は step 末に一斉。** state(t) から読んで state(t+1) に書くダブルバッファ。到着順に反映すると完了順序（= GPU の気まぐれ）が結果に漏れる。
- **厳密な全世界バリアとする。** 理論上は相互作用しえない遠方個体の同期は不要だが、緩和すると決定論の検証コストが跳ね上がる。本選までの時間を考えると厳密一択。

**原則: 打ち切るのは可、劣化させるのは不可。** 7 日で止めたランは有効なデータ、10 日走らせた劣化ランは無効なデータ。

### 3.4 却下: 負荷連動の tier 振り分け

バースト時に S の低い側を小型モデルへ回す案は**却下**。

理由: 品質低下が**イベントと相関する**。世界が最も面白い瞬間に認知が劣化するため、「群衆は緊急時に愚かに振る舞う」という観測が出ても、世界の性質なのか GPU の都合なのかを原理的に分離できない。交絡ではなく、測定装置が現象に反応してしまっている。

**llm.fleet の正しい使い方**: 負荷連動をやめ、**初期化時に固定する**。「認知資源の小さい個体が一定割合いる」をペルソナ属性としてラン中固定。これなら世界の性質であり、認知能力の異質性という実験条件として振れる。

### 3.5 スケジュールリスクの吸収（因果経路に触れない範囲で）

- **バーストはスループット的にはむしろ有利。** 継続バッチング（vLLM 等）なら 500 体同時のほうが GPU 使用率が高い。500 体が 100 体の 5 倍かかるとは限らず 2〜3 倍で収まることが多い。バリアと継続バッチングは相性がよい。
- **prefix キャッシュが最大の効きどころ。** エージェントは世界状態のプレフィックスを共有するため、KV 再利用でバースト時コストが大きく下がる。妥当性に一切触れずに数倍取れる。
- **A5000 × 7 はデータ並列レプリカ**にしてスループットを稼ぐ。
- **パイロット 1 日で発火数分布を実測**し、10 日ぶんの総推論量を見積もる。**調整レバーは事前の世界規模（人数・日数）であって、実行中の劣化ではない。**
- 毎日チェックポイントを取り、いつ打ち切っても成果になる状態を保つ。

## 4. 環境フィードバック（エージェント → 環境）

### 4.1 原則

**エージェントは環境イベントを宣言できない。環境イベントは、集約された物理量が閾値を超えたときにコード側が発火する。**

LLM に「電車が遅延した」と言わせた瞬間、世界は「エージェントが言ったこと」になり、物理制約の前提が消える。因果は必ず物理量を経由させる。

### 4.2 規則セット（最小構成）

| エージェント行動 | 集約物理量 | 環境イベント |
|---|---|---|
| ホームへの流入 | ホーム密度 | 停車時間延長 → 遅延伝播 |
| 改札通過 | 改札スループット飽和 | 入場規制 |
| POI 滞在 | 占有率 > 容量 | 待ち行列 → 他 POI へ流出 |
| 特定 POI への集中 | 需要スパイク | 品切れ・臨時営業（既存の経済スライスへ接続） |
| 歩道の対向流 | 通行速度低下 | 経路変更（物理層の担当） |

実際の鉄道遅延の主因は乗降時間超過であるため、1 行目は現実の機構としても妥当。

### 4.3 得られるもの

**どのエージェントの行動が、どの物理量を、どれだけ動かし、どの閾値を超えたか**が記録から辿れる。「経路を記録から追える状態にする」の環境版。

**環が閉じる**: 行動 → 密度 → 遅延 → 驚きチャンネル → 発火 → 行動。

これが創発を主張できる最初の地点。従来は環境 → エージェントの一方向だったため、何が起きても「入力に反応した」で説明できてしまっていた。

### 4.4 二つの罠

- **発散**: 遅延 → 混雑 → 遅延の正のフィードバックは容易に爆発する。減衰項と上限を入れる（現実の鉄道も回復運転で減衰するので物理的にも正当）。
- **指紋**: 閾値と規則そのものが指紋である。対策は (1) 規則を最小限にする、(2) パラメータを実データ（渋谷駅の実際の遅延統計）で較正する、(3) **環境フィードバック ON/OFF を実験条件にする**。(3) が本質的で、OFF ランと比較して初めて「環境からの反作用があるとき何が変わるか」が言える。

### 4.5 タイミング

環境イベントの計算は **step 末に集約状態から一括**で行う。step 途中で計算すると、その step 内の処理順が結果に混入してバリアの意味が消える。

## 5. 計算量とスケジュール

### 5.1 Δt を細かくしたときのスケーリング

シミュレート期間 T 固定、Δt を 1/10 にした場合:

| 項目 | スケール | 10 分 → 1 分 |
|---|---|---|
| tick 処理（ニーズ減衰、位置更新、S 計算） | ∝ N·T/Δt | ×10 |
| 近傍探索・遭遇判定 | ∝ N·T/Δt | ×10 |
| **LLM 呼び出し** | ∝ 総発火数 | **×1** |
| 物理エンジン | ∝ T·(領域内人数) | ×1 |
| 記憶 / 兆しエンジン | ∝ イベント数 | ×1 |
| ログ I/O | ∝ N·T/Δt | ×10 |

**LLM が ×1 になるのが驚き駆動を採る最大の実利。** 固定間隔なら step 数に比例して即死するが、驚き駆動では総発火数は Δt に依存しない。細かく刻んでも思考の総量は変わらず、思考のタイミング解像度だけが上がる。

**物理が ×1 な理由**: 物理は独自 dt でサブステップするため社会レイヤーの Δt と無関係。Δt を細かくしても物理は安くも高くもならず、変わるのは社会レイヤーが物理の結果を見る頻度だけ。

### 5.2 本当のコストは計算量ではない

CPU 側の ×10 は A5000 × 7 なら誤差。実際に効くのは:

1. **ゴールデン一致テストの失効** — L1 バイト一致は Δt を前提としている。1,391 本のうち時間刻みに依存するものは作り直し。
2. **定数が Δt 前提になっている** — ニーズ減衰率、移動速度、POI 滞在時間、関係性変化率。Δt を変えると世界の挙動が全部変わる。
3. **乱数消費列の変化** — 過去ランとの再現比較ができなくなる。

### 5.3 最優先の作業: 定数の毎分レート化

**Δt を変えることより先に、定数を「毎分レート」に正規化して Δt 不変な実装にする。**

`decay_per_step = 0.02` → `decay_per_min = 0.002` にして実行時に `× Δt` する。

効果:
- Δt が実験パラメータになる（Δt 掃引が条件になる）
- ゴールデンは Δt=10 で維持したまま、細かい Δt を追加条件として足せる
- 較正が Δt に対して壊れなくなる

1 回やれば恒久的な資産であり、壊れにくい作業。**本選前に入れるならこれを最優先。**

## 6. R1 ドクトリン整合と新規テスト項目

### 6.1 整合

- 発火機構・g 更新・環境フィードバックはすべて**既定 OFF** で実装し、OFF 時に既存ゴールデンとバイト一致すること。
- ノイズ・初期値生成は**専用乱数 stream**から引く。
- **物理層は L1 ゴールデン一致から除外する。** GPU 並列の浮動小数は順序依存で非決定的になりやすい。物理は統計的一致（密度分布が許容帯に入るか）で検証し、R1 ドクトリンは移動層と思考層で守る。

### 6.2 新規に必要なテスト

| # | 項目 | 内容 |
|---|---|---|
| T1 | 完了順序不変性 | 同じ step を 2 回、意図的に完了順序を変えて走らせてバイト一致すること。**これが通らないとバリアを入れた意味がない** |
| T2 | 発火オラクル | 既知偏差のイベントを注入し、意図したエージェントだけが発火し、無関係なエージェントが発火しないこと |
| T3 | Δt 不変性 | 毎分レート化後、Δt を変えても統計量が許容帯に収まること |
| T4 | 実時間非参照 | 1 tick の処理内容が GPU の実速度に依存しないこと（実時間を参照するコードがないこと） |
| T5 | 環境フィードバック非発散 | 遅延ループが上限内に収束すること |

## 7. 実装順序

1. **定数の毎分レート化（Δt 不変化）** — 最優先。他と独立に進められる
2. **σ_c 実測** — フラット固定 g で 1 ラン、チャンネル分散を収集して固定
3. **Δt_move = 1 分に変更** — 遭遇検出数が増えることを確認
4. **閾値発火 + 同期バリア + ダブルバッファ** — 既定 OFF
5. **T1（完了順序不変性）・T2（発火オラクル）**
6. **g 更新則を ON** — ペルソナ → (g⁰, η, λ) のマッピングを固定
7. **θ 較正パイロット** — 1 日ラン。同時に発火数分布とスループットを実測し、本選の人数・日数を確定
8. **環境フィードバック規則（最小 3 つ）** — ON/OFF を条件化
9. **初期値条件 F / N / P の切り替え実装**

**物理層は「境界インターフェースだけ実装して中身はスタブ」で本選に入る。** インターフェースが切ってあれば本選後に差し込める。本番ランで物理を動かすと決定論の検証コストが 10 日間を食い潰す。

## 8. 観測量

この設計は制御機構であると同時に測定器である。以下が自動的に取れる。

| 観測量 | 意味 |
|---|---|
| `g` ベクトルの時間発展 | 注意の向き先の軌跡。分散の拡大 = 役割分化の一次証拠 |
| 予測的中率（チャンネル別） | 世界モデルの精度 |
| 発火連鎖グラフ | A の行動が B のチャンネルに誤差を生み B が発火した、という**因果経路**が記録から直接辿れる |
| 発火数の時系列 | バースト = 集合的注意のイベント。L2（物語的虚構）の発生指標になりうる |
| `g(0)` の分散 vs `Δg` の累積 | 「生まれつきか創発か」の分散分解 |

**発火数の時系列は競争的発火では原理的に観測できない**（常に上位 N 体で一定になる）。閾値方式を選んだ理由がここにある。

## 9. 測定指標の扱い（分析側）

エージェントの成長・衰退を **% で測らない**。初期値が小さい個体で発散するため（0.1 → 0.2 が +100%、10 → 12 が +20%）。

代わりに:

- **対数変化 `log(final/initial)`** — 対称で加法的。伸びと縮みが同じスケールになる
- または成長率を初期値で回帰した**残差**（= 初期条件で説明できない成長）
- **順位変化（Spearman）** — 頑健で読み手に伝わりやすい

また**単一スカラーに潰さない**。語彙専門度・関係次数・発火数・目標達成度をそれぞれ別の対数変化率として出す。潰した瞬間に「何が成長したのか」が言えなくなる。

指標名は価値判断を含まない形にする（「成長率」ではなく「語彙専門度の変化率」）。

## 付録: 却下案とその理由

| 却下案 | 理由 |
|---|---|
| LLM に「次に考えるまでの時間」を出力させる | 「次の N 分は環境を無視する」宣言になり、環境駆動と競合する |
| LLM が `g` を宣言する | モード崩壊（全員がほぼ同じベクトルを返す）。また自分の過敏さは自分では設定できない |
| 監視仕様に有効期限を持たせる | 時間軸が裏口から入る。上書きは次の発火時のみ |
| フラット初期値のみで走らせる | 中立ではなく、非人間的な強い仮説。初期値は実験条件にすべき |
| 競争的発火（毎 step 上位 N 体） | 同期発火が原理的に観測できなくなる |
| 遅延キュー + エイジング | 同期バリアを採るため不要 |
| 負荷連動の小型モデル振り分け | 品質低下がイベントと相関し、世界の性質と資源の都合が分離できなくなる |
| LLM をブラックボックス発火判定器にする | 予算の無限後退・測定器の独立性・再現性の 3 点で不可（較正用途のみ可） |
| LLM が環境イベントを宣言する | 世界が「エージェントが言ったこと」になり物理制約の前提が消える |
| 社会レイヤーを秒オーダーにする | 1 step = 1 発話は行動レイヤーの話であり、物理層の管轄 |
