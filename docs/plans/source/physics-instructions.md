# Claude Code 指示書：局所物理エンジンとイベント駆動思考の導入

本選開始（8/15）までに、物理エンジンの選定・統合と、固定10分刻みからイベント駆動への思考タイミングの移行を完了させるための指示書です。**Part 順に、一度に一つずつ Claude Code に渡してください。**

---

## 共通の前置き（毎回の冒頭に付ける）

このリポジトリは渋谷を舞台にした LLM マルチエージェント社会シミュレーションです。R1 ドクトリンという設計規約があります。新機能は既定 OFF、既定 OFF 時にゴールデンランと L1 バイト一致、LLM 呼び出し回数 k に世界状態が非依存、no-fingerprint（実験条件がエージェントから観測可能な痕跡を残さない）、乱数は用途別専用 stream。既存テスト（pytest 1,391本）が落ちる変更は採用しないでください。落ちた場合はテスト側を直さず原因を報告してください。

今回の変更は大きいため、**すべての新機能は機能レジストリに登録し、既定 OFF で入れてください**。物理と可変思考が OFF のとき、既存のグラフ世界・固定10分刻みの挙動がバイト一致で維持されることが、各 Part 共通の受け入れ条件です。本選ランで最悪物理を切っても観察ランが成立する、という退路を常に残します。

各 Part の着手前に、変更予定ファイル一覧と設計方針を提示し、私の確認後に実装してください。

## Part P0：時間アーキテクチャの二層化（最初にやる。全ての土台）

### 背景

現在は「1 step = 10分」が世界の進行と思考の頻度を兼ねています。これを分離します。10分刻みは計算資源の制約から来た暫定であり、思考のタイミングは本来、世界の出来事と個体の状態から決まるべきものです。

### 実装してほしいもの

**(1) 世界時間と認知時間の分離**

- **世界 tick**：世界状態の更新単位。固定刻み。物理領域の内側では細かい dt（後述）、外側では現行の粗い刻み。
- **認知イベント**：エージェントが LLM で思考するタイミング。世界 tick から独立し、イベントキューで管理する。

シミュレーションループを「固定 tick で世界を進めつつ、優先度付きイベントキューから期限の来た認知イベントを取り出して処理する」構造に書き換えてください。**キューの順序は (発火時刻, agent_id) の全順序で決定論的に**してください。同時刻イベントの処理順が実行環境で変わってはいけません。

**(2) 認知イベントの発火源**

以下の三種類を実装してください。

- **定期発火**：エージェントごとの基本思考周期。ペルソナと状況（睡眠中は伸びる等）で変調される。現行の10分固定は「全員の基本周期が10分・他の発火源なし」という特殊ケースとして表現できること。これが後方互換の要です
- **顕著性発火（salience interrupt）**：知覚に顕著な変化が起きたとき（後述の Perception 契約の salience スコアが閾値を超えたとき）に、次の定期発火を待たず思考をスケジュールする。物理層からの「押された」「進めない」「人垣ができている」はここに乗る
- **内部発火**：ニーズ閾値の突破、約束時刻の接近など、世界ではなく自己状態からの割込み

**(3) 現実の人間の時間データへの較正フック**

思考頻度・反応時間の分布をハードコードせず、**較正テーブルとして外部化**してください。文脈カテゴリ（歩行中/会話中/作業中/休息中）× 刺激種別ごとに、思考着手までの遅延分布と基本周期のパラメータを持たせます。初期値は仮置きでよいですが、私が後から人間の実測データ（反応時間研究・行動観察データ）で差し替えられる構造にしてください。テーブルの内容は metrics 同様ハッシュ化して manifest に載せます。

**(4) k 非依存則の再定義**

可変頻度思考は「LLM 呼び出し回数が世界に影響する」機能そのものなので、従来の k 非依存則と正面から矛盾します。次のように再定義してください。

- 旧則（呼数が世界状態に影響しない）は、**可変思考フラグ OFF のときに従来どおり成立**すること
- フラグ ON のときの新しい不変量は「**認知イベントのスケジュール列が同一なら、世界状態が同一**」であること。つまり非依存の対象を「呼数」から「スケジュールの再現性」に移す
- 認知イベントの発火時刻・理由・トリガー元をすべてジャーナルに記録し、事後にスケジュール列そのものを解析対象にできること（思考頻度の分布自体が観測量になります）

### 受け入れ基準

- 可変思考 OFF で既存ゴールデンと L1 バイト一致
- 同一 seed・同一設定で 2 回実行し、認知イベントのスケジュール列と世界状態が完全一致
- 基本周期をエージェント間でばらしても、イベント処理順が決定論的であること

## Part P1：Perception / Intent 契約（物理エンジンより先に切る）

### 背景

エージェントコアと世界の結合面を二つのデータ型に限定します。物理エンジンはこの契約の**裏側**に入るので、契約が先、エンジンが後です。

### 実装してほしいもの

**(1) `Perception`**

エージェントが 1 回の思考で受け取る世界情報の唯一の型。視覚（見えている POI・エージェント・サイネージとその概況）、聴覚（聞こえた発話とその明瞭度）、身体（現在位置、移動の成否、混雑による遅延、接触）、内部状態（ニーズ、時刻感覚）。各項目に **salience スコア**を付与し、P0 の顕著性発火はこのスコアを参照します。

**重要**：Perception の生成はすべて世界側の責務です。プロンプト構築コードが world state を直接読む経路を全廃し、Perception 経由に一本化してください。直接参照が残っていないことを静的検査で確認するテストを書いてください（真偽台帳の漏洩検査と同じ型の検査です）。

**(2) `Intent`**

思考の出力の唯一の型。移動目標（POI または座標）、急ぎ度、回避傾向（人混みを避ける/構わない）、対話意図（相手・話題）、滞在意図。**Intent には物理的な実行の詳細（経路の各点、速度の時系列）を含めない**でください。実行は世界側・物理側の責務です。

**(3) グラフ実装での充足**

現行のグラフ世界のまま、この契約を満たす実装に置き換えてください。この時点では挙動は変わらないはずです（Perception の中身が従来システムが渡していた情報リストと等価になるだけ）。契約化フラグ OFF で従来経路、ON で契約経路とし、**両経路で世界状態が一致すること**をテストしてください。一致を確認できたら、以後の Part は契約経路の上に積みます。

### 受け入れ基準

- 契約経路 ON/OFF で世界状態が一致
- プロンプト構築コードから world state への直接参照ゼロ（静的検査）
- Perception に真偽台帳由来の値が混入しないこと（既存の漏洩検査に統合）

## Part P2：物理エンジンの選定（実装ではなく比較検証タスク）

### 指示

局所領域（スクランブル交差点・ハチ公前広場・駅構内通路を想定）の歩行者群衆物理として、以下の候補を**実際に小さなプロトタイプを書いて**比較してください。評価は口頭比較ではなく、同一シナリオ（幅員の異なる通路での対向流・交差流、200体）を各候補で動かした実測で行うこと。

**候補**

1. **RVO2 / ORCA 系**（Python バインディングまたは自前移植）：速度障害物ベースの衝突回避。決定論的に実装しやすく、群衆の合流・すれ違いの再現性に実績
2. **Social Force Model 自前実装**：連続力学モデル。実装が軽く、パラメータが物理量として解釈可能で、実測データ（歩行速度分布・密度-流量関係）への較正がしやすい
3. **JAX/NumPy によるベクトル化自前実装**（1 か 2 のアルゴリズムをGPU向けに）：A5000 が7枚ある環境を活かす場合の選択肢

**Isaac Sim / Unity / Unreal などのフルエンジンは今回選定対象から除外します。** 理由：本選までの残り日数で決定論性の確保（後述）とヘッドレス統合まで到達する見込みが低く、剛体精度は歩行者群衆の研究課題に対して過剰なため。エンジンの導入自体は本選後の課題として残します。

**評価軸（この順で重み付け）**

1. **決定論性**：固定 dt・固定処理順で、同一入力から同一軌跡がバイト再現できるか。浮動小数演算の順序を固定できるか
2. **境界の縫いやすさ**：グラフ世界との出入り（後述 P3）を実装したとき、境界で不自然な挙動（急停止・瞬間移動・振動）が出ないか
3. **較正可能性**：歩行速度分布、密度-流量曲線（基本図）を実測データに合わせ込めるパラメータ構造か
4. **速度**：200体・物理 dt 0.1〜0.5秒で、シミュレーション時間に対して十分速いか（目標倍率は現行ランの実測から逆算して提示すること）
5. 実装・保守の単純さ

**成果物**：各候補のプロトタイプコード、同一シナリオでの軌跡比較（動画または軌跡プロット）、決定論性テストの結果、推奨案と根拠。**私が選定を承認してから P3 に進んでください。**

## Part P3：空間 LOD と境界縫合

### 実装してほしいもの

**(1) 物理領域の定義**

`physics.zones` として、物理シミュレーションを回す領域をポリゴンで定義できるようにしてください。初期はスクランブル交差点＋ハチ公前の 1〜2 領域から始めます。領域外は従来のグラフ移動のままです。

**(2) 境界プロトコル**

- **流入**：グラフ側でエージェントが物理領域の境界エッジに到達したら、境界上の流入ゲートに物理エージェント（位置・速度・目標出口）として生成する。初期速度はグラフ側の移動速度から連続に引き継ぐ
- **流出**：物理側で出口ゲートに到達したら、対応するグラフノードに配置し直す
- **時間整合**：物理 dt と世界 tick の比は整数に固定し、世界 tick の境界でのみ流入・流出を確定する
- 境界通過のログ（誰が・いつ・どのゲートを・何秒かけて）をジャーナルに記録すること

**(3) 物理→知覚の翻訳**

物理領域内のエージェントの Perception には、物理由来の項目を入れてください。局所密度（周囲の混み具合）、進行の阻害（意図した速度に対する実速度の比）、接触・押し合いの発生、視野内の人垣・滞留。これらの salience を適切に設定し、「進めない」が顕著性発火につながることを確認してください。

**(4) Intent→物理の翻訳**

Intent の移動目標・急ぎ度・回避傾向を、物理エージェントのパラメータ（希望速度、回避半径、目標点）に写像してください。写像テーブルは較正テーブルと同様に外部化し、ハッシュを manifest に載せます。

**(5) 決定論性**

物理層は **strict 等級**で実装してください。固定 dt、エージェント処理順は agent_id 昇順、乱数（あれば）は専用 stream、浮動小数の集約順序固定。同一入力からの軌跡バイト再現を CI テストにしてください。GPU でのベクトル化を選んだ場合、GPU 浮動小数演算の非結合性で再現が壊れる場合があります。その場合は「物理は CPU で strict、GPU は LLM 推論専用」という分担に倒してください。**速度より決定論を優先します。**

### 受け入れ基準

- `physics.zones` 空（物理 OFF）で既存ゴールデンと L1 バイト一致
- 同一 seed で物理 ON のラン 2 回が世界状態・軌跡ともに一致
- 境界通過で位置・速度の不連続（瞬間移動・急停止）が発生しないことをシナリオテストで確認
- 物理領域の存在がプロンプト文言から検出できないこと（no-fingerprint：Perception の語彙は領域内外で同一の型・同一の表現体系を使う）

## Part P4：較正（実測データへの合わせ込み）

### 実装してほしいもの

1. **歩行の基本図の較正ハーネス**：密度-流量関係・歩行速度分布について、物理パラメータを実測データセットに合わせ込むスクリプト。データは私が用意するので、CSV スキーマを先に提案してください
2. **較正結果の凍結**：合わせ込んだパラメータセットをバージョン付きで保存し、ハッシュを manifest に記録。ラン中の変更は不可
3. **検証プロット**：較正後のシミュレーション出力と実測の比較図を自動生成（基本図の重ね描き、速度分布の重ね描き）

これは物理層を「私の手癖」ではなく「外部の実測に釘付けされた層」にするための工程であり、この装置の正当性の根拠になる部分です。省略しないでください。

## Part P5：思考頻度の観測装置化

P0 で認知イベントがジャーナルに乗っているので、解析を追加してください。

- エージェント別・文脈別の思考間隔分布
- 顕著性発火の頻度と、その原因種別（物理由来/社会由来/内部由来）の内訳
- 物理領域内外での思考頻度の差
- 可変思考 ON/OFF の対照ランで、既存指標（語彙専門化・信念分岐・下方因果）がどう変わるか

思考のタイミング自体が研究対象になります。「環境が知覚を通じて思考の頻度そのものを変える」ことが示せれば、環境が行動だけでなく認知のリズムを駆動するという主張の直接の証拠になります。
