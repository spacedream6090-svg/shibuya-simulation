# デジタルツイン定義のすり合わせ

日付: 2026-08-01

## 背景・出発点

Claude Code での実装が、リアルタイム性および現実との同期性を重視しすぎているのではないかという問題意識。デジタルツインの定義を相互に確認し、あわせて 3D シミュレーションと 2D シミュレーションの違いを整理する。

---

## 1. デジタルツインの本質は「同期」ではなく「反実仮想の妥当性」

同期頻度は目的から逆算される従属変数であり、上げれば上げるほど良いものではない。

### 産業系の3分類

| 分類 | データ連携 |
|---|---|
| Digital Model | 自動連携なし |
| Digital Shadow | 現実 → 仮想の一方向 |
| Digital Twin | 双方向 |

「双方向・リアルタイム」がツインの条件とされるのは、タービンや工場のように**状態空間が低次元で観測可能**だから。センサーで状態を合わせれば予測が当たる。

### 都市の社会現象には当てはまらない

人の内部状態は観測できず、秒単位で合わせるべき変数がそもそも存在しない。ここで realtime を追うのは製造業からの**カテゴリの借用ミス**。合わせるべきは瞬間の状態ではなく、**分布と較正**。

---

## 2. 環境をツインとする定義では、改変可能性が主役になる

「ツインは環境視点であり、エージェントは含めない」という定義は妥当。ただしそう置いた瞬間、同期対象は座標ではなく**環境のアフォーダンス**（通れる / 見える / 滞在できる / 開いている）になる。

### 同期性と改変自由度のトレードオフ

- 実験のためには環境を改変する必要がある
- しかし**現実との同期を強めるほど、改変の自由度は下がる**
- サイネージの位置を動かした瞬間、それは現実の双子ではなくなる

→ 求めるべきは「現実に追従し続ける双子」ではなく、**現実から出発できる編集可能な世界**。同期は初期条件と較正のためだけに必要。

---

## 3. 合意した立場

### 包含関係

**メタバースの一部にデジタルツインが存在する**（ツイン ⊂ メタバース）。

### 同一性の根拠

環境を改変した後の世界も、引き続き「ツイン」と呼ぶ。
この立場では、同一性の根拠が**対応（いま現実と一致しているか）から系譜（現実から派生したか）へ移る**。

### 系譜的同一性を採る場合の義務

**現実ベースラインからの差分を明示的に管理すること。**
どこを弄ったか追跡できなくなった時点で系譜が切れ、単なる創作世界になる。改変はコードではなく**データ側の差分**として記録する。

---

## 4. 2D と 3D の分岐点 —「幾何が因果に噛むか」

次元は精度の話ではなく、**どのメカニズムを因果として主張するか**の宣言。

### 3D が必然になる領域

幾何が媒介する現象のみ。

- 遮蔽
- 視線・視野角
- 距離減衰
- 高さ方向
- 高密度時の身体的干渉

広告のインプレッションはまさにここ。「見えたか」は視錐台と遮蔽の関数であり、2D では原理的に定義できない。視覚の導入と広告効果の測定が同じ場所に着地するのは必然。

### 2D（位相・グラフ）で足りる領域

- 意思決定
- 関係形成
- 語彙伝播
- 経済交換

ここを 3D 化しても説明力は増えず、歩容や衝突といった**未検証パラメータが大量に増えて分散だけ上がる**（忠実度の罠）。「本当に動いた」の検証がむしろ難しくなる。

### 推奨する層分け

- **メカニズム層**: 2D / グラフ
- **観測層**: 3D。幾何由来の変数（可視性・被視認・混雑）を返す関数として置く
- **結合**: 原則片方向。3D からはスカラーのみ返す

---

## 5. 3D の利点 —「見て確認できる」以外

効く順。

### 5.1 設計者の仮定が世界の事実に変わる

2D では移動時間・遭遇確率・収容人数をすべて手で決める必要があり、それは設計者の指紋になる。3D なら経路長・共在・床面積から自動的に導出される。検証時に最も厄介な「その挙動、仕込んだのでは?」への反論資材になる。

### 5.2 偶発的遭遇を仮定せずに済む

研究課題に直結する最大の理由。都市集中の創発を問うなら、その核は計画外の遭遇。しかしグラフモデルでは遭遇率がパラメータであり、**答えを先に置いてしまっている**。幾何があれば遭遇は共在から生じ、ネットとの比較実験が初めてフェアになる。

### 5.3 部分観測性が無料で手に入る

遮蔽・距離・照明・角度により、エージェントごとに情報集合が異なる。2D では「知らないこと」を人工的に作る必要がある。噂の分岐を主題にするなら、**情報非対称性が外挿ではなく内生する**ことは決定的。

### 5.4 共有参照点と、視点差による誤差

物理的虚構が立ち上がるには、複数のエージェントが同じ物体を別の視点から見る必要がある。2D では「像がある」という同一の記号が全員に配られるだけで誤解が生まれない。3D なら「夜に遠くから見た人」と「昼に間近で見た人」の記述が食い違い、そこから物語が育つ。

### 5.5 介入点が現実で購入可能な単位になる

サイネージの位置、階段、営業時間。これらは行政や広告主が実際に買える・動かせる単位。グラフの辺重みを変えても現実に対応物がない。広告ネットワークの事業化まで見るなら、可視性は幾何でしか定義できない。

### 5.6 人間と混在できる

同じ空間に VRChat / cluster から人間が入れる。人間の行動をグラウンドトゥルースとして較正に使え、ツインがそのままプロダクトになる。2D には存在しない性質。

### 5.7 世界がエージェントの発話を反証できる

言語だけで閉じると幻覚が検出できない。レンダリング結果と矛盾する発話を弾ける、安価な整合性チェック。

---

## 6. 実装上の線引き

**5.1 〜 5.5 は、2.5D の幾何 + 事前計算した可視性グラフで大半が手に入る。**

剛体物理エンジンが必要なのは、身体レベルの干渉（高密度時の圧力、接触、物体操作）が因果に噛む場合のみ。研究課題はそこにない。Isaac Sim 級を導入すると未検証パラメータが跳ね上がり、5.1 で得た検証上の優位を自ら潰しかねない。

> **可視性は本気で、力学は最小限で。**

---

## 7. まとめ（実装方針）

1. リアルタイム同期は追わない。同期は初期条件と較正のためだけに使う
2. 合わせるのは瞬間の状態ではなく、分布と較正
3. 現実ベースラインからの差分をデータ側で明示的に管理する
4. メカニズムは 2D / グラフ層に置く
5. 3D は観測層とし、幾何由来のスカラーのみを返す
6. 可視性計算は 2.5D 幾何 + 事前計算の可視性グラフで実装
7. 剛体物理は導入しない（身体干渉が因果に噛む課題が出るまで）
