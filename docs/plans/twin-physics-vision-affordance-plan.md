## 1. リポジトリ調査報告(A〜D が接する現状)

結論から: **4系統とも「ゼロから作る」項目はほぼ無い。大半は既存資産の配線・一般化である。**

### 1.1 環境表現(A の接点)

- 地図は OSM JSON(現行既定 `world.map=data/shibuya_osm.json`・広域版 wide_v7 は 7,210 棟)。建物は
  **フットプリント+階数(levels)の 2.5D で実高さを持たない**。入口実データは 3,000 棟中 15 件のみ。
- **`data/plateau/` に PLATEAU 実高さ 6,311 棟(height/base/LOD1-2 メッシュ)+ OSM⇄PLATEAU 対応表 3,531 棟
  (`plateau_match.json`・IoU≥0.4)+ 2m 格子 DEM(1088×921)が既にあり、抽出パイプライン
  (`scripts/plateau_extract.py`/`match_plateau.py`)も完成している**。欠けているのはシム側の配線だけ
  (`src/` から `data/plateau/` を読むのは `simulation.py:101` の terrain.npz 1 行のみ・既定 OFF・「表示専用」宣言つき)。
- 営業時間は実装済み・既定 OFF(`commerce.py:103 is_open()`=時刻の純関数)。**照明は grep 0 件で存在しない**。
- **サイネージ/広告の骨格は既にある**(`src/society/street.py`・第18バッチ・既定 OFF): 掲出枠(large/slots)・
  キャンペーン・視認確率・クールダウン・日次上限・想起窓・有効フリークエンシー・L1 `ad_exposure`/`ad_campaign`・
  プロンプト 1 行(`ads_line`)。広告主はシム内実在 POI なので接触→来店→購買のファネルが世界内で閉じる。
  足りないのは (i) 掲出地点の実データ(基盤 conf は空リスト) (ii) **視認判定が距離のみで LOS を見ていない**
  (`street.py:216-218`) (iii) 照明・向き・時間帯。
- 環境パラメータの conf 面: `world:` ブロック(`map`/`scenario`/`perception_radius_m`/`modes.speeds`/`traffic`/
  `vision`/`scene_desc`/`elevation`/`calendar`)+ EnvPack(場所の値の外出し・**別都市 shimokita の実例あり**=差し替え機構は実証済み)。
  摂動カタログ `world/scenario.py`(`shock_closure`=道路封鎖)が「環境改変条件」の既存の種。

### 1.2 物理・幾何(B の接点)

- **二層は屋内で既に動いている**: 認知 step(10分)⇄ 屋内サブステップ(SFM dt=0.2s・遷移駆動=区画遷移の瞬間だけ積分)。
  ハンドオフは `_phase_indoor`(`scheduler.py:4224`)。接触ペア抽出・`indoor_tracks_*.parquet`(1 サンプル/秒)・
  **L1 バイト不変がテストで表明済み**(`tests/test_indoor_invariance.py`)=「物理層を足しても観測が汚れない」既存パターン。
- 屋外用部品も既にある: `sfm_core.py Crowd`(開放領域 SFM)+ `SignalGate`(信号・スクランブル)+
  `data/crossings_shibuya.json`。**未配線なだけ**。
- 3D 再生(レベル0)はほぼ完成: `scripts/export_3d.py --plateau`(L1 だけ読む・シム非依存)→ `viz/make_viewer3d.py`
  (three.js r128 完全ベンダリング・Cesium 不使用)。L1 は**全行 (x,y) 必須**+`move_segment.pts`(step 内ポリライン)。
  再生専用ツールは 60 本が「L1 を読むだけ」の疎結合パターンに乗っている。

### 1.3 スケジューラ・LLM 予算・乱数・ゴールデン(不変条件の接点)

- `run_step`(`scheduler.py:4395`)1 本・63 フェーズ。環境系フェーズの差し込み位置は「位置確定後(#45 街頭広告)→
  知覚索引構築(#46)」の間が正位置。
- **驚きゲートは存在しない**(2026-07-04 に欲求駆動発火へ移行済み。`lod.congestion_surprise` は死んだ conf キー)。
  発火は `_phase_drive` の予算つき抽選(`sim.budget.take()`)。**★予算は発火と返答保証のみをカバーし、
  朝の計画と夜の内省は予算外**=`lod.max_llm_per_step` は日次総呼数を拘束しきれていない。
- 呼数の均等化は `controls.mode=compute_matched`(k=off でも内省呼びを実行して捨てる)+
  `test_*_call_count_k_invariant` 16 本。**★実査で発見: 最新スイープ endo7 は `controls.mode: none` で回されており、
  k=off/free の呼数が 9.5% 乖離している(5944 vs 6507)** — D17 本実験の前に修正が要る(P0)。
- 実測呼数: **14〜25 呼/agent/日**(mock 実測・10,000体1日=18.95、300体100日=23.10)。
- 乱数は `RngHub` 完全ステートレス keyed stream(**68 種以上**)。新機能は「新 stream」か「既存 stream の
  always-draw 再利用」のみ(ON/OFF で draw 数・順序不変=CRN 共分散維持)。
- ゴールデンは `tests/data/golden_baseline_l1.json`(1,711 イベントの生ダンプ・15体144step)。
  **再生成の前例ゼロ**。既定挙動の変更が不可避なときは `tests/test_scenario.py:45` の append-only
  中和オーバーライド(過去 5 件)に足すのが唯一の先例。テスト総数 1,739(bool フラグ 160 個中 124 個が既定 false)。

### 1.4 知覚・視覚(C の接点)

- 知覚チャネルは事実上 **1 本(可聴=同一 context×40m×非睡眠)**。「見える」と「聞こえる」は同一集合。
- 実装済み・全部既定 OFF の視覚資産: `world.vision`(壁+建物フットプリントの 2D 線分遮蔽)・`world.scene_desc`
  (方向つき視界・注視・垂直 1 行・**追加 LLM 呼ゼロの純関数**)・`indoor.los`(屋内区画 LOS・呼数不変設計)・
  `pov`(CPU 決定論レンダラ)。**高さは一切使われていない**(遮蔽は 2D のみ)→ PLATEAU 実高さと繋げば
  2.5D 遮蔽は近距離にある。

### 1.5 アフォーダンス(D の接点)

- **動詞は 21 型が受理可能**(`parse_action`)。世界改変 6 種(`host_event`/`post_flyer`/`found_group`/`propose`/
  `open_venture`/`job_search`)は `Tools.apply:615`、**提示面は `Tools.offer_text:499` の中立 1 行メニュー**。
- 原指示 D の 4 動詞の現状: **命名=あり**(`coin_label`+LabelSystem・複雑接触 adopt)・**約束/宣言=部分あり**
  (joint 誘い/承諾・第62-64バッチの内生化・提案/立候補)・**集まりの呼びかけ=あり**(`host_event`+招待DM)・
  **共有物の占有=本物あり**(`goods.py` の (node,category) 実在庫・枯渇で購買失敗・(s,S) 補充・災害で品切れ伝播
  =rivalry と控除可能性は実装済み)。評判/痕跡も既にある(`status.py` 客観カウント地位・`gossip.py` 悪評・
  relations の評判項)。
- **最大の欠落は「場所の意味づけ」**: 意味は夜の内省の `belief` テキストに落ちて**場所に戻らない**。
  `coin_label` は状況を命名できるが造語をノードに束縛する機構が無い。蓄積 3 要素のうち「痕跡(場所の意味)」だけが空白。
- 反復性の実体は EPR(正のフィードバック)+決定論日次予定。反収束の圧力(退屈ループ・価値飽和・閾値ドリフト・
  Gumbel 選択)は実装済みだが**全部 OFF**。

### 1.6 規模(25万の接点)

- 100万ペルソナプール実在(737MB・L1住民3万/L2従業者25.4万/L3定期3.7万/L4非定期67.9万/L5役割1,020・LLM生成対象2.4%)。
- **present 1万体×1日は mock 実測で完走済み**(`runs/rehearsal_pool10k`・16.2M イベント・L1 175MB)。
  線形外挿で 25万体×10日 ≈ L1 44GB(million-scale.md の独立見積と一致)。
- 壊れる順序は million-scale.md が数値化済み: ①非LLM エンジン単価(背景 tier SoA 化が唯一の関門)
  ②Agent RAM(25万×~103KB≈26GB) ③観測パイプライン(load_events 全件 RAM 展開=10⁸ 件で破綻・ストリーミング化未実装)
  ④密集セルの知覚 O(n²) 再燃。**★`runs/_bench/bench.json` は 3体スモークで上書きされスケーリング実測が失われている**(P0 で再取得)。

## 3. 環境由来指標「H(到達異質性)」の候補比較(旧称: 導出量としての k)

**命名**: リポの k は「経験→内部状態の結合強度(writeback)」として研究主軸・解析パイプライン・16 本のテスト名に
配線済み(実査 §7)。環境由来の新軸は **H = 到達異質性(reachable heterogeneity)** と命名して衝突を避ける。
研究フレームは **k(内部結合)× H(環境機会)の 2 軸**になり、「生まれつきか環境か」の環境側の操作変数が H。
本選は現実幾何 1 条件のみ = **H_real の基準点測定**。

文献の土台: Moro et al. 2021 *Nat Commun*(experienced income segregation・携帯450万人)と
"income diversity of urban encounters"(*Nat Commun* 2023)が目標概念とほぼ同一量を実データで運用済み。
時間予算は Hägerstrand の時空間プリズム(PPA)で厳密に書ける。

| 案 | 定義 | 計算に必要な環境データ構造 | 実装時期 |
|---|---|---|---|
| **H_C 非冗長性(Burt)** | 遭遇相手のうち互いに繋がっていない相手の割合 = 1 −(遭遇相手間の既存紐帯密度) | **既存の関係グラフのみ**(空間データ不要)。第64バッチ `analyze_weak_ties` に載せるだけ | **今すぐ**(レーン1・解析のみ) |
| **H_A 遭遇エントロピー(Moro 直訳)** | 単位時間に実際に遭遇した他者集合の属性分布エントロピー(属性 c = 来街層 L1-L5/職種/年齢帯など複数で報告) | 遭遇リスト。近似は**現行 L1 から即可**(hear/同席の事後復元・屋内 contacts)。厳密には B-L2 の遭遇リスト。遭遇回数で正規化し「多く歩いた効果」と「多様な場所を選んだ効果」を Moro 流に分解 | 近似=レーン1可・厳密=B-L2 後 |
| **H_B 時空間プリズム内異質性(本命)** | 当日の固定コミットメント(day_schedule)間の自由時間で到達可能な領域(PPA)に居る他者の属性分布エントロピー(Hansen 重力減衰で重み付け可) | ①day_schedule(既存) ②**edge 走行時間を第一級の改変可能属性に**(=A1 の `world.mod` がそのまま供給。歩道幅→速度、接続→開閉、改札→容量) ③場所×時間帯の在場者属性構成テーブル(presence/L1 から事後集計) | レーン3(A 反実仮想と同時) |

- **A と B の乖離自体が知見**: 「到達可能だったのに会わなかった」= Burt 的機会の未活用。
- **H は realized(A)と potential(B)の両方を持つ**ことで、「幾何が変えてよいのは『誰に会うか』であって
  『何回会うか』ではない」(不変条件1)の監査にもなる: 環境改変で H_B が動いても、遭遇**数**・LLM 呼数は
  接触容量固定で不変、動くのは遭遇の**組成**のみ — これを L1 から事後検証する。
