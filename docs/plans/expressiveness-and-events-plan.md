## レーンF — 観察(見える世界にする)

**F1: イベントフィード層(viewer+rollup)**
- 既存2系統(viz/notable_events.py の重要度表・live_viewer の HIGHLIGHT_KINDS)を単一の
  ランキング関数へ統合。スコア=ニュース価値理論(Galtung-Ruge 12因子)の実装可能部分集合:
  規模(参加者数Δ)・希少性(kind頻度の逆数)・人物化(名前付き個体へ帰属可)・
  継続性割引(同一物語の続報は閾値低減=ストーリーライン形成)・意外性(個体の行動事前分布からの逸脱)。
- ペーシング=L4D式(大事件連発後は日常描写を挟む=フィード購読者側の強度推定)。
- UI: viewerに右ペインのイベントタイムライン+クリックで該当時刻・場所へジャンプ。
- **観測専用**(experience manager の観察限定版=世界に1バイトも触れない・R1)。

**F2: 1日トレース(scripts/day_trace.py)**
指定エージェント×日の L1+l1b+journal+provlink(行為→思考リンク)+causality を時系列整列し、
計画→行動→会話→内省を1本の物語(md/HTML)へ。参考=AgentSocietyのday/t+種別タブ・
LangSmithのrun木+thread束ね・GAのrevise_identity(毎朝の自己書き換え=素材として抽出)。
基本は実文の整列(LLM不使用)・任意で要約モード。「世界か否か」の定性評価の正攻法。

**F3: 表示改善(小)**
在館者の散布を建物実フットプリント形状へ・sin揺れの除去(または歩行風の緩速化)・
低ズームでは密度表示へ切替(「四角い塊の不気味な揺れ」の解消)。

## レーンG — 集合イベントの内生化(行動から自ずと起きるイベント)

**設計(ボトムアップ定義=「集まった事実をイベントと呼ぶ」)**
- 既存: appointment(2者)・event_host(主催宣言型のN者=告知→伝播→出席抽選)・
  crowd_surge(年中行事日限定の密度検出)。欠け=**主催者なしの自然発生集合**。
- 追加する台帳(観測+最小の意図状態):
  1. 会話/DM/SNSで「場所×時間帯」トークンが伝播した系譜(flash mobの本質=日時場所指定の伝播)
  2. 予定帳に同一(場所,時間帯)を持つ個体数のカウンタ
  3. 実際の同時同所滞在(既存co-presence)が閾値を超えた時点で `gathering_emerged` を記録
     (規模・参加者・伝播系譜つき)
- 閾値は個体異質(Granovetter: 結果を決めるのは閾値分布の形)。**不発も記録**
  (Schelling: 「臨界まであと何人だったか」=現実では観察不能な量=ユニークデータ候補)。
- **呼数ゼロ**: 行動は既存機構(会話・計画・移動)が生む。追加は記録と、計画プロンプトに
  既に載っている情報の範囲内。既定OFF・finals ONは検証後に判断。
