## 0. 結論(先に)

1. **高精細化の道は PLATEAU 一本**。Google Photorealistic 3D Tiles は規約(保存/オフライン/抽出禁止)で
   公開ミラー+自己完結 HTML と原理的に非両立。ゼンリン=有償・再配布不可。3dcel(CC BY 4.0)は 2014 年取得で
   DT スナップショット定義(2026年の渋谷)と矛盾。
2. **最大の資産はすでに手元にある**: 未展開の PLATEAU 3D Tiles zip に
   **テクスチャ付き LOD2.2(bbox 内 148 タイル・WebP アトラス統合済み)/道路 LOD3(歩道の実ポリゴン)/
   地下街 LOD4.1(内壁 1,934 面・床 145・扉 188)** が入っている。ダウンロード作業は不要。
3. **推奨は「物理を先に、見た目を後に」**: 地下街 LOD4.1 と道路 LOD3 はそのまま
   自前 SFM の**対壁斥力 f_iW と歩行可能面**の入力になる(sfm_core が docstring で「意図的に省略」と
   宣言している穴にちょうど嵌まる)。テクスチャ写実(松)は研究データへの寄与ゼロなので優先度を下げる。

| 症状 | 原因(実測) | 修正 |

## 2. 実装計画(梅→竹→松)

### 第1段=梅: 地下街を「箱」から「部屋」へ(0.5〜1日 / +2〜4MB)

- `plateau_extract.py --extras` の ubld 読み取りを LOD4.1 対応に(InteriorWallSurface/FloorSurface/
  CeilingSurface/Door/ClosureSurface を面種別タグ付きで plateau_web.json extras へ・**追加専用**)。
- ビューワーで床=不透明・内壁=半透明・扉=強調の塗り分け。第0段の「ubld 既定 OFF」は
  この塗り分け完成をもって「地下表示レイヤ」として再 ON。
- 検収: `--plateau` なし出力のバイト同一。

### 第2段=竹: 物理シムへの幾何供給(3〜5日 / +10〜20MB)★推奨・P3 と同一レーン

**P2 承認(自前 SFM 推奨)を前提**に、cognition-physics-plan の P3 縫合と統合して1レーンで実装する:

| バッチ | 内容 | 対応 |
|---|---|---|
| 竹-1 | 新規抽出器 `plateau_tran_extract.py`: tran LOD3 の TrafficArea_function(2000/2010/2020/2030=歩行系)で**歩道実ポリゴン**+**LOD3 被覆マップ**を出力(被覆は bbox の約半分→被覆外は OSM 線分フォールバックの二層設計) | 歩行可能面の実形状 |
| 竹-2 | ubld LOD4.1 → **壁線分**(鉛直面の水平投影・両面重複除去)+**フロア面**(FloorSurface の z クラスタリングで層分離)+**ゲート点**(Door 188)。範囲は渋谷駅地下街 332m×410m のみ=「屋内 SFM=地下街ユースケース」と明示限定 | f_iW の入力 |
| 竹-3 | `sfm_core.Crowd` に**対壁斥力 f_iW を追加(既定 OFF)**。壁最近点は空間ハッシュ。docstring の「意図的省略」節を設計変更として書き換え | Helbing 2000 完全形へ |
| 竹-4 | **P3 縫合**(physics.zones ポリゴン定義・流入/流出ゲート・物理→知覚翻訳)を竹-1/2 の実ジオメトリで実装。dt=0.02-0.05s・第85 Perception 契約が受け皿 | cognition-physics-plan §4 |
| 竹-5 | `world.mod.歩道幅係数` の原点(実測 1.0)を歩道ポリゴン実幅から定義+較正簡易版(P4) | 環境軸 H の実測原点 |

- 検収: 既定 OFF=golden L1 バイト一致・ON 同 seed 2ラン一致・決定論(乱数ゼロ積分)・フルゲート緑。
- 目標: **〜8/11**(P3 目標と同じ。直近の実速度なら 8/4 着手で十分)。8/12-14 はフリーズ。

### 第3段=松: テクスチャ付き写実 LOD2.2(2〜3週相当 / 分離版推奨)— **本選後 or 本選中の観察レイヤ作業**

- 手元 zip の bbox 内 148 タイル→ b3dm から GLB 抽出(28B ヘッダ計算のみ・実証済み)→
  Draco を **Python 側でオフライン解凍**(新規依存は tools/ に隔離)→ **既存 int16 コーデック+UV(uint16)** に再焼き込み→
  WebP アトラスを 1/2 解像度で `data:` URI 埋め込み(ランタイム依存ゼロ・three.js r128 のまま・148 ドローコール)。
- 容量見積: 埋め込み版 ≈74MB(80MB ゲートぎりぎり)→ **分離版(viewer3d_lite + サイドカー)を主経路に格上げ**。
  縮退順を事前確定: テクスチャ 1/2 → 1/4 → LOD2.2 領域のみ → 全廃。
- 副産物: batchTable(gml_id/usage/階数/住所)で plateau_match 照合率 49% の改善。
- **推奨タイミング**: 本選 10 日ラン中(8/16-26)は GPU が塞がるが CPU と観察レイヤは空く。
  src/ゼロタッチの松はこの期間の並行作業に適する(ラン成果物のビューワー生成は事後なので干渉しない)。
