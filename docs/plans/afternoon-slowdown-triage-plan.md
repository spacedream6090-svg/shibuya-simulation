# 午後帯step時間劣化のトリアージ+対策準備計画(2026-08-20・実装は承認待ち)

> 症状: smoke_wit2_day(25k×72step・ATT層A ON+WIT ON)で step時間が**超線形劣化**:
> 朝〜正午1-2分 → 14-15時帯~3分 → 15-16時帯~14分 → 16時台の1 stepで25-40分以上(進行中)。
> LLM呼びは正常(~250/step・cap内・劣化中は沈黙=エンジン相)・CPU 100%単核・RSS 4GBで微増のみ。

## 0. ★確定(2026-08-20 17:19・py-spy火炎図 362,182サンプル/4時間・25k mock・finals conf)

**犯人=物理ゾーン積分(SFM/ORCA)。全時間の78.5%。**

- 超線形の機序: サブステップ数は固定(12,000)だが**夕方はゾーン人口が増え、かつゾーンが
  600秒間ずっと非空**(朝は空でbreak)→ per-substepコスト×稼働率の両方が伸びる。
- ★訂正: stock_out×1,500洪水は「同じ混雑の症状」であって**step時間の主因ではない**
  (火炎図でtruth_ledger圏外・belief 26万行はWIT後は安価)。INV/FACT-Dの意義は
  現実整合+fact衛生+RAMであり、**step時間の対策は物理レーン**である。
- prof_attの傍証: L1フラッシュ間隔が 3分→6分→14分→30分と伸び、14:55以降2.5時間パーツ無し
  =夕方帯は1 step 30分超。プロセスはpy-spy上限(4h)まで生存。

### 対策レバー(物理・承認待ち)
- **P1(conf 1行)**: `density_far.update_every` 10→30(場の再構築0.5s→1.5s周期)。
  _density_grid 24.3%→1/3 = **全体−16%目安**。読み出しは毎サブステップのまま=軌跡への影響軽微。
- P1b(conf 1行): `density_far.blur` 2→1。_box3半減=−10%目安。**場の平滑度が変わる=P2較正に触る**ので非推奨。
- **P3(コード・L3型半日)**: _box3の積分像(cumsum)化・_density_grid のbincount+平滑の融合等。
  WIT型検収(逐語同値の機械証明+OFF不変+フルゲート)。効果は実装後実測。
- P4(判断材料): 250k外挿は「ゾーン面積が物理的にmember数を頭打ちにする」ため単純×10ではない。
  ただし待機列(_admit)コストが未知=**250k縦煙で夕方帯を必ず実測**してから本選ON/OFFを判定。
