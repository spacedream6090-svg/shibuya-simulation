## 第1部: 決定事項(ユーザーの選択が要る)

### ✅ D0. プロジェクトのゴール定義 ★他の全決定の前提 — 【決定 2026-07-03】
- **決定**: **ゴール(必達)= (1) 測定器の完成 + (2) シミュレーション世界のチューニング + (3) k の予備的兆候の観察**。**ストレッチゴール = k* の確定**。
- **含意**: 本選10日は「測定器+チューニング+兆候」に全振りし、k* 確定は時間が許せば挑戦。→ design §4/§14 をこの二段ゴールで更新する。
- 元の材料: red-team 見積り = k* 確定は成功率 5-15%、測定器+兆候は 35-50%([[risk-register]] 総評)。

### ✅ D1. 被説明変数(何を「世界改変」と測るか) — 【決定 2026-07-03】
- **決定**: **連続量(4層への書き換え量)を主指標、二値判定(改変者か否か・別ファミリ LLM-judge)を補助**。
- **含意**: observer は4層への書き換え量を客観計上できるよう設計。judge は補助・校正用(κ≥0.7)。検出力が桁改善+judge 循環回避。
- 元の材料: red-team R2/R4。

### ✅ D2. build-vs-reuse(エンジン基盤) — 【決定 2026-07-03: 案B】
- **決定**: **(B) 自前 lean core**。world/factors/labeling/observer/drift を自作、スケール様式は AgentScope/OASIS を参照(依存にしない)、認知部品は Concordia から再実装(移植でない)。
- **含意**: リポジトリは自前構成。依存は vLLM・数値/DB・skmob 等の個別ライブラリのみ(FW 丸ごと依存を避ける)。10日×1人の統合リスクを最小化。

### 🟡 D3. 言語(日本語/英語/ハイブリッド) — 【仮決定 2026-07-03: 日本語運用】
- **仮決定**: **日本語運用を基本**とする。ただし **A5000×7 実機で動作確認してからモデルを最終選定**するため、**言語も仮決定**(実機ベンチ後に確定)。
- **含意**: 当面は日本語前提で設計を進める(プロンプト・トークン予算・N 上限見積りは日本語基準)。日/英 ablation を1本入れる余地を残す。実機で日本語トークン倍率・スループットを実測し、必要なら英語/ハイブリッドに再考。
- 材料(検証済): Qwen3.6-27B の日本語は十分(Qwen3.5-27B が Nejumi 0.80=24GB級トップ)。日本語はトークン2-3倍で N 上限低下。

### ✅ D4. モデル戦略(運用 + RLHF 対照) — 【決定 2026-07-03: 両方(abliterated 主 + base 副)、実機で最終確定】
- **運用(既定・仮)**: Qwen3.6-27B(AWQ-INT4 `cyankiwi/...` 19GB, Apache-2.0)。実機動作確認後に最終確定(D3 と連動)。
- **RLHF 対照 = 両方の二軸で三角測量**:
  - **主対照**: 同一モデル **Qwen3.6-27B instruct ↔ abliterated(Heretic 手法)**。同一モデル・同一言語で「拒否・同調の抑制」だけ on/off = 最もクリーンな交絡分離。※vLLM 用に**自前 AWQ 量子化が必要**(GGUF 主のため)。
  - **副対照(予算許せば)**: 同一系列 **base ↔ instruct**。OLMo-2-32B(完全オープン・統制最良・英語)または Qwen2.5-32B(日本語強・Apache-2.0)。「事後学習の全体」を測る。
- **含意**: model は config で差し替え可能に(既にある seam)。model×k を実験計画の第一級要因に。
- **要検証(残)**: MTP×4bit 併用は未文書化+既知不具合 → **初日は MTP なしで安定運用**。abliterated の能力劣化は自前 TruthfulQA/GSM8K で裏取り。実機ベンチ後にモデル最終確定。

### ✅ D5. 因子の down-select(OPEN#1) — 【決定 2026-07-03: 暫定案(拡張余地あり)】
- **決定**: trait={NFC, リスク許容, 内的統制} / state={効力感, 不満, 当事者意識} で開始。**因子は seam で拡張可能**にし、社会的アイデンティティ・集団効力感は必要時に追加(第2弾)。
- **含意**: factors モジュールは因子を config/registry で追加できる構造にする(最小セットで開始)。

### ✅ D6. 初期分布 + tail 確保(OPEN#3) — 【決定 2026-07-03: IPF骨格×尺度分布】
- **決定**: IPF(e-Stat 渋谷13113 の年齢×職業×居住/来街の骨格)× 心理尺度分布(GSE/NFC)を独立サンプリング → LLM 文章化。**Verbalized Sampling で mode collapse 対策、尺度は注入用/評価用を分離、tail を明示確保**。
- **含意**: 初期化パイプラインは IPF→尺度サンプリング(tail 保証)→LLM 文章化の3段。embedding 分散を監視。

### ✅ D7. k の操作化と対照設計(★red-team の核心) — 【決定 2026-07-03: 書き戻し主軸+対照3種】
- **決定**: k の**主軸 = 内省の「信念書き戻し自由度」**。対照3種を**全部**実装:
  - **sham reflection**(内省を実行するが書き戻しを捨てる=計算量同一・結合ゼロ)
  - **compute/token 一定の k 掃引**(深さだけ変え総トークン固定)
  - **null 系列**(k を上げず LLM 呼び出し量・温度だけ k と同じに増やす)
- **含意**: 3信号(R²低下・seed発散・EWS)が null/sham で出ないことを示して初めて k* を主張。engine は「内省の書き戻しを on/off/degrade できる」seam を持つ。実験計画の骨格([[lit/method__experiment-design-statistics]])。

### ✅ D8. storage(OPEN#5) — 【決定 2026-07-03: Redis+pgvector+NetworkX】
- **決定**: Redis(state/セッション)+ pgvector(記憶ベクトル+ログ)+ NetworkX(社会グラフ in-proc)。DB 機に小型 embedding 同居。
- **含意**: storage は抽象化 seam を挟む(スケール限界が見えたら Qdrant/Neo4j に差し替え)。数千体は NetworkX in-proc で十分。

### ✅ D9. ラベリング粒度 / viz / 報酬 / B段ゲート — 【決定 2026-07-03: 推奨デフォルトで確定(可逆スイッチ)】
- **ラベリング粒度(OPEN#4)**: スイッチ実装、**既定=制約版(naming-game 的・tractable)**、オープン版は config で切替。
- **viz 経路**: 後で選択(アダプタ差し替え)。ただし **sim 出力座標系 = JGD2011 平面直角 系IX を先に固定**。
- **報酬/ゲーミフィケーション**: **既定 off**、config トグルで実験変数として露出(アブレーション用)。
- **B段 go/no-go ゲート(R6)**: conformity 率・drift 発生を anti-collapse ON/OFF で測る。**合否基準は P1 パイロットのデータを見て設定**(基準値は実測後に確定)。
