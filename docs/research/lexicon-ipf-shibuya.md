## RQ3: 日本語感情辞書の選定(非LLM・決定論で発話 valence を採点)

### 結論(先出し)
- **中核に据えるべきは「東北大 日本語評価極性辞書(用言編+名詞編)」**。理由: (1)ライセンスが最も緩い(クレジット明記で商用利用・再配布可)、(2)語数最大(合計 約13,500)、(3)valence(ポジ/ネガ)を直接与える、(4)`oseti`・`asari` 等が同梱する事実上の標準。
- **実装は `oseti`(MIT)をそのまま使うか、`janome`(純Python)で自作スコアラを書くかの二択**。再現性・同梱容易性を最優先するなら後者(理由は下記「形態素解析」節)。
- **感情10分類まで欲しいなら `pymlask`(BSD-3-Clause)を併用**。否定・顔文字にある程度頑健で、同梱も自由。
- **WRIME は同梱対象から除外**推奨(CC BY-NC-ND: 非商用+改変再配布禁止。そもそも辞書ではなく学習/評価用コーパス)。
- **JIWC は感情7分類の補助**。語数が小さくライセンス要確認(下記)。

### 各リソース詳細

**1) 東北大 乾・岡崎研 日本語評価極性辞書**
- 用言編: 評価値表現辞書 約5,000件を改編し、人手で評価極性を付与。名詞編: 評価極性を持つ名詞(句) 約8,500件に人手付与(p=positive / n=negative / e=neutral)。
- ライセンス: 公式に「クレジットを明記していただければ、商用利用も可能です」と明記。用言編は小林(2005)、名詞編は東山(2008)の引用が条件。→ **リポジトリ同梱に最適**(クレジットファイルを添付すればよい)。
- 入手URL(公式): https://www.cl.ecei.tohoku.ac.jp/Open_Resources-Japanese_Sentiment_Polarity_Dictionary.html
  ファイル: `resources/sent_lex/wago.121808.pn`(用言編) / `resources/sent_lex/pn.csv.m3.120408.trim`(名詞編)
- 注意: 辞書自体は否定・文脈を扱わない。「〜ない」等はコード側で処理が必要。

**2) ML-Ask / pymlask**
- 手法: キーワード/パターンマッチ。約2,100語の辞書で10感情{喜・怒・哀・怖・恥・好・厭・昂・安・驚}を推定。加えて valence(活性/極性)や CVS(文脈的価)も算出。
- 実装: `pip install pymlask`。MeCab は任意(分かち書き済みトークンを渡すことも可)。否定・強調・顔文字の処理ロジックを内蔵 → **SNS風短文にバニラの極性辞書ルックアップより頑健**。
- ライセンス: BSD 3-Clause(原版 2007-2013 Ptaszynski 他 / Python版 (c)2017 Yukino Ikegami)。**同梱自由**。
- リポジトリ: https://github.com/ikegami-yukino/pymlask

**3) WRIME(梶原 他, NAACL 2021)**
- 主観(書き手本人)+客観(読み手3名+平均)の Plutchik 8感情強度(0-3)。Ver.2 で感情極性(-2〜+2, 5段階)追加。SNS(Plurk)投稿ベース。
- **辞書ではなくラベル付きコーパス**。決定論的な語→価のルックアップには使えない(使うなら分類器の学習/評価用=ML化してしまう)。
- ライセンス: **CC BY-NC-ND 4.0**(非商用・改変再配布禁止)→ 再配布したいリポジトリには不向き。
- リポジトリ: https://github.com/ids-cv/wrime / 解説: https://www.jstage.jst.go.jp/article/jnlp/28/3/28_907/_article/-char/ja/

**4) oseti / JIWC / その他**
- `oseti`(MIT): 東北大 用言編+名詞編を使い、文ごとに極性スコア(一致語の極性和÷一致語数)を算出。**否定を実装**(NEGATION スコープ内で符号反転、例「お金がないわけではない」→正に補正)。リポジトリ: https://github.com/ikegami-yukino/oseti
  - **依存**: `setup.py` の `install_requires` は `bunkai`(文境界分割)+ MeCab未導入時に `mecab` を追加 → **実質 MeCab 依存**。純Pythonではない。
- `JIWC-Dictionary`(NAIST社会計算研): 7感情(Sadness/Anxiety/Anger/Disgust/Trust/Surprise/Joy)。語数小(統合539〜2018年版1,691)。ライセンスはページに明記なし=**JIWC_Manual.pdf で要確認**。公式: https://sociocom.naist.jp/jiwc-dictionary/ / GitHub: https://github.com/sociocom/JIWC-Dictionary

### 口語・SNS風短文への頑健性(各辞書の弱点)
- **共通の弱点**: これらの辞書はニュース/レビュー/評価表現ベースで構築。ネットスラング(草・エモい・しんどい)、多義語(「ヤバい」= 正負両義)、皮肉、伸ばし(めっちゃぁぁ)は基本カバーしない。**絵文字/顔文字**は極性辞書(東北大)には無し。
- **否定「〜ない」**: 辞書単体では不可。`oseti`/`pymlask` はコードで否定スコープを扱う。自作する場合は「極性語の直後(同一文節/節内)に助動詞・形容詞『ない/ぬ/ん』が付いたら符号反転」の簡易ルールが最低限必要。
- **強調**: 「とても/超/めっちゃ」等の副詞で重み増幅を入れると精度向上(pymlask は一部内蔵)。
- **絵文字/顔文字**: pymlask/ML-Ask は顔文字を検出。絵文字(😊😡)は小さな絵文字→価の対応表を自作して上書きするのが現実的。

### 形態素解析の要否と統合方法(推奨)
- **形態素解析なしの近似は不可に近い**。日本語は分かち書きされず、用言編は活用語(基本形)を含むため、最低限「分かち書き+基本形化」が要る。表層 n-gram の部分一致だけだと否定・活用で誤爆する。
- **推奨A(最短): `oseti` をそのまま採用**。実装コスト最小・否定処理込み。ただし **MeCab 導入が前提**(Windows では `mecab` + 辞書のセットアップに手間)。
- **推奨B(再現性・同梱最優先): `janome` + 東北大辞書で自作スコアラ**。`janome` は**純Python・pip一発・IPADIC同梱**で MeCab 不要 → 環境再現性が高くリポジトリに閉じられる。処理: janome で分かち書き&基本形取得 → 用言編/名詞編ルックアップ → 否定反転+強調重み+絵文字上書き → 文の valence を [-1,1] 正規化。辞書2ファイルはクレジット付きで同梱。
- **感情カテゴリ(離散10感情)も心理状態更新に使うなら `pymlask`(BSD-3)を併用**。MeCab任意で導入も緩い。
- まとめ: **valence の中核=東北大辞書、実装=janome自作(推奨B)、感情分類の付加=pymlask**。これで LLM 不使用・決定論・再配布可・環境再現性を全て満たす。

### 年齢(5歳階級)×性別 → 実数は「未確認」(取得手順は確定)

### 2026-07-05 実数化 再試行ログ(バッチD)

目的: `data/shibuya_population.json` の `age_bands`(年齢5歳階級×性別)と `occupations`(職業大分類)の share を渋谷区の**実数**へ差し替える。

**試行手順(この日に実際に行ったこと)**
1. WebSearch「渋谷区 令和2年国勢調査 年齢5歳階級別 男女別人口 実数」/「渋谷区 国勢調査 職業大分類 就業者数 …」→ 公式・e-Stat の該当ページ群を特定。
2. WebFetch(小型モデルで本文→数値抽出)を以下に対して実行:
   - 渋谷区ポータル『年齢(5歳階級)別男女別人口』 https://www.city.shibuya.tokyo.jp/kusei/tokei_shibuya/nemrei_danjyo_betsu_jimko/
   - e-Stat『職業別構成(従業地・通学地その2)』 https://www.e-stat.go.jp/dbview?sid=0003002995
   - ecitizen 渋谷区 5歳階級別人口 https://ecitizen.jp/Population/City/13113

**失敗理由(正直な記録)**
- **e-Stat の DB 表示ページは JavaScript 描画**で、静的 HTML に数値セルが出力されない(「統計表表示」操作で初めて描画)→ WebFetch では数値ゼロ抽出。対象表: 職業大分類×市区町村 `statsDataId=0003176482`、年齢(5歳階級)×職業 `0003450693`、人口等基本集計(年齢×男女)。
- **渋谷区ポータルの当該ページはカテゴリ一覧のみ**で、本文に表もExcel直リンク文字列も現れず(WebFetch がリンク先URLを取得できない)。
- **ミラー系サイト**(ecitizen 等)は 2020 年の値が**将来推計人口**であって国調実数でなく、かつ**男女別内訳なし**。1985–2015 は5歳階級実数があるが年次が古い。
- **e-Stat API(getStatsData)は appId 必須**で本環境では発行・利用不可。

**結論**: 静的取得ツール(WebSearch/WebFetch)では age_bands/occupations の渋谷区実数は取得不可。**暫定値は据え置き**、`shibuya_population.json` の `meta.status` は変更せず、`meta.retrieval_attempts` に本試行を記録した(推定値を実数と偽装しない方針)。

**人手での代替取得手順(次に実数化する人向け)**
- 年齢×性別: 渋谷区『令和2年国勢調査』 https://www.city.shibuya.tokyo.jp/kusei/kuni_kikamtokei/kokusei_cyosa/01kokusei_r2.html →『年齢(5歳階級)別、男女別人口の推移(平成12年〜令和2年)』Excel をブラウザでDL→ 18–79 の 5 バンド(18-24/25-34/35-49/50-64/65-79)へ合算し、来街者の若年偏りをどう扱うか(住民=夜間基準なので昼間の来街者補正を別途かけるか)を決めて `age_bands.share` を置換。
- 職業: e-Stat `statsDataId=0003176482`(職業大分類×男女×市区町村)を **appId 付き getStatsData**(REST/JSON or CSV)でDL→ 渋谷区(コード13113)行の職業大分類を本ファイルの職業カテゴリ(会社員/エンジニア/…)へ写像して `occupations.share` を置換。
- 置換時: `meta.status` を "real"(または部分real)へ、`meta.sources` に取得日・表ID・URLを追記。差し替え後は `python scripts/build_personas.py 20 --no-llm` が通ることを確認(IPF が周辺分布の変更で壊れないこと)。
