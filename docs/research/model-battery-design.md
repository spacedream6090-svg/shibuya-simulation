## 0. 3行サマリ

1. **共通ハーネスが端から端まで動いた**。5層(A個体行動 / B摂動応答 / C会話統計 / D分散と裾 / E長期退行)+ プラセボ対照を、同一プロンプト・同一シード・同一温度で流し、来歴つき JSONL に保存してプロファイル表まで出す。ローカル Ollama の **qwen3:4b / qwen3:8b / プラセボの3本で縮小版(scale=0.2)を実走**した(結果は §5)。
2. **ライセンスは3件とも確定した**。社会生活基本調査(e-Stat)は政府標準利用規約2.0準拠・CC BY 4.0 互換で**数値をリポジトリに置いてよい**(出典+加工の明記が条件)→ 実数値を `data/battery/reference/` に収載。名大会話コーパス(NUCC)は **CC BY-NC-ND 4.0** で加工版の再配布も商用利用も不可 → **生データは同梱せず記述統計のみ**。CEJC は有償の利用許諾契約ゲート(アカデミック2.5万〜商業1000万円)→ **DP-U1 待ちでスコープ外**を明記。
3. **決定論は二層に分けて正直に宣言した**。ハーネス層(刺激・シード・呼び出し順)は完全決定論で鎖ハッシュが一致する。**モデル層は ollama に `options.seed` を渡しても再現しない**(実測: 同一シード・同一プロンプトの再送で応答 sha256 が一致したのは qwen3:4b **0/4**、qwen3:8b **1/4**、プラセボ 4/4)。宣言ではなく毎ランの `determinism_probe` で計測して manifest に残す。
4. **縮小版の実測で3つの実質的な発見**が出た。(a) **モデルを大きくすると分散が潰れる** — qwen3:8b は A/B/C で 4b を上回るのに D層(分散と裾)で下回り、6サンプルすべてが同一選択に収束した。文献の alignment-simulation tradeoff と整合。(b) **qwen3:4b は A層の JSON スキーマを守れない**(4件中3件で `activity` キーを丸ごと落とす)。(c) **両モデルとも「誘い」に 100% 乗り、あいづちが1回も出ない** — 迎合と過剰情報量の実測。

## 1. 構成

```
scripts/model_battery/
  __init__.py     HARNESS_VERSION
  metrics.py      指標(純関数・I/O なし・乱数なし)
  reference.py    参照統計の読み込みと来歴の強制
  stimuli.py      A〜E 5層の刺激生成(決定論)
  clients.py      モデルアダプタ(ollama / openai互換 / プラセボ)
  harness.py      実行 CLI
  report.py       集計 CLI
tests/test_model_battery.py     21 テスト
data/battery/reference/*.json   対照統計(来歴つき)
data/battery/raw/<model>/       生の応答 JSONL + manifest.json
data/battery/report.{json,md}   プロファイル表
```

### 1.1 実行

```bash
# 縮小版(各層 1/5)。GPU が空いていることを ollama ps で確認してから。
python scripts/model_battery/harness.py \
    --model ollama:qwen3:4b --model ollama:qwen3:8b --model placebo:template \
    --layers all --scale 0.2 --seed 20260803 --temperature 0.8 \
    --determinism-probe 4 --out data/battery/raw

python scripts/model_battery/report.py --raw data/battery/raw \
    --reference data/battery/reference --out data/battery [--d-ratio-floor 0.6]
```

`--dry-run` で LLM を呼ばず刺激件数と鎖ハッシュだけ出せる。モデル指定は
`<backend>:<model>[|k=v]` 形式(`ollama:qwen3:4b|host=...` / `openai:gpt-x|base_url=...|api_key_env=...` / `placebo:template`)。

### 1.2 `src/` との関係

- **OpenAI 互換**は `society.llm.openai_compat.OpenAICompatBackend` を**継承して再利用**した。API キーを `self` に載せず呼び出しごとに環境変数から読む規律をそのまま引き継ぐため(キーの値はコード・ログ・エラー文字列に一切出さない)。
- **Ollama は継承せず自前 HTTP** で叩いている。理由は `src/society/llm/ollama.py` の `generate()` が `options.seed` を送らないから。バッテリーの前提「全モデルに同一シード」が成立しないので、seed 付きの呼び出しを `clients.py` に置いた。送信内容は src と同型(`model/prompt/stream/think/options` + 必要なら `format:"json"`)で、`options.seed` を足しただけである。`think=False` 固定なのも src の実測注記(思考が `max_tokens` を食って空応答になる)に従っている。
- **本バッチは `src/` を編集していない**。将来 `OllamaBackend` に seed を足すなら、`clients.OllamaClient` は薄い継承に置き換えられる。

## 2. 5層の設計

共通の掟が3つある。

1. **全モデルに同一プロンプト**(正典 §4「モデル別のプロンプト調整は採用決定後」)。刺激文字列にモデル名・バックエンド名を入れない — テストで固定している。
2. **応答の長さを指定しない**。C層は発話長分布そのものが観測量なので「20〜60字で」と書くと測りたいものを潰す。
3. **オラクルの無い量は絶対評価しない**。参照統計が無ければその項目を落として平均し、`ref_missing` として明示する(`scripts/analyze_specialization.py` と同じ思想)。

| 層 | 刺激 | 主な下位指標 | 正規/縮小(scale=0.2) |
|---|---|---|---|
| **A 個体行動** | ペルソナ5種 × 平日/休日 の1日スケジュール生成(JSON、行動20分類) | `hourly_jsd_weekday`(時刻別活動分布の JSD)、`budget_jsd_week`、起床/就寝/通勤の分位差、`persona_sensitivity`、`daytype_sensitivity`、`coverage`、`conflict_free` | 10 / 4 呼 |
| **B 摂動応答** | 雨・遅延・誘い・閉店 × ペルソナ | `direction_ok`(方向妥当性)、`persona_spread`、摂動別 `change_rate`、`invite_change_rate`(迎合診断) | 20 / 8 呼 |
| **C 会話統計** | 2体ロールプレイ短対話 × 10話題 | 発話長分布(mean/median/p10/p90/CV)、`backchannel_rate`、`disagreement_rate`、`topic_persistence`、`vocab_entropy`、`vocab_richness`、`non_repetition` | 80 / 8 呼 |
| **D 分散と裾** | **完全に同一のプロンプト** × n サンプル(シードだけ変える)8択+理由 | `choice_entropy`、`choice_gini_norm`、`lexical_diversity`、`distinct_choices`、**分散比** | 30 / 6 呼 |
| **E 長期退行** | 連続自己対話 50 ターン + シミュ3日相当の繰り返し計画 | `novelty`、`late_novelty`、`vocab_retention`、`repetition_by_window`/`repetition_slope`、`plan_diversity`、`contradictions` | 53 / 13 呼 |

**A層の行動語彙は社会生活基本調査の「行動の種類(20分類)」に揃えた**(`metrics.ACTIVITY_CATEGORIES`)。モデルは「通勤」「移動(通勤・通学以外)」「昼食」などの表記ゆれを平気で返すので、`normalize_activity()` が別名表と部分一致で正典語へ寄せる(捨てて "その他" に落とすと被覆率が測れなくなるため)。

**E層の自己対話は履歴窓6ターン**にしている。50ターン全部を積むと文脈長がモデル間で違ってしまい、退行の測定に文脈長が交絡する。

**トークン予算は層ごとに固定**(A=900 / B=300 / C=220 / D=200 / E自己対話=220・E計画=400)。全モデルに同じ値を配る。`think=False` 固定(`src/society/llm/ollama.py` の実測注記「思考が `max_tokens` を食って空応答になる」に従う)。

### 2.1 C層・E層を JSON 封筒にした理由(実装中に実測で判明)

当初 C/E は自由文で応答させていた。ところが **qwen3:4b は `think=False` でも英語で推敲を延々と書き、発話に到達しない**。`max_tokens` を 220 → 800 → 1400 と上げても最後まで "Okay, I need to come up with the first sentence that 田村 (Tamura) would say..." が続き、日本語の発話が1つも出なかった(ラテン文字率 0.90、8発話すべて)。

これは**本番より厳しい別条件を測っていた**。本シミュ本体は会話も `format=json` の行動 JSON で受け取っている(`src/society/cognition/deliberate.py` の `parse_action`。JSON 遵守率は実測 fallback 0%)。そこで**封筒だけ本番に合わせ**、C/E の応答形式を `{"say": "<発話>"}` + `format=json` にした。**中身(発話の長さ・語彙・あいづち・不同意)は一切指定していない**ので、測りたいものは保たれる。封筒変更後は両モデルとも素直な日本語の発話を返した。

副産物として、封筒が壊れた応答を**発話として数えない**ようにした(生 JSON 文字列が語彙統計に混ざるのを防ぐ)。捨てた分は `schema_ok` に現れる。

なお**ラテン文字率のゲート**(`japanese_ratio` を C/E スコアの係数にする)はそのまま残してある。封筒があっても中身が英語になるモデルはありうるし、そのとき「発話長も語彙多様度も見かけ上よい」という誤読を確実に殺す必要があるため。

**指標に形態素解析器を使わない**。語彙系はすべて**文字 n-gram**で測る。MeCab/UniDic を足すと環境依存が増え、モデル比較の再現性が落ちるため。あいづち率・不同意率は正規表現による**粗い代理指標**であり、モデル間の相対比較にのみ使う(絶対値を「日本語会話のあいづち率」として主張しない)。

### 2.2 層スコアの作り方(隠さない)

各層のスコアは**下位指標の単純平均**であり、「人間らしさの総合点」ではない。レポートは必ず下位指標を全部併記する。参照統計が使えた層では `1 - JSD` と `timing_fit` が平均に加わる。

**重要な性質**: プラセボは JSON を壊さないので `schema_ok` / `coverage` / `conflict_free` は満点を取る。プラセボを沈めているのは **`persona_sensitivity` / `daytype_sensitivity` / `direction_ok` / `persona_spread` / `choice_entropy` / `lexical_diversity` / `plan_diversity`** ——「刺激の違いに応答が反応するか」を測る指標群である。これは意図した設計で、**同じ一日を全員に配る生成器は人間らしくない**という判断を明示的に指標へ埋め込んでいる。

### 2.3 D層(生命線)の分散比と判定線

正典 §4 の判定線は「全カテゴリでプラセボに有意差をつけ、かつ D 層の分散比が事前に決めた下限を上回るモデルが2本以上」。実装は次のとおり。

- **下限はハードコードしない**。`report.py --d-ratio-floor` は既定 `None` で、未指定なら分散比を出すだけで合否を出さない(`NOT_JUDGED`)。事後に閾値をいじれないようにするための制約で、テストで固定している。
- **人間参照が無い**ので、現状の分散比は **`relative_to_best_model`(その回の最良モデルを 1.0)** である。レポートは `variance_ratio_mode` を必ず出力する。絶対値(人間との比)を出すには、同一刺激に対する人間の選択分布を取る小規模調査が別途要る(`data/battery/reference/jp_conversation_corpus_descriptive.json` の `human_choice_entropy` に未取得として登録済み)。
- 文献側の相場は「LLM の応答変動性は人間の1/20〜1/300」(`docs/research/llm-human-fidelity.md`)。**その桁の絶対比較は今の材料では出せない**ので、出せないと書く。

### 2.4 プラセボ対照

`clients.PlaceboClient` はテンプレート応答のルールベース。藁人形にしないため、**JSON を壊さない・日本語として自然・会話は3種を巡回(単一文字列固定ではない)**。それでもペルソナ・日種別・摂動・シードのいずれにも反応しない。

レポートの `placebo_sanity` は「全層でプラセボが最下位(プラセボ最大 < 実モデル最小)」を検査する。合成テスト(`test_placebo_sinks_in_every_layer`)で、意図的に作った「人間らしい」合成モデルに対してプラセボが5層すべてで沈むことを固定している。

**FAIL の読み方(実測を経て改めた)**: 当初は「FAIL = その指標が人間らしさを測れていない」とだけ考えていたが、実測で A層が FAIL した原因は指標ではなく **qwen3:4b がスキーマを守れずスケジュールを1件しか出せなかったこと**だった。つまり FAIL は次の2通りを含む。(i) 指標が刺激差に反応していない(指標の欠陥)、(ii) **そのモデルが本当にテンプレート以下**(常に妥当な形式を返す定型 > 形式を壊すモデル)。どちらかは下位指標を見れば分かる(`schema_ok` が低ければ (ii))。両方とも役割決めに使える情報なので、判定は落とさず両方を報告する。

### 3.2 名大会話コーパス NUCC — ★生データは置かない

- 配布: 国立国語研究所 <https://mmsrv.ninjal.ac.jp/nucc/>(元は科研費 基盤研究(B)(2) 研究代表者 大曽美惠子。現在は NINJAL に移管)。CEJC とは**別コーパス**。
- ライセンス: **CC BY-NC-ND 4.0**(表示-非営利-**改変禁止**)。※ CC BY-NC-**SA** ではない。リンク先も `by-nc-nd/4.0` で確認済み。
- 帰結:
  - 未改変の逐語再配布は理屈上は可(非営利+表示+改変なし)。**しかし ND により整形・分かち書き・タグ付与・部分抽出した版の再配布は不可**、NC により商用利用も不可。本リポジトリは公開ミラーを持つので、**同梱しない**運用が安全。
  - **派生的な記述統計の公表は可**(事実データは著作権の保護対象外)。
- **判定: `redistribution: "derived_stats_only"`。生データは保存せず、公表済みの記述統計のみを出典つきで収載した。**

収載した記述統計(柏野・西川・小磯 2017 / 山崎・大村 2019):129会話・約100時間・平均47分・話者198名(女性161/男性37)・延べ語数1,129,271・異なり語数18,186。

**★ C層の絶対比較は今回できない**。`mean_utterance_chars`(平均発話長)・`backchannel_rate`(あいづち率)・`disagreement_rate`(不同意率)の**公表値が存在しない**ため、参照ファイルでは `values: null` / `status: "未確認"` にした。したがって C層は**モデル間の相対比較のみ**になる。埋めるには NUCC を規約どおり個別取得して自前集計し、算出手順ごと参照ファイルに記録する必要がある。なお NUCC 自身が「あいづちの認定が難しい」ことをデータの問題点として自認している(<https://mmsrv.ninjal.ac.jp/nucc/nucc_abst.html>)ので、算出しても留保つきになる。

利用時の引用義務(公式指定):藤村逸子・大曽美恵子・大島ディヴィッド義和 2011『言語研究の技法』pp.43-72 または Fujimura, Chiba, Ohso 2012 のいずれか。

## 4. 決定論の宣言(二層に分ける)

- **ハーネス層 = 完全決定論**。刺激(プロンプト)・シード・温度・呼び出し順は `seed` と `scale` だけの純関数で、モデルにも時刻にも環境にも依存しない。`manifest.json` の `digests.prompt_chain` / `record_chain`(`observer.state_hash` と同じ正準シリアライズ+sha256 の鎖)で検査でき、テストで2回走らせて一致を固定している。時刻・所要秒は決定論ダイジェストに含めない。
- **モデル層 = 保証しない**。ollama には `options.seed` を渡しているが、再現するかはサーバ/ドライバ/バッチ状況に依存する。ハーネスは毎ラン `determinism_probe`(先頭 K 呼を同一シード・同一プロンプトで再送し応答 sha256 の一致率を測る)を実行し、**実測値を manifest に残す**。「再現した/しなかった」は宣言でなく計測で答える。
- **構造上の帰結**: C層とE層のプロンプトは前ターンの応答に依存するため、モデルが揺れると `prompt_chain` も揺れる。これはバグではない。A/B/D層のプロンプトはシードにも応答にも依存しないので常に一致する(テストで固定)。

### 5.4 実測から読み取れること

**(1) 判定線は NO_GO(下限 0.6)。ただし縮小版の n が足りていないことを込みで読む。**
`--d-ratio-floor 0.6` で通ったモデルは0本(2本以上が条件)。`ollama/qwen3:4b` は D 分散比 1.000 だが A層でプラセボを下回るため条件「全層でプラセボ超え」を満たさず、`qwen3:8b` は分散比 0.494 で下限未満。**ただし縮小版の D層は n=6(正規は30)**で、8択の選択エントロピー推定としては粗すぎる。判定線を本気で当てるには `--scale 1.0` が要る。今回の NO_GO は「この2本では足りない」であって「本番を回す価値がない」ではない。

**(2) ★モデルを大きくすると分散が潰れる(D層 = 生命線)。**
`qwen3:8b` は A(0.828)・B(0.750)・C(0.753)で 4b を上回るのに、**D では 0.244 と 4b(0.495)を下回った**。6サンプルすべてが「散歩する」に収束(`distinct_choices` 1、`choice_entropy` 0.000)。4b は2択に散った(0.306)。これは `docs/research/llm-human-fidelity.md` の **alignment-simulation tradeoff**(instruction-tuning が多元的な問いで性能を落とす。SimBench のエントロピー相関 r=−0.942)と正確に同じ向きで、**「一番賢いモデルに心を全部任せる」構成は分散崩壊を招く**という正典 §5 の混成 fleet 判断を実測で裏づける。

**(3) qwen3:4b は A層の JSON スキーマを守れない。**
`schema_ok` 0.250 / `activity_labeled` 0.289 — 4件中3件で `{"start","end"}` だけを返し **`activity` キーを丸ごと落とした**。正典 §7 の day_plan v1 は1ブロックあたり8フィールド(列挙型を含む)を要求するので、**4b を朝の計画層に置くのは危険**。逆に B層(4フィールド)・C層(1フィールド)・D層(2フィールド)は 4b でも遵守率 1.000 で、**フィールド数がスキーマ遵守の効く軸**らしいことが見えた。

**(4) 迎合(sycophancy)が両モデルで飽和。**
`invite_change_rate` が 4b・8b とも **1.000** — 「今夜ごはんでもどう?」に全ペルソナが100%乗った。夜勤明けだろうと子育て中だろうと断らない。`persona_spread` も 0.250 と低い。正典 §1 の「LLM の会話は過剰に流暢で協力的」がそのまま出ている。**断る自由をどう実装するか**は day_plan の priority/flex(§7)とは別に手当てが要る。

**(5) あいづちがゼロ。**
`backchannel_rate` は3本とも 0.000(8発話中0件)。発話長は 4b が平均56.4字、8b が44.3字で、**どの発話も情報を持った完全文**である。人間の日常会話は「うん」「そうだね」のような内容語をほぼ持たない発話が相当量を占める(NUCC が文字化規則で相づちを独立表記するほど)。`disagreement_rate` は 8b が 0.375 と 4b の 0.125 より高く、**不同意は 8b の方が出せている**。

**(6) A層は 8b が参照統計にも近い。**
時刻別活動分布の JSD は 8b 0.202 < プラセボ 0.344 ≒ 4b 0.358。時間配分の JSD も 8b 0.076 が最小。ペルソナ感度 0.615・曜日感度 0.448 と、刺激差にもきちんと反応している。一方 `timing_fit` はプラセボ(0.883)が最良 — テンプレの起床06:38/就寝23:00 が全国平均のど真ん中だからで、**「平均を当てる」ことと「個人差を出す」ことは別**という正典 §1 の指摘そのままである。通勤開始は 8b が中央値で参照より80分早い。

**(7) B層の方向妥当性チェックは粗い。**
`qwen3:4b` は「店が臨時休業 → `睡眠`」「電車が30分遅延 → `睡眠`」のように**意味的に不合理な代替**を返すが、`change=true` なので `closure` の判定を通ってしまう(`direction_ok` 0.833)。`delay` だけは `delta_minutes` を要求するので 0.50 に落ちた。**列挙型の妥当性まで見る判定は入っていない**ことを限界として記録する。8b は 1.000。

**(8) 運用: モデルの切れ目で VRAM を空けないと十数倍遅い。**
最初の実行では `qwen3:4b` が keep_alive で常駐したまま `qwen3:8b` を呼んでしまい、`ollama ps` が `48%/52% CPU/GPU` を表示、A層1呼が **86.5秒**かかった。`OllamaClient.unload()`(`keep_alive: 0`)をモデルの切れ目に入れたら同じ呼が **25.9秒**(3.3倍)になった。ハーネスは既定で unload する(`--no-unload` で無効化可)。

**(9) 決定論の実測。**
`options.seed` を固定して同一プロンプトを再送したときの応答一致率は **qwen3:4b 0/4、qwen3:8b 1/4、プラセボ 4/4**。**ollama の seed は再現性を保証しない**。したがって本バッテリーが約束できるのは §4 のとおり「ハーネス層の決定論=刺激とパイプラインのみ」である。モデル比較を統計的に語るなら、シードではなく**サンプル数**で担保するしかない(= D層 n=30 が効く理由)。

## 6. 限界と持ち越し

1. **C層の絶対評価ができない**(§3.2)。NUCC の平均発話長・あいづち率の公表値が無い。規約どおり個別取得して自前集計するのが次の一手。CEJC が使えるなら 200時間・240万語の方が母集団としてはるかに良い(DP-U1)。
2. **D層の分散比が相対値にとどまる**。人間側の参照(同一刺激への選択分布)が無いため。小規模でも人間データを取れば絶対比が出る。判定線 `--d-ratio-floor` はそれまで較正対象として引数のまま置く。
3. **A層の参照は全国値・週全体**が主で、渋谷(東京都/人口集中地区)の値は代替系列として登録しただけ。本番の較正では東京都値に切り替える判断がありうる(参照ファイルの `*_alt` 系列)。また `week_average_minutes` は週全体平均なので平日/休日を分けた比較ができない(時刻別行動者率は平日のみ収載)。
4. **層スコアの重みは単純平均**で、下位指標の重要度を反映していない。役割決めには下位指標の表を直接読むこと。重み付けを入れるなら根拠(何が fleet の役割に効くか)を先に決める必要がある。
5. **`vocab_retention` は上限1.0でクリップ**するため、常に同じ語彙量を吐く定型生成器が満点を取る。実測でも**プラセボが 1.000 で最良**になった(4b 0.906 / 8b 0.956)。E層はこの1指標だけでは判定できず、`novelty` / `plan_diversity` と併読する前提になっている。
6. **候補モデルが2本+プラセボ**にとどまる(手元GPU=RTX 5070 12GB の制約)。正典 §4 は「多言語系と日本語特化系の両方を5〜6本」を求めており、本選前に 24GB 級で 7〜14B クラスを足す必要がある。ハーネスは `--model` を並べるだけで拡張できる。
7. **ブラウザ/人手による応答の質的レビューはしていない**。機械指標のみ。応答本文は `data/battery/raw/` に全文残してあるので、人手レビューは後から差せる。
8. **B層の方向妥当性が列挙型の意味まで見ていない**(§5.4-(7))。「臨時休業 → 睡眠」が通ってしまう。摂動ごとに「妥当な代替カテゴリ集合」を定義すれば締められるが、集合の決め方自体が主観になるので、入れるなら根拠を先に決める。
9. **縮小版の n が小さい**。特に D層 n=6(正規30)は8択のエントロピー推定として粗く、判定線の結論はこの n では確定しない。ハーネス自体は `--scale 1.0` で 193 呼/モデルまでそのまま伸びる(qwen3:8b の実測 10.2s/呼 から、正規版は1モデル約33分の見積り)。
10. **C層の話題数が2**(正規10)。話題持続・語彙エントロピーは話題数に敏感なので、C層の数値は暫定。
11. **`--scale` は層ごとの縮尺を1つのノブで動かす**ため、「D だけ正規・他は縮小」ができない。生命線である D を厚くしたいなら `--layers D --scale 1.0` を別途1本回すのが現実的。

## 7. DP-U2(心モデルの最終ショートリスト)への示唆

正典 §9 の未決事項「心モデル候補の最終ショートリスト」に対して、今回の材料から言えることだけを書く。**手元は RTX 5070 12GB / 候補2本 + プラセボ / 縮小版1本**なので、これは結論ではなく**次の測定の設計指針**である。

1. **単一モデルで fleet を組むな、という判断が実測で支持された。** `qwen3:8b` は構造(A)・妥当性(B)・会話(C)で最良なのに、D層(分散と裾)で **6サンプル全部が同じ選択**に潰れた。正典 §5 の「異種モデルの混成は性能ではなく多様性の実装として正当化される」は、**同一シリーズの 4b と 8b の間にすら分散の差が出る**という形で裏づけられた。ショートリストは「一番強い1本」ではなく「**D層のプロファイルが互いに違う数本**」で組むべきである。
2. **役割の初期割り当て案(この2本に限った暫定)**:
   - **計画(day_plan v1 の生成)= 8B 級以上**。4b は `activity` キーを落とすので、8フィールドの列挙型スキーマには載せられない。フィールド数がスキーマ遵守の効く軸らしいので、候補追加時は**まず A層(9フィールド)を先に流して足切り**するのが安い。
   - **会話 = 8B 級**(C 0.753、不同意率 0.375)。ただし迎合と「あいづちゼロ」は 8b でも直らないので、**モデル選定では解けない**(プロンプト/機構側の課題)。
   - **裾の供給 = 小型を混ぜる**。4b は品質では劣るが D層では 8b を上回った。「高解像度層に大型・基底層に小型」(正典 §5)は計算予算の話として提案されていたが、**分散の観点からも同じ配置が正当化される**。
3. **次に測るべきこと(優先順)**:
   1. **D層だけ正規サイズ(n=30)で回す**。`--layers D --scale 1.0` なら1モデル30呼で数分。判定線 `--d-ratio-floor` を較正できるのはここだけ。
   2. **候補を増やす**。正典 §4 は「多言語系と日本語特化系を5〜6本」。24GB 級が使えるなら 7〜14B クラス(Qwen3 系の上位、日本語特化系)を足す。ハーネスは `--model` を並べるだけ。**ライセンス**は `docs/research/llm-model-selection.md` の指摘どおり日本語特化系(Sarashina/PLaMo)が非商用で壁になる点に注意。
   3. **人間側の D層参照を取る**。同一刺激(「渋谷で1時間空いた」8択)を人間に配れば、分散比が `relative_to_best_model` から絶対比になる。数十人規模で足りる。これが無い限り「人間の1/20〜1/300」という文献値との突き合わせはできない。
   4. **A層のスキーマ足切りを day_plan v1 の実スキーマで**。今の A層は行動20分類だけの簡易版。本番スキーマ(priority/flex/同伴者/目的を含む)で流せば、**修復発生回数のモデル別集計**(正典 §7 が「テストバッテリーの追加指標になる」と書いているもの)がそのまま取れる。
4. **測定の前提として直すべき運用**: モデルの切れ目で必ず VRAM を空ける(§5.4-(8))。空けないと 8B 級で十数倍遅くなり、候補を増やすほど破綻する。本選の 7GPU 環境でも「1GPU に複数モデルを常駐させない」形で同じ問題が出る。
