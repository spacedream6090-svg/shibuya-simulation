# 実在庫システム設計の実証値(INVリサーチ・2026-08-20)

> 2層在庫(店頭+バックヤード)+店員補充の実装のための実証値。日本の一次資料優先。

## 1. 設計に直結する数値

### 店頭/バックヤード比率(業態差)
- 日本スーパー: **BY=延べ面積の30.0%**(全国スーパーマーケット協会2023・n=200・規模別28-32%)。
- 日本コンビニ: BY狭隘=「小分けした数量を納品」(JFA物流自主行動計画2023)。設計目安=面積の10-20%。
- 欧州実測(Pires 2017): コンビニ型 売場1,100/BY660m²・SM 2,100/1,400・ハイパー 7,500/5,400。

### 在庫日数・消尽レート(較正アンカー3系統が一致)
- 蘭SM実測(van Donselaar 2010・19,417SKU): 中央値**1.2個/SKU/日**・店在庫4.2-9.3日。
- 日本SM導出: 客数1,854×9.9点≈18,400個/日÷1-2万SKU≈**1-2個/SKU/日** ✓
- 日本CVS導出: 日販70万円÷客単価743.8円×~2点≈1,900個/日÷3,000SKU≈**0.6個/SKU/日** ✓
- 店頭棚在庫日数(寺嶋2013・日本SM実測): 上位SKU **4.7-13.3日**・「棚在庫は最大陳列量で決まる
  (需要からでなくフェイス数×奥行)」。毎日発注なら棚だけで足りる(=日本SMは棚が厚い)。

### 補充作業(秒単位・欧州2チェーン実測 Curșeu 2009)
```
TST(秒/SKU) = 10.2 + 19.1×ケース数 + 1.33×個数   (平均57.3秒/SKU)
内訳: 陳列48%・開梱20%・廃材13%・歩行8%・棚準備6%・探索4%
```
- 店舗内物流=**総労働時間の40%**(Reiner 2013・202店)・SC荷役の75%は店内・品出し40-60ケース/時。

### 納品・発注(日本)
- CVS: チルド**1日2-3便**(セブン5-7時/11-13時/17-19時)・発注→納品**24時間未満**。
- SM: 加工食品=**週3回(隔日)が最多**・リード1-2日。蘭SMは毎日〜週3・L=1営業日・充足率99.15%。

### 欠品の実証(既収集Gruen 2002に追加)
- 曜日: 日曜10.9%最高・土曜7.3%最低。時間帯: 「最低=早い午後・**最高=20時以降**・夕方に上昇が全研究で一貫」(数値表は非公開)。
- 持続: 8時間以内補充~20%・3日超~20%。
- **「店内に在るが棚に無い」25%**(Gruen)・棚欠落16%超(Ton & Raman 2010)・BY内で商品を見つけられない率10%(Waller 2008)・在庫記録不正確65%(DeHoratius & Raman 2008)。
- 日本の欠品率実測は**存在しない**(自己申告0.5-1.0%=寺嶋2008アンケートのみ)。
- 品切れ時反応(Gruen世界7.1万人): 他店31/別ブランド26/同ブランド別品19/延期15/非購入9%。
  日本ABM先行(Matsumura 2016・日本コンビニPOS較正)はswitcher:loyal=52:48を採用。

## 2. 2層在庫モデルの推奨形
- 状態: shelf[p,c]・back[p,c]・S_cap=フェイス数×奥行・**需要は棚からのみ充足**(BYに在っても補充までは品切れ=Gruen25%を再現する唯一の構造)。
- 発注: **(R, s, nQ)**(グロサリー自動発注の実態形)。s=最低陳列在庫+L+R期間需要・SS=z·σ·√(L+R)。
- 棚容量則: **pack-and-a-half**(S_cap≥1.5×ケース入数QならBYほぼ不要=CVS設計・SMは不成立でBY必然)。
- **業態差はS_cap/Q比とRだけで表現できる**(最少パラメータ): CVS=S_cap/Q≥1.5+日3便/SM=S_cap/Q<1.5+隔日。
- 閉形式(Hübner & Schaal 2017): BY在庫 y=max(⌈D/f−x⌉,0)・BY補充回数⌈y/x⌉・間接補充コストは直接の2倍以上。

## 3. エンジン計算量(実測ベンチ済み・Python 3.12)
- **SoA numpy int32 2枚(50k POI×50cat)=8-10MB・全2.5Mセルeager走査1.78ms/step**。
  ネストdictは103MB・4.07ms=**25倍のメモリ**(第141のpickled→in-RAM 13.6倍と同じ失敗モード)。
- **在庫は必ず整数**(floatは非結合律で順序依存)。
- **遅延評価は禁物**: max(0,x−d)は合成不能(clampで品切れタイミングが変わる)=resume減衰二重適用
  (第98/第142)と同じバグクラス。eagerで十分速い。
- heapqは疎なスケジュール事象(便・補充ラウンド)のみ(0.6µs/event)。
- カテゴリはCSR/raggedで3-8/店に落とせば2.5M→数十万セル。

## 4. 先行と新規性
- 日本コンビニABM(Matsumura 2016・POS較正・欠品→来店間隔延長の店舗ロイヤルティ毀損機構)が最近接。
- **都市規模ABMで店舗ごとの在庫を持った先行は無い**(Covasim/JUNE/MATSim/AgentSociety/CitySim全て
  店=接触場所のみ・MATSim capacityは実質∞)→ 貢献として主張可能。
- 最大のper-POI動的状態先行=Chang et al. Nature 2021(55万POI×máx収容キャップ・9,800万人)。
