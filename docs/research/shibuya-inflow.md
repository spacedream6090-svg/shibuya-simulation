# 渋谷の昼間流入・流出の統計と「通勤流入者」ペルソナ設計案(R2、2026-07-06)

> ユーザー指摘: 「渋谷へ職場・学校に来る大部分の人は渋谷駅周辺に住んでいない」。
> → 国勢調査 従業地・通学地集計の流入人口、昼間人口 551,344 の内訳、渋谷駅の乗降人員、時間帯別プロファイルを調査。
> **本バッチは調査・設計のみ・実装なし**。出典 URL 必須・数値未取得は「未確認」と明記。
> 既存: [lexicon-ipf-shibuya.md](./lexicon-ipf-shibuya.md) の RQ4(昼間 551,344/夜間 243,883/来街者比率 0.56)を土台に精緻化。

## 0. 結論(先出し)
ユーザー指摘は統計的に正しい。**渋谷区の昼間人口の約 3/4 は区外からの通勤・通学流入**であり、
その大半は渋谷駅周辺に住んでいない(近隣区・沿線からの通勤)。現行シミュの `visitor`(来街者=家は街の外)
概念は既にこの構造を捉えているが、**「通勤流入者」の到着時刻分布・出入口配分・居住地=沿線という属性**を
明示的に設計に落とすと、朝夕のラッシュ・日中の勤務人口・夜の帰宅波がリアルになる。

## 3. 時間帯別の流入プロファイル(通勤ラッシュ)
- **区別・駅別の時間帯別断面(大都市交通センサス由来)の実数は本調査で未取得**(センサス集計は要 DL/OCR)。
- 東京圏の一般則(接地に使える定性): 朝ピーク **7:30-9:00 着**(最混雑 8 時台)、夕ピーク **17:30-19:30 発**。

## 4. シミュ反映の設計案 —「通勤流入者」ペルソナ骨格

### 4.1 現行との対応
- 既に `Agent.visitor`(家は街の外・夜は範囲外へ帰る・帰路の電車で内省)と、ペルソナの**来街者比率 0.56**
  (`data/shibuya_population.json`)が流入構造を捉えている。`persona.py` は visitor の home を駅ノードに置き、
  就寝→駅→exit_area→睡眠+αで朝に return_at で帰還、という往復を回している。
- **不足**: (a) 到着/帰宅の**時刻分布**(現状は sleep_steps+乱数で緩く分散)、(b) **出入口の配分**
  (現状は station に重み3 だが徒歩/バス縁との比率は未設計)、(c) **居住=沿線という属性**(内省・会話の話題接地)。

### 4.2 追加提案(seam・既定は現行維持)
**「通勤流入者(commuter)」= visitor の下位型**として、以下の分布を conf 化(ペルソナ生成 build_personas 側で付与):

| 設計項目 | 推奨値/分布 | 根拠 |
|---|---|---|
| 流入者比率(昼間人口ベース) | 昼間就業・通学者の **~74%** を区外流入に | 表B(402,000/551,344 ≈ 0.73) |
| 流入者のうち鉄道利用 | 大半(渋谷は鉄道ターミナル)。徒歩/バス縁は少数 | 4社 ~260万の輸送規模 |
| 朝の到着時刻(職場 start の前) | 二峰: 通学 7:30-8:30 / 会社員 8:00-9:30(最頻 8 時台) | §3 東京圏一般則 |
| 夕の流出時刻(勤務 end の後) | 17:30-19:30 中心 + 夜遊び層の遅い裾(22-24時) | §3 + 既存 nightlife |
| 出入口の配分(到着/帰宅) | 駅ゲートウェイ **~85-90%** / 徒歩・バス縁 **~10-15%** | 鉄道ターミナル。実比率は未確認→暫定 |
| 居住地=沿線タグ(話題接地用) | {東横=横浜/中目黒, 田園都市=二子玉川/川崎, 井の頭=下北沢/吉祥寺, 山手=新宿/池袋, 世田谷/杉並/目黒} | 表C。persona 文に薄く注入(構成概念でないので frame 分離に抵触しない) |

### 4.3 到着時刻分布の具体案(実装は次バッチ)
- visitor の朝の `return_at`(帰還=渋谷への到着)を、現行の「睡眠長+乱数」から**職場 work_start_min から逆算した
  二峰正規分布**に置換する seam。例: 会社員は N(work_start−40min, 20min)、学生は N(work_start−30min, 15min)
  で駅ゲートウェイに enter_area。start が無い型(フリー・観光)は日中一様。
- 出入口: `city.station_node`(鉄道)を第一候補に、確率 p_walk(≈0.12)で縁ゲートウェイ(徒歩/バス)に振る。
  → 現行 `exit_points`(station に重み3)の**到着側**への対称化。
- **R1 非干渉**: これらは世界側 affordance(到着時刻・出入口)の変更で、k・発火入力・LLM 呼数に影響しない。
  内省の k 処置は「帰路の電車で全員に保証」の現行機構を維持(visitor は既に reflect_step を帰宅時に立てる)。

### 4.4 観測での活かし方
- 流入者/居住者のタグ(既存 traits.json の `visitor`)で Y(世界改変量)の層別が可能
  ("keystone は流入者か地元民か")。到着時刻分布は朝の混雑(congestion→grievance)を現実化し、
  発火ゲージの朝ピークを生む。

## 5. 確定できなかった数値(正直な記録)
1. **区別の流入元ランキング実数**(世田谷 27,817 以外)— e-Stat `statsDataId=0003454517` は JS 描画で本調査未取得。取得先は特定済み。
2. **74%/402,000 人の年次**— 2次資料(マンション経営.東京)で 2000年代前半の記述。2020 の一次値は e-Stat 従業地・通学地集計で要確認(規模オーダーは信頼できる)。
3. **昼夜間人口比率の正確値** — 常住基準が 243,883/230,609 で食い違い(226〜240%)。
4. **時間帯別断面(駅別/区別の実数)** — 大都市交通センサスの DL/OCR が必要。§3 は東京圏の定性則。
5. **出入口配分(駅 vs 徒歩/バス)の実比率** — §4.2 の 85-90% は暫定。渋谷区交通戦略 PDF の断面値で要確認。
6. 私鉄乗降人員は**直通通過客を含む**ため渋谷実乗降はこれ未満(重複補正は未実施)。
