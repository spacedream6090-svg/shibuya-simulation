## 0. 3 行サマリ

1. このサーベイは **individual → scenario → society** の 3 層で分野を整理し、各層に「アーキテクチャ/構築法/対象分類/**評価法**」の 4 点セットを与える。最大の価値は**分類体系そのもの**と、各パラダイムの**典型的失敗様式(failure mode)を明記した比較表 3 枚**(Table 2/4/6)である。
2. サーベイが繰り返し「未解決」と名指しするのは **①評価(特に macro とロングホライズン)②再現性 ③現実整合(alignment)④解釈可能性**の 4 点。我々はこのうち **②再現性と、観測の非侵襲性については分野水準を明確に超えている**(§4)。逆に **①評価の作法(micro/macro/system の 3 段報告・stylized facts との照合・主張の境界宣言)は、我々が今すぐ整えるべき最大の穴**である。
3. 本プロジェクトの研究課題(k*・組織形成・自然造語)に**直接効く未導入機構**は、(i) **アウトライアの扱いを設計として明文化すること**(サーベイ標準は「核心ノードを厚くモデル化」だが、我々は**あえて採らない**=それ自体が主張になる)、(ii) **組織構造の分類軸(mode × structure × role)を観測指標に落とすこと**、(iii) **MAS 失敗様式の既製タクソノミを組織形成の失敗観察に流用すること**の 3 つ。

## 2. 分類体系の要約(論文の構造に忠実に)

### 2.1 全体構造

「**個体モデリングの粒度**」と「**多様性・規模**」を直交軸に取り、左から右へ規模が増し、右から左へ粒度が細かくなる連続体として 3 型を置く(Fig. 1)。3 型は**累進的**で、individual が scenario と society の基礎をなし、society は理論上「無数のサブシナリオからなる混沌とした世界」を包含しうる、とする。

| 型 | 定義 | 典型規模 | 目的 |
|---|---|---|---|
| **Individual Simulation**(§3) | 特定個人 or 人口統計群の模倣。**多エージェント相互作用を含まない** | 1 | 個人の特徴(性格・意見)の再現 |
| **Scenario Simulation**(§4) | 特定文脈で目標・タスクに駆動された小集団の協働 | 数〜数十 | **集合知**でタスクを解く |
| **Society Simulation**(§5) | エージェント社会内の相互作用から**社会動態と創発**を観る | 数十〜100万 | 社会科学理論の検証・現象の予測 |

背景章(§2)では、伝統的 ABM/MAS の限界(意思決定の貧しさ・完全合理性の仮定・多様性の表現不足・手作りドメイン外への汎化不能・固定通信プロトコル)を挙げ、LLM は**エージェントの推論エンジン**としてこれを拡張する、と位置づける。

### 2.2 Individual Simulation(§3)

- **アーキテクチャ 4 部品**: **Profile**(構築=手動 vs LLM 生成 / 形式=記述 vs 対話)・**Memory**(型=短期/長期、操作=writing / retrieval / **reflection**=断片的経験の一貫した知識への統合)・**Planning**(**empathetic planning**=他者の感情・意図を推論して適応 / **subjective planning**=自身の思考・アイデンティティに沿って行動)・**Action**(状況=単純対話 vs **crafted situation**(規則付き環境・サンドボックス) / 領域=closed(選択肢限定) vs open(自由生成))。
- **構築法**: **nonparametric prompting**(system prompt "You are a…"・few-shot)vs **parametric training**(pre-training / fine-tuning(LoRA で複数キャラを 1 モデルに)/ RL(報酬関数の改変でペルソナ選好を制御))。
- **対象**: **Demographics**(属性を共有する群。埋め込み空間のクラスタ表現と解釈)vs **Characters**(実在=伝記等で部分検証可能 / 仮想=物語整合性が主)。
- **評価**: **static**(subjective=人/LLM の主観採点、インタビュー法・BFI/MBTI 等の心理尺度 / objective=正解率・F1・perplexity・ROUGE-L・BLEU)と **interactive**(設計環境+実時間フィードバック+多段評価。ゲーム性能・タスク完遂・多ターン一貫性)。
- **比較表(Table 2)の失敗様式**: parameter-embedded=過学習・破滅的忘却・幻覚ペルソナ / context-compressed=情報損失・**ドリフト** / conditional-control=**ステレオタイプ増幅**・キャラ崩壊・ラベル衝突。
- **反省(§3.5)**: 客観評価は粗粒度・静的多肢選択に偏り、開領域対話では無力。主観評価はコスト高・**再現不能**。そして **lifelong evaluation(長期の役割一貫性評価)がほぼ存在しない**。

### 2.3 Scenario Simulation(§4)

- **系の 4 要素**: **Environment**(configuration / state(観測+フィードバック)/ history(素の追記・切詰・要約・記憶化))・**Role**(communicator / worker / **director**(planner・coordinator・integrator))・**Organization**(mode=static / dynamic、structure=layered / centralized / decentralized)・**Communication**(format=非構造自然言語 UNL vs 構造化言語 SL、style=協調 vs 競争)。
- **シナリオ**: dialog-driven(社会的相互作用・QA・ゲーム)/ task-driven(科学・ソフトウェア開発・その他産業)。
- **評価**: **task / sub-task / system** の 3 スコープ × **automatic / LLM / human** の 3 手段。
- **比較表(Table 4)の失敗様式**: static pipeline=**誤り伝播**・スキーマ硬直 / **unstructured debate=social sycophancy・context dilution** / dynamic organization=計画ボトルネック / **environment-centric=状態デシンク・無限ループ**。
- **反省(§4.4)**: 対話系の評価は人/LLM 判定に依存。LLM 判定は「目標達成」次元では人間とよく一致する(Sotopia)が、**他の次元では大きな乖離が残る**。

### 2.4 Society Simulation(§5)

- **社会構築 4 要素**:
  - **Composition**: 個体構成の決め方(仮想合成 / 既存データセット / **実世界分布の複製**)。**精度と規模のトレードオフ**(大規模では属性を削る・共有記憶へ圧縮・通信を簡略化)。そして **outlier の特別モデリング**(意見リーダー・セレブは網の中心を占め影響を増幅するので、資源制約下では**核心的生産者だけ厚く**モデル化し、多数は簡略化する。介入策も鍵ノードに集中する)。
  - **Network**: offline(対面接触・疾病伝播。乱数/事前定義、外部アルゴリズム推定、大規模では**無視して独立扱い**も)/ online(実 SNS からのクロール、少量の実関係+大量の合成、homophily 仮定での接続)。
  - **Social Influence**: **受け手側**(同じ情報でも profile により効果が違う。認知バイアス・規範への内省を足す例)/ **送り手側**(誰が言うかで効果が違う=Pareto 分布・**Matthew 効果**。群サイズが大きいほど単一影響者の効果は下がり、集合的影響が**同調(herd)**を生む)。
  - **Outcomes**: **マクロ統計**(投票結果・世論水準。相互作用を無視して単純合算する系と、多ラウンド相互作用後に統計する系)/ **社会現象と社会規範の形成**(推薦のバブル・エコーチェンバ・Matthew 効果・自発的協調、コミュニティ規則が規範を作るか、規範創発アーキテクチャ、規制下での言語進化)。
- **評価**: **micro**(個体挙動の人間らしさ。Turing テスト的主観、実データがあれば感情・態度・行動一貫性の自動指標)/ **macro**(伝播規模・意見分布・トレンドが現実と整合するか。相関係数・当てはめパラメータ。経済系では「**代表的なマクロ経済法則を再現できるか**」)/ **system**(実行時間・資源・スケーラビリティ・**トークン消費と費用**)。
- **比較表(Table 6)**: ルールベース ABM=整合弱/規模強/解釈強・**行動的リアリズム**が失敗点。LLM+ABM ハイブリッド=**境界アーティファクト・統合の非一貫性**。純 LLM の naive prompting=**ステレオタイプ・バイアス**、theory-informed prompting=**未検証の仮定**、task-specific prompting=整合強いが**転移しない**。総括として「**大規模・長ホライズンでは伝統 ABM とハイブリッドの方が時間的行動ドリフトと解釈不能性に強い。LLM 中心は短期・行動豊富な設定で、慎重に較正した場合に向く**」。
- **反省(§5.4)**: micro は粗い整合に留まりがち、macro は**比較対象の実データが希少**。とりわけ**創発の評価が難しく**、手法間比較が成り立たない。ABM の伝統に倣った**古典シナリオを設計して横断比較可能にすべき**、と提言。

### 2.5 リスク(§7)と課題(§8)

- **リスク 5 種**: **Reproducibility**(乱数種・プロンプト言い回し・モデルの軽微な変更に敏感。scenario では非決定性が増幅、society では初期化・網構造・構成の僅差が全く違う創発を生む。緩和=**標準化された報告・透明な実験文書化・決定論的複製だけに頼らず変動を織り込む統計枠組み**)/ **Bias**(訓練データ・プロンプト由来。scenario で相互作用を通じ蓄積、society で分極やエコーチェンバへ増幅。緩和=監査・脱バイアス・**異質性の意図的な組み込み**)/ **Interpretability** / **Safety**(毒性・幻覚が共有記憶を汚染)/ **Misuse**(prompt injection・jailbreak・大規模心理操作)。
- **課題**: individual=完全な行動履歴と内面が無いため高忠実複製が困難・**「平均人格」による異質性の欠如**・長期の一貫性維持・大量生産の困難。scenario=フロー設計に人間の専門知が要る・**協調失敗率が高い**(Cemri et al. 2025 が 14 の失敗様式を specification / inter-agent misalignment / task verification に分類)・精度と効率の両立。society=**現実整合の限界**(構築環境で観察するだけで現実の人口構成・相互作用機構との整合を担保しない研究が多く、結論に実務的意味があるか不明)・規模化に伴う簡略化・因果説明の困難。
- **層間のトレードオフ**: micro は忠実度、大規模は規模性を優先。**大規模社会シムでは厳密な個体整合は必ずしも必須ではなく、集計パターンが信頼できる限り中程度の個体ノイズは許容される。ただし結論の射程は慎重に区切ること**(Wu et al. 2025, "LLM-Based Social Simulations Require a Boundary")。

## 3. ★本プロジェクトへの反映点(18 項目)

各項目は「**サーベイの指摘 → 我々の現状 → 具体的アクション**」。優先度は ◎=本選前に効く / ○=本選後 / △=判断のみ。

### (a) 評価・検証手法 — 妥当性主張の作法

---

**S-01 ◎ micro / macro / system の 3 段で報告を固定する**

- **サーベイの指摘**: society simulation の評価は **micro(個体挙動の人間らしさ)/ macro(集合結果が現実のパターンと整合するか)/ system(実行時間・資源・スケーラビリティ・トークン消費と費用)** の 3 レベルに分かれる(§5.3)。3 つを揃えて出す論文が「妥当性を主張できている」論文である。
- **我々の現状**: **部分実装**。macro 相当は `scripts/calibrate_report.py`(現実の一次統計バンドとの照合・機械系と LLM 依存系を分離して表示)。system 相当は L2 の `llm_health` 3 列・`watchdog_llm`・`analyze_firing.py` の推論量見積・トークン予算調査。**micro が最も弱い**(実在人物の行動ログとの照合を持たない=構造上持てない)。3 者を 1 つの報告書に束ねる型は無い。
- **アクション**: 10 日観察ランの報告書テンプレを **§micro / §macro / §system の 3 節に固定**し、各節冒頭に「**何と比較したか / 比較できないなら、なぜできないかと代替**」を必ず書く欄を設ける。micro については「実個人との照合は行わない。代わりに(i) `calibrate_report` の行動頻度バンド、(ii) `judge.py` の κ、(iii) 分布の分散(S-03)で代替する」と**明示的に宣言**する。宣言することが妥当性主張になる。

---

**S-02 ◎ macro の判定を「stylized facts の再現」に置き換える**

- **サーベイの指摘**: 経済シムの評価は「**最も代表的なマクロ経済法則を再現できるか**」で行われる(EconAgent)。macro 評価一般でも「伝播規模・意見分布・トレンドが現実と整合するか」を**事前に決めた指標**で見る。さらに §5.4 は「ABM の伝統に倣った古典シナリオを設計せよ」と提言する。
- **我々の現状**: **部分実装**。`calibrate_report.py` は現実バンドとの照合を持つが、これは**水準の照合**であって「**法則の再現**」ではない。事前登録(`docs/plans/stationarity-preregistration.md`)は非定常性の判定式を固定しているが、対象は反復性であって現実整合ではない。
- **アクション**: 事前登録に **「渋谷の stylized facts リスト」** を 1 節追加する(例: 時間帯別人流の二峰性、滞在時間分布の裾の形、週次周期、発話・関係次数の**べき則/Pareto 性**、混雑と待ちの単調関係)。**ラン前に「再現できたら成功と見なす法則」と「再現できなくても主張に影響しない法則」を分けて固定**する。これがないと事後にどの数字でも「合っている」と言えてしまう。

---

**S-03 ◎ 「平均は合うが分散が痩せる」を測る列を calibrate_report に足す**

- **サーベイの指摘**: LLM は「**average personality**」を示し、シミュ集団の**行動的異質性を制限する**(§8.1)。バイアス緩和策として「**異質性の意図的な組み込み**」を挙げる(§7)。
- **我々の現状**: **未実装(既知の穴)**。`docs/research/llm-human-fidelity.md` §1.4 が既に「**平均バンドは通っても分散が人間の何割かは calibrate_report では見えない**」と自己指摘しているが、対応は入っていない。`experiment.flat_traits`(ゼロ対照)と `analyze_g.py` の分散分解は「生まれつき vs 創発」の分離装置であって、「**人間と比べて分散が痩せているか**」は測っていない。
- **アクション**: `calibrate_report.py` に **分散/分位列**(個体間 CV、上位 10% シェア、Gini)を追加し、現実側にも同じ統計のバンドを置く。**平均が ✅ でも分散が現実の何割かを必ず併記**する。これは k* の主張(=裾の創発)に直結する最重要の測定であり、**平均だけで「現実的」と言うのは分野の典型的な過大主張**である。

---

**S-04 ◎ 主張の「境界」を事前登録で宣言する**

- **サーベイの指摘**: §8.4 が明示的に引く Wu et al. 2025 *LLM-Based Social Simulations Require a Boundary* — 「集計パターンが信頼できる限り中程度の個体ノイズは許容されるが、**結論をシミュレーションの射程を超えて拡張しないよう慎重に境界を引くこと**」。§8.3 も「構築環境で観察するだけの研究は、結論に実務的意味があるか不明」と断じる。
- **我々の現状**: **部分実装**。`propagation_off` の `fingerprint_risk=known` 正直宣言、registry の repro_tier、verify モードが「LLM 自由文が世界状態になる 3 機能を落とす=正直な宣言」など、**局所的な正直さの作法は既にある**。しかし「**この研究は何を主張し、何を主張しないか**」の全体宣言が 1 か所に無い。
- **アクション**: 事前登録に **§0 「主張の境界」** を新設。書くべき 4 行: ①主張する(例: 「この設計の下では、k* 的個体の出現は初期特性より環境フィードバックの寄与が大きい/小さい」)②主張しない(例: 「現実の渋谷で同じ比率で世界改変者が現れる」)③外的妥当性の限界(モデル 1 系統・10 日・LLM の positivity bias)④反証条件(何が観測されたら仮説を捨てるか)。**これは実装コストほぼゼロで、査読者が最初に見る箇所**である。

---

**S-05 ◎ 再現性の主張を「決定論的複製」から「変動を織り込む統計枠組み」へ二本立てにする**

- **サーベイの指摘**: 再現性の緩和策は「標準化された報告・透明な実験文書化、そして**決定論的複製だけに頼るのではなく、内在的変動を織り込む統計枠組み**」(§7)。society レベルでは「初期化・網構造・人口構成の僅差が全く違う創発を生む」。
- **我々の現状**: **決定論的複製は分野最高水準**(golden L1 バイト一致・RngHub named streams・CachedLLM・journal/replay fail-fast・`observer.state_hash` チェーン)。一方で「**seed 間の変動に対する頑健性**」の提示は弱い。観察ランは「再現性を厳密に求めない」方針(2026-07-31 決定)なので、**ここが主張の弱点になりうる**。
- **アクション**: 観察ランの結論指標について **seed 間分散 vs 条件間差の分散分解**を必ず出す(`analyze_g.py` の分散分解の型を全主要指標へ拡張)。「**条件差が seed 差より大きい**」ことを示せなければ、その結論は出さない、と事前登録で固定。決定論資産(verify)は「**装置が正しいことの証明**」、統計枠組みは「**結論が偶然でないことの証明**」として役割を分けて書く。

**S-06 ○ lifelong evaluation(長期一貫性)を個体レベルでも測る**

- **サーベイの指摘**: 「**lifelong evaluation、たとえば行動的役割の長期一貫性の評価はほぼ存在しない**」(§3.5)。context-compressed 型の典型的失敗は**ドリフト**(Table 2)。

**S-07 △ LLM-judge の使い方は現状を維持し、根拠をサーベイで補強する**

**S-08 ◎ アウトライアを「厚くしない」ことを設計主張として明文化する**

**S-09 ◎ 組織形成の観測を mode × structure × role の 3 軸に落とす**

**S-11 ○ 送り手側の影響力(誰が言ったか)の内生化を検討する**

- **サーベイの指摘**: §5.1.3 *Influence Exerted by the Influencer* — 「同じメッセージでも**誰が届けるかで社会的影響が異なる**。影響と注目は少数の支配的個体に集中し、**Pareto 分布と Matthew 効果**に一致する。シムは送り手の**身分・地位・評判**を考慮しなければならない。ただし群サイズが増えると単一影響者の効果は下がり、集合的影響が**同調(herd)**を生む」。
- **我々の現状**: **部分実装**。`closeness`/tier・partnership・`relations.dunbar` により「**関係の近さ**」は効くが、「**評判・地位**」という送り手属性は独立には持たない。信念台帳(`beliefs`)は情報の真偽と伝播木を持つが、送り手の重みづけは弱い。

**S-15 ◎ sycophancy / 調和への収束 — 対策は「測る」までは済み、「戻す」は未着手**

- **サーベイの指摘**: unstructured debate 型の典型的失敗が **social sycophancy と context dilution**(Table 4)。安全性の章では、有害・迎合的内容が**共有記憶を汚染して集合推論を壊す**とする(§7)。§8.1 は「平均人格」による異質性の欠如を挙げる。
- **我々の現状**: **測定は実装済み・是正は未着手**。`observer.echo`(L2 常設 5 列)は発話の自己反復・同質化を測る主装置で、事前登録は **`echo_max == 1.000` の崩壊ランを k* 推定の母集団から除外**する規則まで持つ。`ablate.propagation_off` は「他者文脈を注入しない」対照。一方、`docs/research/llm-human-fidelity.md` §2.2 が指摘する **utopian illusion(不満が発話段で鎮静される)への是正機構は入っていない**。

**S-16 ◎ プロンプト言い回しへの感度 — 頑健性 ablate が 1 本足りない**

**S-17 ○ 境界アーティファクト — 我々はハイブリッドなので Table 6 の失敗様式が直撃する**

- **サーベイの指摘**: Table 6 — **LLM+ABM ハイブリッド**(hierarchical hybrid / functional hybrid)の典型的失敗は「**boundary artifacts(境界のアーティファクト)**」「**integration coherence(統合の非一貫性)**」。ルール層と LLM 層の接合部で、どちらの層にも由来しない偽の構造が生まれる。
- **我々の現状**: **装置はあるが、この観点で読んでいない**。`ablate.llm_off`(LLM 0 本・ルール層のみ)は**まさに境界の片側を落とす実験**であり、`cognition.contract`(世界→Perception→prompt / LLM→Intent→実行の 2 型に結合面を限定)は**境界を型として明示した**もので、分野の平均より遥かに整った構造。
- **アクション**: 報告書に「**境界アーティファクト検査**」という節を立て、`llm_off` と本番の差分を**「LLM 由来の寄与」ではなく「境界で生まれた構造の有無」として読む**。具体的には、`llm_off` にも本番にも無い構造が両者の中間条件(例: `propagation_off`)で現れたら、それは境界アーティファクトの候補。**`contract` の型定義があるので、どの結合面が疑わしいかを特定できる** — これは我々にしかできない検査。

**S-18 ◎ ステレオタイプ増幅 — ペルソナ由来の定型語を 1 度は測る**

- **サーベイの指摘**: conditional-control 型(多様なペルソナのプロンプト注入)の典型的失敗は「**stereotype amplification(ステレオタイプ増幅)**・キャラ崩壊」(Table 2)。Table 6 でも naive prompting の失敗は **stereotype bias**。バイアスは「scenario で相互作用を通じ蓄積し、society で分極・エコーチェンバへ増幅する」(§7)。
- **我々の現状**: **未実装**。ペルソナは IPF 合成属性 + LLM 文章化 = サーベイの分類では「conditional-control(多様なペルソナのプロンプト注入)」に該当し、**この失敗様式が直接あてはまる**。造語観測(`natural-coinage`)は語の**発生**を見るが、属性別の**定型語の偏り**は見ていない。
- **アクション**: 属性(年齢層・職業など)ごとに**その群に過剰出現する語**を測る 1 回限りの検査(Marked Personas 型の語彙マーキング検査)を、既存 L1 の発話テキストに対して**オフラインで**行う(`scripts/` に読み取り専用スクリプトを 1 本、シム本体ゼロタッチ)。**「造語が自然発生した」と主張する前に、「その語がペルソナ属性のステレオタイプの反映でないこと」を示せる必要がある** — 自然造語観測の主張の防壁として重要度が高い。

## 4. 我々が既にサーベイ水準を超えている点(正直な列挙)

サーベイ本文・Table 5(society simulation の代表研究一覧)・§7 リスク章と照合したうえで、**「サーベイに記述が無い」または「課題として挙げられているだけで解決例が示されていない」** ものを挙げる。

1. **決定論的再現性の装置一式**。サーベイ §7 は再現性を全レベルの課題として挙げるが、解決例は「標準化された報告」までしか示さない。我々は **golden L1 バイト一致 / RngHub named streams(68+)/ CachedLLM(内容アドレスキャッシュ)/ LLM 入出力ジャーナル+REPLAY fail-fast / `run_manifest.json`(git SHA・config hash・全トグル)/ `observer.state_hash` チェーン**を持つ。**「同じ入力から同じ社会が再生される」ことをバイト単位で証明できる社会シムは、Table 5 の 40 本余の代表研究に存在しない**。
2. **指標定義そのもののハッシュ凍結**(`metrics_spec_hash`、指標定義 14 ファイルの正規化ハッシュを manifest へ)。**事後に指標定義を書き換えていないことの機械的証明**であり、これは社会シム分野に前例をほぼ見ない。事前登録(閾値の事前固定+変更履歴の義務+変更前後の両方報告)と合わせ、**サーベイ §3.5/§5.4 が「評価が信頼できない」と嘆いている問題への直接の回答**になっている。
3. **観測がシムを変えない構造**。`no-fingerprint` テスト、`cognition.contract` の ON/OFF **プロンプト文字列完全一致**、observer の読み取り専用性、`live_viewer.py` の別プロセス読み取り(+Windows 共有フラグ事故の発見と修正)、judge のシム逆流不能。**サーベイには「観測の侵襲性」という概念自体がほとんど現れない**(評価は事後解析として自明に非侵襲と仮定されている)。我々は「計器を挿したことで社会が変わっていない」ことを証明する装置を持つ。
4. **アブレーションとゼロ対照の体系**。`llm_off` / `propagation_off` / `cognitive_tier` / `shuffle_partners` の 4 種 + `experiment.flat_traits`(CRN 乱数消費一致のゼロ対照)。サーベイの評価節(§3.4/§4.3/§5.3)に**アブレーションの作法はほとんど登場しない**。とくに `propagation_off` で「fingerprint_risk = known」と**残存リスクを消せないまま正直に宣言**する態度は、分野の平均的な報告水準を明確に上回る。
5. **測定循環(measurement circularity)への防壁**。`judge.py` の R4 憲法(主指標は客観カウント / judge は補助 / κ ≥ 0.7 / 別ファミリ推奨 / シム逆流不能)。サーベイ §4.4 は「LLM 評価は偏りうる・信頼できない」と述べるだけで、**循環を構造的に断つ設計を示していない**。
6. **物理空間への現実接地の深さ**。実地図(PLATEAU/OSM)・実ダイヤ(ODPT)・建物高さ 3,531 棟・2.5D LOS 可視性行列・天候生成器(較正+来歴 sha256)・環境フィードバックの**環の閉じを L1 実例で実証**(待たされた本人が密度に還る)。Table 5 の society simulation はほぼ全て**属性と社会網の接地**までで、**物理環境の接地を持つ研究は事実上ゼロ**。サーベイが environment-centric 型の失敗として挙げる「state desync」に対し、我々は不動点収束の実測(γ=0.7・10 分)で応えている。
7. **ロングホライズンの定常性診断**。サーベイ §3.5 が「lifelong evaluation はほぼ存在しない」と述べる領域で、我々は `diagnose_stationarity.py`(日次自己相似性 TVD・符号反転置換検定・ノイズ床でのスケールフリー化・lag_slope・burn-in 推定)を**事前登録つきで**持っている。§5.4 が求める「創発の系統的評価」に対する具体的回答になりうる。
8. **創発の因果候補の抽出**。`analyze_firing.py` の**発火連鎖グラフ**(A→B の因果候補・確度 3 段)・Kleinberg バースト・下方因果解析(`analyze_norms.py`)。サーベイ §7/§8.3 は解釈可能性を未解決課題としたまま、role-based attribution や可視化の提案に留まる。

### 4.1 逆に、正直に弱い点

- **micro-level の人間データ照合が無い**(実在個人の行動ログとの比較は構造上できない)。サーベイの micro 評価の主流はこれ。→ S-01/S-03 の代替宣言でしのぐ。
- **単一モデル系統への依存**。サーベイ Table 2/6 はモデル選択がパラダイムの性質を決めると示す。`docs/research/model-contrast-setup.md` に計画はあるが、**model × k の交互作用は未実施**。
- **プロンプト言い回しの頑健性が未測定**(S-16)。
- **分散・裾の現実比が未測定**(S-03)。研究課題が「裾」である以上、これが最も痛い。
