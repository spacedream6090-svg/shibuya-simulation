# LLMエージェントの記憶・注意アーキテクチャ総覧(注意機構ATT設計の基盤・レーン2/4)

> 2026-08-19。前提制約: 25万体/LLM呼上限1500/step/注意機構自体の追加LLM呼ゼロ
> (1stepに発火できるのは全体の約0.6%=注意状態は発火間を跨いで永続し、非発火時はエンジン側の
> 決定論更新のみで維持する必要がある)。

## 1. Generative Agents系 retrieval scoring=事実上の注意機構

- **原典**(Park et al. 2023, UIST, arXiv:2304.03442): score=recency(指数減衰0.995/ゲーム時)+
  importance(LLMが1-10採点=**観察毎に追加1呼**)+relevance(embeddingコサイン)→上位k注入。
  reflectionの「salient questions 3つ生成→再検索」=自己宣言的注意の最初期前例。
- **importance採点の問題**: 書き込み毎1呼は25万体で即死。スコア分布は左偏り・較正不良・モデル更新で
  ドリフト(MemReranker 2026等)→**イベント種別テーブル+頻度逸脱等のエンジン側プロキシ置換が実務標準**。
- 改良系: **Lyfe Agents**(arXiv:2310.02172)=workmem/recentmem/longmem 3層+Summarize-and-Forget・
  コスト1/10-1/100。**AGA**(arXiv:2402.02053)=方策キャッシュ+**ペア単位social memory**(関係+対話
  要約の圧縮)でトークン費3.4-42.7%。**Humanoid Agents**(arXiv:2310.05418)=欲求・感情・closenessの
  数値状態変調(呼ゼロ)。ACAN(Frontiers 2025)=学習型注意スコアラ(本選には過剰)。

## 2. MemGPT/Letta系=注意の出し入れ(ページング)

- **MemGPT**(arXiv:2310.08560): main context内の**書き込み可能な有限core memoryブロック**+external
  storage。LLM自身がfunction callで出し入れ=「何を文脈に置くか」の自己決定。専用呼は予算に反するが、
  **「有限の常駐ブロックを通常応答の中で編集する」骨格は追加呼ゼロに転写可能**。
- **MEM1**(arXiv:2506.15841, ICLR 2026): **毎ターン有限の内部状態<IS>を「前状態+新観察→統合・棄却」で
  全量再宣言**。RL訓練だが、**宣言フォーマットとしてはプロンプト指示+構造化出力で模倣可能=最有力前例**。
- **MemoryBank**(arXiv:2305.10250): **Ebbinghaus忘却曲線の呼ゼロ減衰**=非発火個体のスロットdecayに直用。
- 他: A-Mem(arXiv:2502.12110)=Zettelkasten+top-k注入・RAISE=Scratchpad・HiAgent=サブゴール単位
  チャンク化・Mem0=ADD/UPDATE/DELETE演算列の宣言形式。

## 3. 明示的な注意・作業記憶を持つ提案

- **CoALA**(arXiv:2309.02427): working memory=決定サイクル間の可変状態。**注意ブロック=CoALAの
  working memoryの構造化・有限スロット化**と位置づけると論文的に据わる。
- **PIANO/Project Sid**(arXiv:2411.00114, 〜1000体Minecraft): 並行モジュール群+**cognitive controllerが
  情報ボトルネックで集約→決定→放送**。ボトルネック=設計された注意という思想の明文化。
- **Attention Schema系**(PNAS 2021・arXiv:2305.17375): **自分の注意状態の記述モデルを持つと注意制御が
  向上**の実証=「スロットをエージェント自身が読める形でプロンプトに載せ自分で更新宣言させる」根拠。
- **★新規性確認**: 「社会シムで有限スロットの社会的注意(人物/場所/話題)を構造化出力で宣言・維持する」
  **直接の先行は見当たらない**。最近傍=MEM1(形式)・PIANO(思想)・MetaGPT購読(対象選択)。

## 4. 大規模社会シムの知覚・過負荷・選抜

- **OASIS**(arXiv:2411.11581, 100万体): **RecSysが事実上の注意機構**(TwHIN-BERT興味類似+recency+
  フォロワー数/Reddit hot score上位k)。24次元時間帯別活動確率で発火制御。100万体18h/step(A100×27)。
  **「候補生成=エンジン、選択=LLM」の二段化が100万体を成立させた**。
- **AgentSociety**(arXiv:2502.08691, 1万+体): Maslow欲求階層で動機優先度→計画。
- **AgentTorch/LPM**(MIT, 840万体): archetype集約=呼数を個体数から切り離す最強前例。ただし個体性が
  消えるため本件の中心機構には不採用(周縁個体のフォールバック候補)。
- SocioVerse(1,000万人プール・部分集団駆動)・GenSim(10万体)・S3。
- **過負荷対策4類型**: ①環境側選抜 ②個体側発火予算 ③集団圧縮 ④方策キャッシュ。本シムは①②を保有=
  注意ブロックは「①で絞った候補を②の発火時に個体が取捨する」第3の層。

## 5. 会話シムの聴衆モデル

- GA原典: 視野半径内観察・傍観者には**イベント要約のみ**(全文でない)。会話開始時に関係要約を注入。
- **Concordia**(arXiv:2312.03664): GMが観察を個別作文・配送=環境が注意を代行する極。
- **ChatArena**: **メッセージのvisible_toフィールド**=可視性メタデータ付きプールの工学的最小構成。
- AutoGen=次話者選択+全員放送・Werewolf=チャネル所属が聴衆・AI Town=近接会話+top-3記憶注入。
- **設計含意**: 聴衆=(物理範囲 or チャネル)∩(受け手の注意スロット)の二段フィルタが全前例を包含。

## 6. コンテキスト管理

- **Lost in the Middle**(arXiv:2307.03172): 長文脈中央は系統的に無視=**「大量に入れてLLM内部の注意に
  任せる」の否定**→少数高価値スロットを固定位置(先頭/末尾)に置く根拠。
- HippoRAG(arXiv:2405.14831)=KG+PPRで多段連想を検索時呼ゼロ。社会情報選抜の前例は(a)ペアキャッシュ
  (AGA)か(b)検索(GA)の2系統。

## 7. 適用可否マトリクス(要旨)

| 部品 | 判定 |
|---|---|
| recency/Ebbinghaus減衰・embedding類似 | 採用可(呼ゼロ・エンジン側) |
| importance LLM採点 | 不可→種別テーブル+頻度逸脱プロキシ |
| core memoryブロック(常駐・自己編集) | 骨格採用(専用呼は廃し既存呼へ相乗り) |
| MEM1式全量再宣言 | 宣言フォーマットとして採用 |
| OASIS式候補→LLM採否 | 採用(二段注意) |
| ChatArena visible_to | 採用(発話レコードに可視集合) |
| AGAペアsocial memory | 採用可(スロット付随の相手要約) |
| archetype集約 | 中心には不採用(個体性が主データ) |

**推奨骨子**: K=5-9スロット `{target_id, kind(person/place/topic/goal), why(短文), salience, last_update}`・
更新は(a)発火時=構造化出力で全量再宣言(候補はエンジン提示)(b)非発火時=decay+イベント駆動boost・
注入は固定位置・聴衆は二段フィルタ・傍聴者はイベント要約。
