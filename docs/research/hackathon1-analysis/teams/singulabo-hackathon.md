## ⚠ 最優先の訂正: A3.5 は「行動誘導」判定ではない

**担当時の想定(「何が行動誘導判定を招いたか」)は事実と異なる。** 講評・検証レポートを両方通読した結果、A3.5 の減点理由に**行動誘導(fingerprint)の指摘は一つも無い**。実際の減点理由は正反対の性質で、以下の3点に集約される。

1. **エージェントの行動自由度が事実上ゼロ**。各エージェントは `assigned_machine` を50 step 打ち続ける固定行動で、機種を変える `maybe_switch` ロジックは **v4.5 で意図的に削除**されている(`CLAUDE.md` に明記)。意思決定は完全に rule-based の感情更新式に支配される。
2. **LLM がシミュレーションのループに一切フィードバックしない**。LLM は Phase 3(心の声生成)・Phase 9(感情ラベル)・Phase 10(状況判断)の **観察用 sidecar** に徹し、出力はログ・JSON への保存のみで `PersonaState` も物理乱数系列も変えない。`submission/draft.md` 自身が「数値観察 = numpy + 確率モデル」「結果後の語り = LLM」と、**LLM をシミュレーションの外部に置く設計を明示している**。
3. **エージェント間相互作用が存在しない**。1,000人が並列に動くだけで、隣の台のヒットを見て感情が変わる・ホール全体のムードが個人に影響する、といったソーシャル動態が皆無。

講評の一言コメントが本質を突いている:
> 「LLM がシミュレーションの外部観察者に留まり、エージェントの自律的意思決定・相互作用・記憶という『マルチエージェント創発』の本質的要素が薄い点が惜しい。仮説検証実験としての設計は卓越している一方で、**『LLM ベースの自律マルチエージェント』というハッカソンテーマの軸からはやや距離がある**。」

つまり **B9.0(世界設定)と A3.5(創発設計)の乖離は、「作り込みの深さ」と「創発の器としての適格性」が別軸である**ことの実例。世界を精密に作り込むほど A が上がるわけではなく、むしろ**確率モデルで世界を固めきると A の余地が消える**。

## どんなシムか

パチスロホールを舞台に「最も脳汁(ドーパミン)が出る瞬間」を検証するシミュレーション。**8属性(初心者/ライトユーザー/中毒者/アフター5層/悠々自適/シニア/主婦/パチプロ)× 6機種カテゴリ = 48セル**に合計 1,008人を配置し、1日8,000G相当を50 step に圧縮して一斉実行。各エージェントは脳汁・ストレス・幸福度・絶望度の心理4値を持ち、機種側は初当たり確率・連チャン継続率・払出分布(対数正規)・払出上限・イベント衝撃度で表現される。仮説は3段論法 — ①ストレス極限で「爆発の兆し」を見たとき脳汁が最大化 → ②最もストレスを抱えるのは中毒者 → ③ゆえに最大の脳汁は中毒者が兆しを感じた瞬間、ではないか。結論は「**人 × 機種の合作**」で、仮説は支持されたが仮説だけでは足りない、というもの。

## 講評の要点

**強み(B9.0 / D7.0 の理由)**
- **世界設定の解像度と独自性が突出**。6機種完全校正(4号機・5号機・初代GOD まで実機経験ベース)、8属性 × 1,000人のパラメータ化、DeepResearch 由来の 169ペルソナカード、`docs/multi-path-addiction-model.md`(14経路中毒モデル、18KB)の原典資料まで整備。「依存症心理・ドーパミン報酬学習・大逆転認知の神経科学」レベルの解像度。
- **校正の厳密さ**。`run_calibration` で 1,000人 × 50 step を実走して `target_return` を実測検証。`MachineType.__post_init__` が対数正規の mu/sigma を mean/std から自動逆算し、`event_impacts["chain_start"]` も `chain_start_impact` から自動同期して **SSoT 違反を構造的に防止**。`assign_machines` は人数不一致で `raise`(fail-fast)。
- **仮説検証の科学的態度**。仮説提示 → **自己成就回避のための反論軸**(非中毒者ピーク / 低ストレス時ピーク / 機種独立効果)を明示的に確認 → 結論、という構造が draft.md と動画 Phase 6-8 で一貫。
- **LLM プロンプト品質**: `format=json` + retry(max_retries=2)+ `voice_history` 直近6件 + life_themes ヒント + 禁止語 + 属性別の性別分布・年齢サンプリング、と多層の制御。

**弱み**
- 上記の A3.5 の3点。
- C6.0: `src/` のプロダクション実装が**ほぼ空のスタブ**で本体は `spike/` に留まる。`spike_v44_demo.py` が 2,273行のモノリスで Phase 1-10 の描画関数が混在。`configs/machines.yaml` / `run_mvp.yaml` があるのに本番はベタ書き値を使い**参照していない**。
- D7.0 のメモリ側が 1-2点: エージェント単位の持続的メモリが存在しない。`voice_history` 直近6件は「被り回避用」であってエージェント個別の履歴ではない。CLAUDE.md には `session_context` / `social_commitment_density` / `afterglow` の設計記述があるが**シミュレーションループには適用されていない**。

## コード実査で面白かった点

1. **`__post_init__` による SSoT 自動同期**(`spike_v44.py:55-66)。dataclass に `payout_mean` / `payout_std` を人間が読める形で書き、`__post_init__` が対数正規の `payout_mu` / `payout_sigma` を逆算する:
   ```python
   sigma_sq = log(1.0 + (s * s) / (m * m))
   self.payout_sigma = sqrt(sigma_sq); self.payout_mu = log(m) - sigma_sq / 2.0
   ```
   さらに `if "chain_start" not in self.event_impacts:` で派生値を自動注入。**設定を2箇所に書かせない仕組みをコンストラクタで強制**するのは、shibuya-simulation の較正パラメータ管理にそのまま応用できる。

2. **`run_calibration` が「実測 vs ターゲット」の表を出す**。1,000人 × 50 step を回して機種別に `n_hits` / `total_stake` / `total_payout` / 払出分布 / イベント発生数 / 連チャン中ヒット数を集計し、`summarize_calibration` で目標値と並べて表示する。**確率モデルを書いたら必ず実走で回収率を確かめる**という規律。

3. **属性パラメータが「感受性・ストレス・閾値・所持金・回復」の5軸で構造化されている**。例えば中毒者(`C_CHASE`)は `sens_mean=0.92`(ドーパミン感受性最大)/ `base_stress_mean=0.78`(基礎ストレス最大)/ `threshold_median=15000`(撤退閾値が最小 = 粘る)/ `stress_floor_mean=0.48`(ストレスの床が高い = 下がりきらない)/ `hammari_tau=8`(ハマり耐性が最短)+ extras に `recovery_relief_weight=1.35`。**「中毒」を1つのフラグではなく5〜7個の連続パラメータの布置として表現**しているのが巧み。

4. **プロンプトの「被り回避」設計**(`spike_llm_voice.py`)。直近6件の他プレイヤーのセリフを渡して「**出だし・語感・言い回し**が被らないように」「特に『また』『もう』『やっぱり』など同じ書き出しを避ける」「数字(残金・連続外れ)の引用も控えめに」。さらに「お金の話だけにしない。属性ごとの生活感・感情・思い出・人との関係なども適度に混ぜる」「人名・地名・固有名詞・パチンコ用語の専門略語は使わない」。**20字以内・一人称・句点なし**という厳しい形式制約と `temperature=0.95 / top_p=0.92` の組合せ。
   - ただしこれは singulab と同じ構図で、**多様性をプロンプトの禁止語で確保している**(A を上げる方向ではない)。本作は LLM がループ外なので A への影響はもともと無いが、shibuya-simulation が真似する場合は同じ罠に注意。

5. **Phase 10 の「未来情報を渡さない」判断観測**。5つの状況シーンに8代表を置き、**次の抽選結果・最終ランキング・脳汁増分を渡さずに**「続行・追う・休む・台移動・撤退」を判断させる。「結果を知った後のコメントではなく、**結果を知らない状態での人間らしい迷い**も観察対象にした」。LLM をループ外に置きつつ、**情報遮断だけは真面目にやっている**点は評価できる。

6. **提出物の「限界と倫理的配慮」が5項目明記されている**。「抽象モデルであり実機再現ではない」「代表 seed の可視化であり**有意性検定は本提出物の範囲外**」「Phase 10 の LLM 判断は8代表への補助観察であり1,000人全体の統計値を上書きしない」「属性ごとの人数は比較のため均等化しており現実のホール構成比とは異なる」「機種名や依存症への言及は教育的・分析的文脈であり特定機種や特定行動を推奨するものではない」。**A が低くても D と提出物完成度で点を確保した要因**。

7. **主催配布コードを `reference/` 配下に改変なしで同梱**し、自作を `pachinko_hall_sim/` に分離。派生関係を明示する運用として真似する価値がある。

## shibuya-simulation に活かせそうな点

- **【最重要の教訓】「作り込み」と「創発の器」は別軸**。B9.0 と A3.5 の 5.5点差がその証拠。shibuya-simulation は現実渋谷の忠実再現(realism-first-scale)を掲げているので、**忠実に作り込むほど A が上がる**という素朴な期待は危険。忠実さは B に効き、A に効くのは「**LLM の出力が世界状態を変えるか**」「**エージェント同士が相互作用するか**」「**行動の選択肢が実質的に開いているか**」の3点。本選提出前に、この3点それぞれについて「どのコードのどの行が担保しているか」を1行で言えるようにしておくべき。
- **決定論エンジンと LLM の役割分担を「監査」で誤魔化さない**。本作は LLM を「数値状態を人間が読める形に変換する監査レイヤー」と位置づけたが、それが A3.5 の直接原因になった。shibuya-simulation の関係内生化(第62バッチ)は `w·較正 + (1−w)·内生` の合成 p で **LLM 由来の内生シグナルが実際に確率を動かす**構造なので方向性は正しい。ただし第62バッチの実測で `fallback 97.2%`(材料は day2 から効く)だったことを踏まえると、「**内生化率**」KPI は A 評価に直結する数字として本選で前面に出すべき。
- **`__post_init__` による派生値の自動同期**。shibuya-simulation の較正値・確率パラメータで「人間が読む値」と「実装が使う値」が二重管理になっている箇所があれば、dataclass のコンストラクタで一方から他方を導出する形に寄せると SSoT 違反が構造的に消える。
- **確率モデルは必ず実走校正して「実測 vs ターゲット」表を出す**。`run_calibration` + `summarize_calibration` の型は、shibuya-simulation の `calibrate_report.py`(REALITY 較正)と同じ思想。本作は「1,000人 × 50 step を回して回収率を実測」まで踏み込んでいるので、mock 実行での較正回収を同様に定型化したい。
- **「自己成就回避のための反論軸」を実験設計に組み込む**。本作は仮説(中毒者 × 爆発の兆し)を出したうえで、①非中毒者のピーク ②低ストレス時のピーク ③機種側の独立効果 という**仮説を否定しうる3つの観察軸**を先に決めてから結果を読んでいる。k* 掃引でも「k* が存在しない場合に何が見えるはずか」を事前登録しておくと、第63バッチの sign-flip permutation と合わせて主張の強度が上がる。
- **「限界と倫理的配慮」を提出物に明記する型**。5項目の書き方(モデルの抽象性 / 有意性検定の範囲外 / 補助観察が全体統計を上書きしない / 構成比の人工性 / 題材への非推奨表明)はほぼそのまま shibuya-simulation の提出物に転用できるテンプレート。
- **属性を「1フラグ」でなく「5〜7個の連続パラメータの布置」で表す**。「世界を変えようとする個体」を bool や単一スコアで持つと相転移が見えにくい。感受性・閾値・回復・床値・耐性のような複数軸の布置として持てば、k* 掃引で**どの軸が先に動くか**まで観測できる。
- **`spike/` と `src/` の乖離を作らない**。C6.0 の主因は「本番が spike フォルダ、`src/` はスタブ、`configs/*.yaml` は誰も読まない」という状態。shibuya-simulation は実装が直下に統一されている(github-repo の掟)ので現状問題ないが、締切直前に「動く方」が分岐しないよう注意。

## web リサーチ

- **ニアミス効果(near-miss effect)**: 本作の中心概念「爆発の兆し」に対応する確立された研究概念。客観的には負けだが勝ちに酷似した結果が生理的覚醒を高め、ギャンブル継続の動機を強化する。Griffiths (1999) は「ギャンブラーは**常に負けているのではなく、常に惜しいところまで勝っている**と信じる」と表現した。
  - Clark ら (2010) の fMRI 研究は「**ギャンブル重症度が、勝利ではなくニアミスに対する中脳ドーパミン系の反応の大きさを予測する**」ことを示した。本作の仮説「最もストレスを抱える中毒者が兆しに最も強く反応する」は、この知見と方向性が一致している(ただし本作は文献を根拠に挙げていない)。 https://pubmed.ncbi.nlm.nih.gov/20445043/
  - ラットのスロットマシン課題でもニアミス効果のドーパミン変調が確認されている(Neuropsychopharmacology)。 https://www.nature.com/articles/npp2010230
  - VR を使ったニアミス効果研究(Frontiers in Psychiatry 2024)。 https://www.frontiersin.org/journals/psychiatry/articles/10.3389/fpsyt.2024.1322631/full
- **A3.5 の構図に対応する学術的論点**: **"Should LLM Agents Decide in Social Simulations? Comparing Finite-State and LLM-Based Decision Policies"**(arXiv 2606.12369)。有限状態機械による決定と LLM による決定を社会シミュレーションで比較する論文で、まさに本作が選んだ「決定は確率モデル、LLM は語り」という分業の是非を扱う。**分業自体は学術的にも正当な選択肢**であり、ハッカソンのルーブリックが「LLM ベースの自律マルチエージェント」を評価軸に置いていたためミスマッチが起きた、という読み方ができる。 https://arxiv.org/html/2606.12369v1
- **Mechanism Plausibility in Generative Agent-Based Modeling**(arXiv 2605.12824)。生成的 ABM の検証指標として "believability"(もっともらしさ)が 35論文中 22本で主要指標に使われていると指摘し、**メカニズムの妥当性**へ軸を移すべきと論じる。本作の Phase 9「人間が見て自然な内面反応として読めるかを監査する」はまさに believability 基準であり、この批判の射程にある。 https://arxiv.org/pdf/2605.12824
