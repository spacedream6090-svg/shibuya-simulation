## どんなシムか

隕石衝突から 3 ヶ月後の不安定化した社会を舞台に、住民 20 名(心理学教育あり群 10 名 / なし群 10 名)の振る舞いを比較する災害社会心理シミュレーション。世界は 5 フェーズ固定ナラティブ(衝突から3ヶ月・食料価格高騰 → 根拠不明の噂が拡散 → 隣人との摩擦 → コミュニティの分断 → 最終的な決断)で段階的に圧力が上がる。各エージェントは善良さ/狡猾さ/感情的/論理的/自己保存/依存性の 6 次元パラメータを `random.random()` で持ち、Groq API(llama-3.1-8b-instant, temperature=0.9)で `COOPERATE / TEACH / HOARD / ISOLATE / PANIC` の 5 択から行動を選ぶ。唯一の動的フィードバックは「自己保存 ≥0.7 のエージェントが HOARD/ISOLATE を選んだら次フェーズに『食料が原因不明で一部消失』イベントを挿入」の 1 種類。研究上の問い:「心理学教育を受けた人々は危機時により協力的に行動できるのか」。

**A=4.5**: 3 つの構造的制約が指摘された。
1. **行動が事前ラベル化された 5 択**。`simulation.py:52` のプロンプトが「以下の5つのアクションから1つを選んでください」。講評:「これは『生データやルール』ではなく事前にラベル化された行動選択肢で、行動の自由度が大きく狭められている」。
2. **エージェント間相互作用が存在しない**。`_build_prompt` は自分の性格・自分の行動履歴・フェーズ文だけを渡し、**他エージェントの行動を一切観測しない**。20 体いるが実態は 20 本の独立試行。
3. **世界状態が動かない**。5 フェーズは `config.yaml` にハードコードされた固定ナラティブ。_eval_review が追加で確認したところ、`agent.stress_level` は dataclass の初期値 0.3 のまま**全フェーズを通じて一度も更新されない**——にもかかわらずプロンプトには「あなたの現在のストレスレベル: 0.3/1.0」と毎回入る。

**D=6.0**: メモリが `", ".join(d["action"] for d in agent.decisions)` でアクション名の羅列のみ。**LLM が書いた reasoning はプロンプトに戻らない**(記録はされるが使われない)。要約・反省・抽象化なし。`random.random()` にシード無し。

### 講評が拾っていない、こちらで見つけた計測上の欠陥(2 件)

**(a) 「協力行動率」と「パニック行動率」が定義上つねに足して 100% になる。**
`agent.py` の定義:
```python
COOPERATIVE   = {"COOPERATE", "TEACH"}
UNCOOPERATIVE = {"HOARD", "ISOLATE", "PANIC"}
...
@property
def panic_score(self): return sum(1 for d in self.decisions if d["action"] in UNCOOPERATIVE) / len(self.decisions)
```
`panic_score` は名前に反して「**非協力率**」で、5 アクションが 2 集合に排他網羅されるため `panic_score = 1 − cooperation_score` が恒等的に成立する。スライドの結果表(教育あり 92.7% / 7.3%、教育なし 80.0% / 20.0%)がぴったり 100% になるのはそのため。**独立な 2 指標として提示された発見は、実際には 1 個の数字の裏返し**。まとめの「パニック行動率において教育あり群(7%)と教育なし群(20%)の間に約 3 倍の差」は、協力率 +12.7pt という同一事実の言い換えにすぎない。

**(b) パース失敗が PANIC に計上される。**
`utils.py` は「未知の ACTION 値 → PANIC」「キーワード推定も失敗 → PANIC」。しかも `_KEYWORD_MAP` は dict 順で COOPERATE から走査するため、「冷静」「安心」を含む文はパニック的内容でも COOPERATE に落ちる。**LLM の出力形式崩れが被験者の心理状態として記録される**構造。

**(c) スライドの n=3 と、講評が評価した n=30 の乖離。** `run_stats.py` は `MAX_RUNS = 30` だが、スライドの結果は「統計結果(n=3回の平均)」「今後の課題: より多くの試行回数(**今回は API 制限により n=3**)」。講評 B/D は「n=30 回反復」をコードから読み取って加点しているが、**実際に報告された数値は n=3**。標準偏差 ±9.0% に対する差 +12.7pt は n=3 では有意とはとても言えない。

## それでも光る点

1. **問いが具体的で反証可能**。「小学5年生から義務教育・高校・大学を通じて心理学教育を受けた人々は、食糧難などの社会的危機に直面したとき、より協力的に行動できるのか?」——独立変数を 1 個(教育の有無)に絞り、群を 10/10 に分けた対照設計。B=7.0 はこの明快さへの評価。
2. **創発フィードバックのループを 1 本だけ持っている**。「自己保存 ≥0.7 の個体が HOARD/ISOLATE → 次フェーズに『食料が原因不明で一部消失』イベント」。**個体の行動が世界を変え、世界が次の個体行動を変える**という閉ループの最小形。1 本しかないのが弱点だが、方向性は正しい。
3. **結論の押し付けを自ら禁じている**。スライドの補足:「本シミュレーションは『協力行動が正しい』という結論を導くことを目的としていない。**食料を確保し家族を守ろうとする HOARD 行動もまた、生存戦略の一つである。危機的状況における人間の行動に、単純な善悪の判断を下すことはできない**」。研究倫理として誠実。
4. **仮説に反する観察を隠さない**。「心理学教育を受けていても、自己保存パラメーターが高い個人は HOARD 行動を取る場合があった」「教育なしグループも一定の協力行動(約80%)を示した。これはシナリオの性質上、協力が合理的選択として認識されやすかったことが影響している」——**自分のシナリオ設計が協力に偏っていた可能性を自己申告している**。
5. **多段フォールバックパーサ**(正規表現 → エイリアスマップ → キーワード推定 → 既定値)と、Groq の RateLimitError だけを上位に再送出しそれ以外は握るエラー分離。指数バックオフ `time.sleep(2 ** attempt)`。
6. **スライドに生 reasoning ログを添付**している。「[教育なし] 中村さん (自己保存=0.90) アクション: COOPERATE 理由: 他者と協力すれば〜」のように、集計値だけでなく個体の生発話を出す提示。審査側が中身を確認できる。

## shibuya-simulation への教訓

- **⚠ README 1 個で C が 4.0 に落ちる。** コードの拡張性は「平均以上」と認められていたのに、将来展望の文書がないだけで下位に沈んだ。shibuya-simulation は docs が厚いが、**提出時点で README 単体を読んで「目的・実験設計・結果・将来展望」が完結するか**を確認する。詳細ドキュメントへのリンクだけで済ませない(mars も同じ罠で C=5.5)。
- **⚠ 相補的な指標を 2 つの発見として書かない。** `cooperation_score` と `panic_score` が恒等的に足して 1 になる例は、R²(k) 掃引の KPI 設計にそのまま刺さる。**L2 KPI 列を追加するとき「この列は既存列の線形従属か」を必ず確認する**。渋谷側なら「変革志向率」と「現状維持率」を排他網羅の 2 集合から作ると同じ事故になる。指標の相関行列を出して従属列を検出する仕組みを入れる価値がある。
- **⚠ パース失敗を特定カテゴリに落とすと、そのカテゴリが汚染される。** 「失敗 → PANIC」は「LLM の出力崩れ」を「エージェントのパニック」として記録してしまう。渋谷側は **パース失敗を専用の `unparsed` カテゴリに隔離し、いずれの行動カテゴリにも計上しない**。fallback 発火率を独立に出す(mars・risk-gap の教訓と合流)。加えてキーワードマップの走査順が結果を左右する(先頭カテゴリが有利)ことにも注意。
- **⚠ プロンプトに入れる状態変数は、必ず更新されていることを検査する。** `stress_level` が 0.3 で固定なのに毎ターン「現在のストレスレベル: 0.3」と提示されていた。渋谷側では **プロンプトに載る全状態変数について「ラン中に値が変化したか」を検査するテスト**を入れられる(全ステップ同一値なら警告)。安いのに効く。
- **行動を列挙型に落とすと A が 4〜5 点帯で頭打ちになる。** 講評の提言:「アクションを 5 択カテゴリに限定せず、**LLM に自由記述させてから事後分類する設計**にすると行動の自由度が大幅に上がり創発ポテンシャルが向上する」。これは shibuya-simulation の観測分離(行動は自由・分類は観測側)と完全に同じ主張で、**現在の設計が正しいことの外部からの裏付け**として使える。
- **「N 体いる」だけではマルチエージェントとみなされない。** 20 体いても他者を観測しなければ 20 本の独立試行。渋谷側は会話・同席・関係性で相互作用があるが、**「あるエージェントの行動が他のエージェントの入力に到達する経路」を図で 1 枚にして提出物に載せる**と A 軸で確実に効く。
- **コードが n=30 対応でも、報告値が n=3 なら n=3 の研究**。API 制限で回せなかったことをスライドに正直に書いた点は誠実だが、結果として主張の強度が落ちた。8/30 に向けて **本番ラン数のためのレート・予算計画を先に固定する**。
- **結論を押し付けない書き方は真似する価値がある**。「HOARD もまた生存戦略の一つ」の一段落は、価値判断を避けつつ観察を提示する良い型。渋谷側の「世界を変えようとする個体」も、変革を善と前提しない書き方で提示する。

## web リサーチ

- 本作の前提「災害時に人はパニックになる」は災害社会学では **disaster myth(災害神話)** として長く否定されてきた。実証研究では避難行動はむしろ秩序的で、相互扶助(emergent norm)が優勢とされる。Quarantelli の一連の研究(Disaster Research Center, University of Delaware): https://www.drc.udel.edu/ 、および Drury et al. 2009, "The nature of collective resilience: survivor reactions to the 2005 London bombings", International Journal of Mass Emergencies and Disasters: https://doi.org/10.1177/028072700902700304 — 本作の結果(両群とも協力率 80〜93%)は、皮肉にもこの実証知見と整合している。スライドの自己批判「協力が合理的選択として認識されやすかった」はこの文献に接続すれば強い考察になった。
- 「緊急時に自発的な協力規範が立ち上がる」= **Emergent Norm Theory**(Turner & Killian)。災害時の集合行動の標準理論: https://en.wikipedia.org/wiki/Emergent_norm_theory
- 指標の線形従属(complementary metrics)を独立な発見として提示する誤りは、心理測定学で **criterion contamination / redundant measures** として扱われる。指標間の冗長性検出には相関行列と VIF が定番: https://en.wikipedia.org/wiki/Variance_inflation_factor
- LLM に自由記述させて事後分類する手法(本作への講評の提言)は、社会科学の質的コーディングを LLM で自動化する流れと同じ。Ziems et al. 2024, "Can Large Language Models Transform Computational Social Science?", Computational Linguistics: https://doi.org/10.1162/coli_a_00502
