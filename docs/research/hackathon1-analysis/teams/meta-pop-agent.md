## どんなシムか

仮想売場に「価格訴求 POP(198円)」と「体験数字 POP(糖度12度)」を左右に置き、10 体の「AI 消費者」が入口から入って**どちらの POP を選ぶか**を matplotlib で可視化するデモ。エージェントは「価格重視 / 品質重視 / 家族向け / 健康意識 / 発見好き / 料理好き」の 6 属性から `random.choice` で 1 つ割り当てられ、40 step かけて選んだ POP へ線形補間で近づく。主張は「支払数字から体験数字へ」——価格ではなく体験の数字で価値を伝えれば、価格競争から脱却できる。

## 講評の要点(なぜ減点されたか)

### D=0.0 が何を意味するか

**LLM を一切使っていない。** それだけ。

`main.py` の import は 2 行:
```python
import matplotlib.pyplot as plt
import random
```
講評:「`openai` / `anthropic` / `langchain` などの SDK インポートも、HTTP による API 呼び出しも、**プロンプト文字列**も、構造化出力パーサも存在しない」「README は『AI エージェントを仮想売場に配置し、購買行動をシミュレーション』と謳うが、**実装上の意思決定は純粋な Python の `if/else`**」。

ルーブリック D は **LLM 3点 + Memory 3点 + コード品質 2点 + シミュレーション正確性 2点 = 10点**。LLM 0/3 とメモリ 0/3 が確定した時点で上限 4 点、そこから「LLM 未使用かつ意思決定がハードコードであるため残る 2 項目でも引き上げられない」として 0.0 が付いた。**ハッカソンの主題(LLM ベースのマルチエージェント・シミュレーション)を満たしていない、という宣告**。

_eval_review はここだけ元評価に異議を唱えている:「ルーブリックの加点項目(CodeQ/SimCorrect)は LLM 有無と独立に評価すべき設計のため、0.0 は厳しすぎる可能性がある。**1.0〜2.0/10 が穏当**」「matplotlib による可視化は実動作する(demo.png が成果物として存在)ことを踏まえれば最低 1.0 は付け得る」。総合も「7.0 は妥当範囲だが 8.0 程度が穏当」。**それでも最下位は動かない**。

### A=1.0: 「結論が if 文で保証されている」

エージェントの選択は初期化時に確定し、ループ中に一度も再評価されない。実コード(`main.py:26-31`):
```python
if agent_type == "価格重視":
    target = price_pop_area
    choice = "価格訴求 POP"
else:
    target = experience_pop_area
    choice = "体験数字 POP"
```
**6 属性のうち 5 属性が同じ else 分岐に流れる**(_eval_review が明示的に指摘:「属性ラベルは見かけ上の多様性であり世界モデルとして機能していない」)。したがって「体験 POP を選ぶ確率」は構造的に 5/6 ≈ 83%。

そして README の「実証結果」:
> - 体験数字 POP が多数のエージェントに支持される
> - 価格重視層のみ価格側へ

講評の指摘が痛烈:「**"結果" がコードの if 分岐で機械的に保証される構造**」。スライドも「実証結果 … 多くの消費者は『意味』で選ぶ」と結論し、「インパクト: 価格競争からの脱却 / 利益率の改善 / ブランド価値の向上 / **小売のルールが変わる可能性**」まで踏み込む。**入力した仮定をそのまま出力し、社会的結論として提示している**——シミュレーション研究における最も基本的な誤り(循環論法)。

さらに実装を読むと、40 step のループ内で `price_count` / `experience_count` を毎 step 数え直しているが、数えている `agent["choice"]` は初期化以降不変。**40 step 動かす意味が計算上ゼロ**で、最終出力は初期の `random.choice` の内訳そのもの。世界も 3 座標の定数(`price_pop_area=[-8,2]` / `experience_pop_area=[8,2]` / `start_area=[0,-8]`)だけで、混雑・知覚境界・情報伝播・エージェント間相互作用は一切ない。

### C=2.0

87 行の単一ファイルにトップレベル手続きで全部書かれ、`def` も `class` も 1 つもない。設定の外部化なし、`random.seed` なし。README に将来展望セクションなし(スライドには「将来展開: 実店舗導入 / EC / AI 接客 / メタバース売場」があるが、**リポの README には無い**)。

### _eval_review が拾った追加の綻び

- **README とコードで属性ラベルが不一致**: README「健康志向 / 家族志向」vs コード「健康意識 / 家族向け」。ドキュメントとコードの整合性欠如。
- 「6 属性中 5 属性が同一分岐へ収束」は A/B 両方の減点根拠になり得たが、元評価では B で軽く触れられたのみ。

## それでも光る点

1. **問いの立て方は本物**。スライド:「**人は本当に価格で商品を選んでいるのか？** ⇩ 本質的には、『体験・意味』で選んでいるのではないか」。背景も具体的:「現在の小売は価格競争に依存 → 値引きが前提の売場 / 商品の価値が伝わらない / 利益が残らない構造 → 消費者は『価格』でしか判断できない状態」。**現場の課題認識から始まっており、B=4.0 はこの一点で取れている**。

2. **「198円」vs「糖度12度(いちご並み)」という具体例が強い**。抽象的な「価値訴求」ではなく、**同じ商品に貼る 2 枚の POP** という最小の対照実験の形をしている。この対照設計自体は正しく、LLM に判断させれば実際に検証可能な仮説だった。講評も「小売・マーケティング領域に一定の現実的関連性を持ち、テーマ性は明確」と認めている。

3. **エージェント属性のラベル設計にペルソナの萌芽**。「価格重視 / 品質重視 / 健康志向 / 家族志向 / 発見好き / 料理好き」は消費者セグメンテーションとして妥当。実装が追いつかなかっただけで、**この 6 属性を LLM のシステムプロンプトに入れて POP 2 枚を見せる**だけで、D の LLM 項目は 0→2 になり、A も上がった。講評の提言も同じ:「最低限、各エージェントの選択を `if/else` ではなく属性・POP 情報・周囲の混雑などを与えた LLM プロンプトに委ねる構成へ置き換える必要がある」。

4. **87 行で動く可視化が完結している**。demo.png が成果物として存在し、`pip install matplotlib && python main.py` で誰でも動かせる。_eval_review が「最低 1.0 は付け得る」と擁護した唯一の根拠。

## shibuya-simulation への教訓

- **⚠⚠ 「結論が if 文で保証されている」構造を絶対に作らない。** これが最下位の本質的な理由(D=0.0 は形式要件違反だが、A=1.0 と併せて致命的)。shibuya-simulation は「世界を変えようとする個体は生まれつきか環境から創発するか」を問う。もし**エージェントのプロファイルに「変革志向」パラメータを置き、それが高い個体が変革行動を取るように実装したら、本作と同じ循環論法になる**。R²(k) の R² が「入力した変革志向の分散」を測っているだけ、という批判は必ず来る。
  - 対策 1: **sham/null 対照を必ず走らせる**(既に原則にある)。「変革志向を全個体同一にしても同じ R² が出るか」を測れば循環でないことを示せる。
  - 対策 2: 観測される「変革性」は**行動ログからの事後分類**であって、入力パラメータの読み出しではない、という経路を図で示す。
  - 対策 3: **入力パラメータと出力指標の相関を明示的に報告する**。相関が 1 に近ければ、それはトートロジー。
- **⚠ ループを回しても状態が変わらないなら、それはシミュレーションではない。** 本作は 40 step 回すが結果は step 0 で確定している。渋谷側で「日数を増やしても KPI が動かない」系列があれば、それは**その系列がシミュレーションから何も得ていない**サイン。L2 KPI 列ごとに「ラン中の分散がゼロでないか」を検査するテストを入れる(psychology-simulation の `stress_level` 固定と同じ検査で拾える)。
- **⚠ ハッカソンの形式要件(=LLM を意味のある形で使う)を満たさないと、他が良くても 0 点の項目が出る。** 8/30 提出前に、**募集要項の要件を 1 行ずつチェックリストにして、各要件に対応する提出物内のファイル・行を対応づける**。「LLM を使っている」ことが一目で分かる場所(README のアーキテクチャ図、プロンプト実物の掲載)を必ず作る。
- **⚠ README とコードのラベル不一致は拾われる。** 「健康志向 vs 健康意識」レベルの表記揺れも _eval_review が記録した。渋谷側は用語が多い(k、R²、tier、closeness、joint_invite …)ので、**用語集を 1 つ持ち、README・コード・スライドで同じ語を使う**。
- **⚠ スライドにあって README にないものは、評価されないことがある。** 本作は「将来展開: 実店舗 / EC / AI 接客 / メタバース売場」をスライドに書いたが、README に無いため C の将来展望が 2.0 になった。**スライドの主張は必ず README にも入れる**(逆に mars は「解析は PDF 参照」で README を空にして C を落とした。同じ穴の両側)。
- **✓ 現場の課題から始まる問いは強い。** B=4.0 は「小売の価格競争依存」という具体的な課題認識だけで取れている。渋谷側の「世界を変えようとする個体」も、抽象的な学術関心ではなく**具体的な社会的な問い**として最初の 3 行で言い切ると B が伸びる。
- **✓ 最小の対照実験の形(同じ商品に貼る 2 枚の POP)は美しい。** 条件を 1 個だけ変えて比較する設計は、複雑にする前に必ず通るべき道。渋谷側の CRN ペア比較実験(第63バッチの `endogenous_accept.yaml` 等)は既にこの型を持っているので、**「1 個だけ変える」という形の分かりやすさをスライドで前面に出す**。

## web リサーチ

- 「体験数字 POP」の背景にある「価格ではなく価値で売る」は、マーケティングでは **value-based pricing** と、店頭 POP の効果測定は **shopper marketing** の領域。POP 広告の売上効果に関する実証: Point of Purchase Advertising International(現 Shop! Association)の研究群 https://shopassociation.org/
- 「糖度◯度」のような属性情報の提示が選好を変える効果は、食品の **sensory expectation / label framing** 研究で扱われる。糖度表示と購買意向については日本の農研機構等の研究がある: https://www.naro.go.jp/
- 「意思決定を if 文で書いたシミュレーションが、入力した仮定を結論として出力する」問題は、エージェントベースモデリングでは **model validation / docking** の中心課題。Epstein の "Generative social science" は「生成できたこと」を説明の条件とするが、本作は生成していない(仮定の再表示)。Epstein 2006, *Generative Social Science*: https://press.princeton.edu/books/paperback/9780691158884/generative-social-science
- ABM の検証手法(トートロジー回避を含む)については Rand & Rust 2011, "Agent-based modeling in marketing: Guidelines for rigor", International Journal of Research in Marketing: https://doi.org/10.1016/j.ijresmar.2011.04.002 — マーケティング ABM の厳密性ガイドラインで、まさに本作が踏み外した点(検証・感度分析・パラメータの独立性)を扱っている。
