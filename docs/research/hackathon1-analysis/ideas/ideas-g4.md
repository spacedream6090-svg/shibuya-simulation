## 創発設計

### IDEA: 規範化の言語形式検出器(定冠詞化・as per our・as previously discussed)
- 出典: lunar_simulation / 説明資料 p10-11(`slides/17-2267-lunar_simulation.pdf`)
- 分類: 創発設計 / 実験・評価
- 内容: lunar は「プロトコル」の語をプロンプトに一切書いていないのに、Step 9 に Agent 2 が `as per our survival protocol` と無冠詞で命名 → Step 10 に別体が複製 → Step 11 に全体放送 → **Step 13 に定冠詞つき `the rotation protocol` として既存ルールに昇格**、という 4 ステップの規範化を観察した。別ランでは私的つぶやきの「酸素 20.0」が 20 ステップで「条約」になり、`as previously discussed` を根拠に他者へ退出を強制した。**誰も合意した記憶のないルールが拘束力を持った**と作者は書いている。
- shibuya-simulation への適用案: `coin_label` / ラベル伝播の観測に**言語形式ベースの規範化ステージ判定**を足す。(1) 無冠詞初出ステップ、(2) 他個体による初引用ステップ、(3) **定冠詞つき参照の初出ステップ**、(4) `as per our X` / `as previously discussed` / 「さっき決めた」相当の**合意参照表現の初出ステップ**、の 4 点を語ごとに記録する。観測側のみの追加なので no-fingerprint を一切壊さない。L2 に `norm_stage_reached`(0〜4)と `steps_to_definite_article` を足せば、k に対する規範化速度の反応が測れる。
- web リサーチ知見: Ashery et al., "Emergent social conventions and collective bias in LLM populations", Science Advances 11(20), 2025 — https://www.science.org/doi/10.1126/sciadv.adu9368 。naming game 枠組みで LLM 集団の規範自発形成を実証した先行研究。lunar も beyond-badminton も**この文献を引いていない**。shibuya が引けば研究文脈への接続が一段深くなる。
- 重要度: ★★★

### IDEA: 未定義行動(enum 外出力)を捨てずに創発シグナルとして計測する
- 出典: kibo_crew_sim / 説明資料 p10・p11・p13・p14-3(ユーザー共有 PDF)
- 分類: 創発設計 / 実験・評価
- 内容: kibo のプロンプトは action を 7 値の enum で厳密に定義している(move_forward / move_backward / turn_left / turn_right / inspect / communicate / report_status)。ところが Run 3 では LLM が**「ハッチを開けたい」という意図から `interact` という enum 外の行動を自分で発明**し、3 回出力した。リポの `runs_data.json` の `action_counts` にも `"interact": 3` として実在する。作者はこれを「行動空間を突破する意図」と呼び、「用意された選択肢では解決できない状況に対し、環境への物理干渉を LLM 自らが提案した」と創発の兆候に数えている。研究上の示唆でも「エージェントの意図と用意された行動空間のギャップ。未定義行動をどう近い定義済み行動へマッピング(補正)するかがシステム設計の鍵」と述べている。
- shibuya-simulation への適用案: **構造化パース時に enum 外だった出力をエラーとして捨てず、`undefined_action` イベントとして残す**。L2 に `undefined_action_rate` と、発明された行動の語彙リストを足す。これは「世界を変えようとする個体」の**操作的定義の最有力候補**になりうる —— 与えられた行動空間で目的が達成できないときに空間そのものを拡張しようとする個体、という定義は研究課題そのもの。R²(k) 掃引で `undefined_action_rate` が k に対して閾値的に反応するなら、それ自体が k* の証拠になる。**現在エラーとして捨てているものが最重要の創発シグナルかもしれない**。
- web リサーチ知見: —(コード実査と資料読解による)
- 重要度: ★★★

### IDEA: ペルソナ文言の行動指示棚卸し —— 環境の no-fingerprint と役割の no-fingerprint は別物
- 出典: ai-homecare-simulation(A=4.5・本グループ最低)/ beyond-badminton(A=6.5)
- 分類: 創発設計 / 提出物・審査対策
- 内容: ai-homecare は環境情報の提示を厳格に数値のみに絞り、コードにも `Only quantitative data is provided` とコメントを残していた。**にもかかわらず A=4.5**。理由はペルソナ記述が「老人がサポートを必要としている場合、**すぐにケアを行います**」「親の体調悪化の知らせがあれば、**すぐに駆けつけます**」で埋まっていたから。beyond-badminton も同様に `Inaction is boring` / `ACT INSTEAD` / `Avoid abstract discussions` をプロンプトに埋め込んで A=6.5。**評価軸では環境側の禁欲と役割側の指示が合算されて『行動の自由度』として一つに評価される**。
- shibuya-simulation への適用案: 本選提出前に**全ペルソナ/ロール文言の棚卸しを 1 回やる**。「サービス提供者も全員エージェント」方針を取っている以上、店員・駅員・警察官・医療者といった職能ロールがこの罠に最もはまりやすい。書き換え規則: 「あなたは駅員です。**混雑時は誘導します**」→「あなたは駅員です。改札とホームの間で働いています」。**存在条件・所属・関心領域までは書いてよいが、条件つきの行動(『〜のときは〜する』)は削る**。削った分の行動圧力は定員・時間・体力・関係という物理制約に移す(= all-in-smoke の Layer 2 の思想)。棚卸し結果は提出資料に「行動指示ゼロの証明」として載せる。
- web リサーチ知見: —(2 チームの減点構造の対照分析による)
- 重要度: ★★★

### IDEA: 「指示しない」だけでは不十分 —— 決定論部分と LLM 判断部分の境界を先に説明する
- 出典: all-in-smoke(A=5.0)/ ai-homecare-simulation(A=4.5)
- 分類: 創発設計 / 提出物・審査対策
- 内容: all-in-smoke は資料の Layer 2 で明確に**「『逃げろ』と指示しない」**と設計方針を宣言している。にもかかわらず A=5.0。理由は、指示しない代わりに**作品のハイライトである危機下の意思決定そのものを閾値 if/elif ロジックに移した**から(`live_fire_simulation.py:1264-1331`、`FIRE_CONTACT_DANGER=0.92`、`FATAL_EXPOSURE_TICKS=3`)。inner_voice すらテンプレート生成。ai-homecare も死亡が step 50 で強制発火し「医者・救急隊が何をしても結果が変わらない」と減点された。**no-fingerprint は必要条件であって十分条件ではない**。
- shibuya-simulation への適用案: 第62バッチの `relations_endo.py` は「構造化決定論抽出」+ 合成 p = clamp(w·較正 + (1−w)·内生) − gossip という決定論的合成を持つ。これは all-in-smoke の閾値ロジックと**外形が似ている**ので、審査でそう見られるリスクがある。提出資料に **「どこまでが世界の物理(決定論)で、どこからが個体の判断(LLM)か」の境界図**を 1 枚入れる。主張の型: 「衝突・定員・体力・移動時間は世界が課す制約であり、それを受けて**何をするかは LLM が決めている**。all-in-smoke が減点されたのは『立つか座るか』という**行動選択そのもの**を閾値が決めたからで、当プロジェクトでは行動選択は一貫して LLM 側にある」。あわせて ai-homecare の _eval_review が評価した「**イベントは決定論、反応は LLM**」というハイブリッド構造の言語化も流用する。
- web リサーチ知見: —(講評の減点構造の分析による)
- 重要度: ★★★

### IDEA: 「ペルソナを薄くすると別種の創発(構造化志向)が起きる」を想定して観測項目を用意する
- 出典: beyond-badminton / 説明資料 p17-19, p20-22, p26 発見 2・3
- 分類: 創発設計 / 実験・評価
- 内容: 2×2 のペルソナ無し 2 セルでは、応援(cheer)も命名(Punctuation Pass)も**ゼロ件**だった。しかし「何も起きなかった」わけではなく、**集団は揃って『構造を作ること』に向かった**。P8(名前を伏せた環境)は `structure 13,073` / `rod 6,763` / `grid 2,619` と環境の測定・構造化へ、P9(バドミントン環境)は `sequence 8,044` / `Handover 564` と身体動作シーケンスの手順化へ。作者は LLM の事前学習に含まれる教科書的・分析的文章のバイアス由来ではないかと推測している。総メッセージ数は P7 19,183 に対し P8 19,330 と**ほぼ同じ = 議論量は変わらず質だけが一変**した。
- shibuya-simulation への適用案: 個性を薄くした条件(sham/null 対照や低 k 条件)を回すとき、**現在の指標だけだと「創発が起きなかった」と誤読する**恐れがある。対照条件でも総発話量・総行動量は変わらず、内容だけが「関係的」から「構造的」へシフトしている可能性を先に想定し、**「構造化語彙」側のカウンタも用意しておく**(手順・順序・最適化・測定・配置・役割定義といった語群)。「創発の有無」ではなく「創発の**種類**」を測る枠組みにすることで、null 対照が「何も出ない対照」ではなく「別種が出る対照」として機能する。
- web リサーチ知見: —(4 セル比較の生数値による)
- 重要度: ★★

### IDEA: 「報酬関数から降りる力」を評価軸に立てる
- 出典: all-in-smoke / 説明資料 p8-③(社会実装の可能性)
- 分類: 創発設計 / その他
- 内容: 作者は社会実装先の 3 つ目に「AI エージェントの安全性評価 —— **『撤退能力』『危機認識』『報酬関数から降りる力』**を検証する評価環境。タスク成功率では測れない能力を評価」を挙げている。まとめ頁でも「損失が目前にあるとき、避難は『**敗北**』として意味づけられる」と、降りることが負けとして意味づけられる構造を指摘。
- shibuya-simulation への適用案: 「世界を変えようとする個体」の**裏返しの観測項目**として「与えられた役割/目標から降りる個体」を立てる。組織/経済モジュールがあるので、「所属組織の目的関数に反する行動を取った回数」「所属を離脱した個体数と離脱ステップ」は実装可能。**世界を変える個体は、まず既存の枠から降りる個体である**という仮説なら、両者の時間的順序(降りる → 変える)が観測できるかもしれない。

### IDEA: 初期フレーム(初期数ステップの解釈状態)をラン単位共変量として記録し層別集計する
- 出典: kibo_crew_sim / 説明資料 p10・p11・p14-1
- 分類: 実験・評価
- 内容: **同一シナリオ・同一プロンプト・同一モデルで 3 回実行して、行動戦略に大きな分散が出た**。Run 3 は初期から `alert` で最も広く移動し enum 外行動まで発明、Run 4 は `calm` から段階的、Run 5 は最も慎重で移動幅最小・唯一 `concerned` を使用。作者の研究上の示唆 1: 「**初期状態を『警戒』と解釈するか『平穏』と解釈するかで、その後の探索範囲や行動アグレッシブネスが決定づけられる**」。lunar も「同一条件内でも初期配置等の複合要因により結果が分散し、5 回の試行では傾向の特定に限界があった」と同じ問題を報告している。

### IDEA: 「命名者」と「制度化者」を分けて観測する(coiner vs institutionalizer)
- 出典: beyond-badminton / 説明資料 p16
- 分類: 実験・評価 / 創発設計
- 内容: P7 の Step 65 で "Punctuation Pass" を**命名したのは Agent 19(Casual / "first encounter, no agenda" ペルソナ)**。翌 Step 66 に 16 体が一斉採用したが、それを**形式化・パラメータ化したのは agenda の強い分析志向ペルソナ**(Agent 1 = Strategic Champion が「3 メートルの固定距離」「90 度の弧」を提案)。作者の観察: 「ペルソナの多様性が、『命名 → 共有 → 形式化』のサイクルを 2 ステップで成立させた」。
- shibuya-simulation への適用案: 研究課題「世界を変えようとする個体は生まれつきか環境から創発するか」に対し、**『世界を変える個体』が一種類ではない可能性**を観測する。`coin_label` の記録に (a) その語を**最初に発した個体**、(b) その語を**ルール/規範の文脈で再利用した個体**(= 上の「規範化検出器」の定冠詞化/合意参照が起きた発話の主)を分けて残し、両者の特性(k、tier、closeness、組織所属)を比較する。**k* が二層化する**(発案の k* と制度化の k* が別の値を持つ)なら、それ自体が論文級の発見になる。
- web リサーチ知見: Centola, Becker, Brackbill, Baronchelli, "Experimental evidence for tipping points in social convention", Science 360(6393), 2018 — https://www.science.org/doi/10.1126/science.aas8827 (OA: https://openaccess.city.ac.uk/id/eprint/20031/1/CM_CRO_Version.pdf)。人間 20 人集団で **committed minority が 25% に達すると急激に多数派が新規範を採用する**臨界質量を実験的に示した。beyond-badminton の「1 体(5%)が命名 → 翌ステップに 16 体(80%)が採用」は 25% よりはるかに低い比率で飽和しており、**LLM 集団では臨界質量が人間より低い可能性**がある。shibuya の k* 探索の事前予測として使える(相転移閾値が人間実験より低い方向にずれる)。
- 重要度: ★★★

### IDEA: 「1 行のプロンプト差分」を独立変数にする最小実験
- 出典: lunar_simulation / 説明資料 p4・p7・p9

## 本グループ横断の総括

1. **A(創発設計)を落とす原因は 3 つしかない** —— (a) ペルソナ/プロンプトに条件つき行動を書く(ai-homecare 4.5、beyond-badminton 6.5)、(b) ハイライトの判断を LLM から取り上げる(all-in-smoke 5.0)、(c) エージェントが 1 体(kibo 5.5)。**shibuya はこの 3 つを最初から回避している**が、(a) は職能ロールのペルソナで再発しやすく、(b) は決定論的合成の説明不足で誤解されうる。
2. **B(世界設定)は素材の実在性で決まる**。実装量ではない。エージェント 1 体・テスト 1 本・README 無しの kibo が B=8.0。渋谷という実在の場所を扱う shibuya は最初から有利だが、**一次データへの接続を明示しないと取りこぼす**。
3. **C(発展性)の減点はほぼ全部「README に成果と展望が無い」**。5 チーム中 3 チームがこれで落ちている。
4. **再現性で減点されなかったのは all-in-smoke だけ**。seed 固定は D の必須条件。shibuya は決定論/ゴールデンテストを既に持っているので、**その事実を明示的に主張する**べき。
5. **先行研究を引いたのは beyond-badminton だけ**(しかも人文系の古典 2 本)。LLM 集団の規範創発は既に Science Advances(2025)に載っているのに、規範創発を観察した lunar は気づいていない。**shibuya は文献を引く文化を既に持っており、これは決定的な差別化要因になる**。
