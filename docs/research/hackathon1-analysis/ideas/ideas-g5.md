### IDEA: プロンプト行動指示検出器(no-fingerprint の機械的証明)
- 出典: spring-park-simulation / https://github.com/ichiko-trace/spring-park-simulation(README と `config.yaml`)、mars-llm-simulation-wanko / `agent.py:451`
- 分類: 提出物・審査対策
- 内容:
  spring-park の README は「行動指示や定性的評価(「危険」「快適」等)は一切与えない」と謳うが、同じリポの `config.yaml` に「においがするかぎり、北(up)へ一歩あるけ。**actionは "move" + "up" を選べ。**」「**actionはstayのみ。**」がある。審査員はこの矛盾を発見し、**根拠欄に README とコードを並べて引用したうえで A=3.0** を付けた。mars も `agent.py:451` の「ストレスレベルが0.7以上の場合は、原則としてhabitatに戻って休息…」で A=5.0 止まり。
  **主張は検証される。検証されて矛盾すると、主張しなかった場合より大きく減点される。**
- shibuya-simulation への適用案:
  no-fingerprint 原則は shibuya-simulation の看板であり、**同じ検査を必ず受ける**。以下を実装する。
  1. **`test_no_fingerprint_in_prompts.py`**(仮)を追加。全プロンプトテンプレート+config 由来の全文字列を結合し、禁止パターンにマッチしないことを assert する。禁止パターンは (a) 命令形語尾(`〜してください` / `〜せよ` / `〜を選べ` / `〜すること`)、(b) 閾値語+条件(`〜以上の場合は` / `〜を超えたら`)、(c) 定性評価語(`危険` / `安全` / `快適` / `避難すべき` / `望ましい`)、(d) 研究上の観測対象語(`世界を変える` / `イノベーター` / `変革` 等 = natural-coinage 観察の汚染防止と同じリスト)。
  2. **禁止語リストは `conf/` にデータとして置き**、テストとプロンプト生成の両方から参照する(spring-park の 215 行の ad-hoc 正規表現の逆をやる)。
  3. **README のトップに「このテストがある」ことと、テスト名・実行コマンドを書く**。審査員が主張を検証しにいったとき、矛盾ではなくテストが出てくる状態にする。
  4. mars の良い側(`_build_fire_section` の docstring "Only quantitative data is provided… No qualitative descriptions (e.g. "dangerous", "evacuate") are included.")を型として採用: **世界情報を生成する全関数の docstring に「何を渡し、何を渡さないか」を書く**。
- web リサーチ知見: no-fingerprint に相当する概念は ABM 検証論では「モデルの仮定と結論の分離」として扱われる。Rand & Rust 2011, "Agent-based modeling in marketing: Guidelines for rigor" https://doi.org/10.1016/j.ijresmar.2011.04.002
- 重要度: ★★★

### IDEA: 相補的 KPI(線形従属列)の検出
- 出典: psychology-simulation / `agent.py`(`cooperation_score` と `panic_score` の定義)
- 分類: 実験・評価
- 内容:
  **講評も _eval_review も見落とした欠陥をこちらで発見した。** psychology-simulation は 5 アクションを `COOPERATIVE={COOPERATE,TEACH}` と `UNCOOPERATIVE={HOARD,ISOLATE,PANIC}` に排他網羅で二分し、`panic_score` を後者の割合として定義している。したがって `panic_score = 1 − cooperation_score` が恒等的に成立する。
  スライドの結果表(教育あり 92.7% / 7.3%、教育なし 80.0% / 20.0%)がぴったり 100% になるのはそのため。**「協力率 +12.7pt」と「パニック率が約 3 倍」は独立した 2 つの発見として提示されているが、実際には 1 個の数字の裏返し**。
- shibuya-simulation への適用案:
  L2 KPI 列が増え続けている(第62〜64バッチで承諾率/内生化率/較正乖離/履行率/invite_weak_tie_rate/endo_share 等を追加)。**新規 KPI 列を追加するたびに「既存列の線形結合になっていないか」を検査する**。
  1. mock ランの L2 CSV に対し **KPI 列間の相関行列を出力**し、|r| > 0.98 のペアを警告する小さなスクリプトを `analysis/` に追加。
  2. 論文・スライドで KPI を並べるとき、**独立でない列を「別々の発見」として書かない**。特に「率」と「その補集合の率」は 1 列にまとめる。
  3. R²(k) の主指標と補助指標についても同じ検査を通す。
- web リサーチ知見: 指標の冗長性検出には相関行列と VIF(分散拡大係数)が定番 https://en.wikipedia.org/wiki/Variance_inflation_factor 。心理測定学では criterion contamination として扱われる。
- 重要度: ★★★

### IDEA: パース失敗を独立カテゴリに隔離する(fallback による分布汚染の防止)
- 出典: psychology-simulation / `utils.py`(`parse_agent_response`)
- 分類: LLM統合
- 内容:
  psychology-simulation のパーサは「未知の ACTION 値 → PANIC」「キーワード推定も失敗 → PANIC」と、**LLM の出力形式崩れをエージェントの心理状態(PANIC)として記録している**。しかも `_KEYWORD_MAP` は dict 順で COOPERATE から走査するため、「冷静」「安心」を含む文はパニック的内容でも COOPERATE に落ちる。**測定したい量(パニック率)が、測定失敗によって直接汚染される**構造。
  _eval_review も「パーサのデフォルト PANIC は計測バイアス源となり得る」と補足した。
  mars も同様に「テキスト解析 → stay」のフォールバックを持つが、こちらは stay(=中立)なのでまだ被害が小さい。
- shibuya-simulation への適用案:
  1. **パース失敗は `unparsed` 専用カテゴリに隔離し、いずれの行動カテゴリにも計上しない**。KPI の分母からも外すか、分母に含めるなら「unparsed 込み」を明示する。
  2. **fallback 発火率を L2 KPI として常時出す**(第62バッチの mock 実測で fallback 97.2% という値が出た実績があり、この数字が KPI として見えていること自体は正しい設計)。fallback 率が高いランは、KPI の解釈に注意が必要というフラグになる。
  3. キーワード推定を使う場合、**走査順が結果を左右する**(先頭カテゴリが有利)。全カテゴリのマッチ数を数えて最大を取る、あるいは複数マッチ時は `ambiguous` に落とす。
- web リサーチ知見: 分類器の未分類クラスを既存クラスに押し込むと事後確率が歪む。機械学習の rejection option / abstention の議論: Chow 1970, "On optimum recognition error and reject tradeoff" https://doi.org/10.1109/TIT.1970.1054406
- 重要度: ★★★

### IDEA: トートロジー回避の明示的な提示(sham/null 対照を前面に出す)
- 出典: meta-pop-agent / `main.py:26-31` + README「実証結果」
- 分類: 実験・評価
- 内容:
  最下位(7.0/40)の本質的な理由。エージェントの選択が初期化時の `if agent_type == "価格重視"` で確定し、6 属性のうち 5 属性が同じ else 分岐に流れる。したがって「体験 POP 支持率」は構造的に 5/6 ≈ 83%。それを README は「実証結果: 体験数字 POP が多数のエージェントに支持される」、スライドは「多くの消費者は『意味』で選ぶ」「小売のルールが変わる可能性」と社会的結論にまで拡張した。
  講評:「**"結果" がコードの if 分岐で機械的に保証される構造**」。**入力した仮定をそのまま出力し、発見として提示する**——シミュレーション研究で最も基本的な誤り。
- shibuya-simulation への適用案:
  研究課題「世界を変えようとする個体は生まれつきか環境から創発するか」は、**構造上この批判を受けやすい**。もしプロファイルに変革志向パラメータを置き、それが高い個体が変革行動を取れば、R² は「入力した分散の読み出し」になる。
  1. **sham/null 対照を必ず走らせ、結果の隣に並べて出す**(既に原則にある。実行して提示することが重要)。「個体差を全て同一にしても同じ R² が出るか」を示せば、循環でないことの証明になる。
  2. **入力パラメータと出力指標の相関を明示的に報告する**。相関が 1 に近い列があれば、それはトートロジー。上記「相補的 KPI 検出」と同じスクリプトで測れる。
  3. 「変革性」は**行動ログからの事後分類**であり、入力パラメータの読み出しではない、という経路を **1 枚の図**にしてスライド・README に置く(観測分離の説明そのもの)。
- web リサーチ知見: Epstein の generative social science は「生成できたこと」を説明の条件とする(仮定の再表示は生成ではない)。Epstein 2006, *Generative Social Science* https://press.princeton.edu/books/paperback/9780691158884/generative-social-science
- 重要度: ★★★

### IDEA: エージェント間の情報到達経路を 1 枚の図にする
- 出典: psychology-simulation(他者非観測)・agi-job-simulator(相互作用ゼロ)・meta-pop-agent(相互作用ゼロ)・risk-gap(3人分を1回のLLM呼び出しで一括生成)
- 分類: 提出物・審査対策
- 内容:
  下位チームの A 低得点の最大公約数が「**N 体いるが相互作用しない**」。psychology-simulation は 20 体いるが `_build_prompt` に他者の情報が一切入らず、実態は 20 本の独立試行。agi-job-simulator は 100 人生成するがループもメモリも通信もない(A=2.0)。risk-gap は 3 人分のセリフを 1 回の LLM 呼び出しで一括生成しており「エージェントとしての独立性・自律性を持たない」と評された。
  審査員は**「あるエージェントの行動が、他のエージェントの入力に到達する経路があるか」を A 軸の核心として見ている**。
- shibuya-simulation への適用案:
  渋谷側は会話・同席・関係性(closeness/tier)・joint_invite・gossip で相互作用が豊富だが、**それが提出物から一目で分かるとは限らない**。
  1. **「情報到達経路図」を 1 枚作る**: 個体 A の行動 → 発話 → 同席者の観測 → 記憶 → 翌日の計画 → 誘い → 承諾/拒否 → 関係性更新 → …のループを図示。第62〜64バッチの内生化(relations_endo)がまさにこの経路を強化した仕事なので、その成果を可視化することになる。
  2. **1 エージェント 1 LLM 呼び出しを守る**。会話バッチ最適化を入れる場合も、「同一プロンプト内で他エージェントの発話まで生成する」形にしない(risk-gap の失点パターン)。他者の発話は**入力としてのみ**渡す。
  3. 図には**経路ごとの実測トラフィック**(mock ランでの発火回数)を添える。第64バッチの mock 実測(source 内訳 closeness 146 / weak_tie 9)のような数字がそのまま使える。
- web リサーチ知見: Generative Agents の記憶ストリーム→検索→リフレクション→計画のループが、この種の経路の標準的な提示形 https://arxiv.org/abs/2304.03442
- 重要度: ★★★

  1. **設計自由度の棚卸し**: 「結果に影響しうる設計判断」を一覧化する(パラメータだけでなく、イベント設計・人口構成・場所の配置・時間解像度も含む)。
  2. **主要な設計判断について感度分析を持つ**か、少なくとも**「この判断は結果に影響しうる」と明記する**。
  3. **sham/null 対照**は、この「過剰関与」批判に対する最も強い回答。世界設計が結果を作っているなら、対照条件でも同じ結果が出るはず。
  4. 「少人数・低解像度でも見える現象はある」——**大規模ランの前に、小さい設定で現象が見えるかを確認する**。realism-first-scale と矛盾しない(小で見えたものを大で確認する順序)。
- web リサーチ知見: ABM のパラメータ空間探索と過適合の議論。Thiele et al. 2014, "Facilitating parameter estimation and sensitivity analysis of agent-based models", JASSS https://www.jasss.org/17/3/11.html
- 重要度: ★★

  3. **注意**: 叙述生成に使うプロンプトが、シム側のプロンプトと共有されないこと(観測語彙の隔離。前掲の `analysis/` 隔離と同じ)。
