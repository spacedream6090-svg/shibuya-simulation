### IDEA: 行動誘導リント — 「状態記述は可、行動推奨は不可」

**出典**: happy-to-chat-bench-simulation `_eval_review`(A 9.0 の満点を阻んだ唯一の要因)/ `agent.py:339-344`
**分類**: 創発設計 | 提出物・審査対策

**内容**
A9.0 を取った happy-to-chat のベンチ追記は2文からなる。前半 `Anyone sitting here is signaling "I am open to chat with strangers."` は**状態の記述**で問題視されず、後半 `Approaching this bench is a socially accepted way to start a conversation` が「**弱い行動誘導とも解釈可能**」と検証レポートに名指しされた。差は主語と述語の型にある — 前半は「このベンチに座っている人は〜という状態にある」、後半は「〜すること(動名詞)は社会的に容認された方法である」= **行動を主語にした推奨形**。

**shibuya-simulation への適用案**
no-fingerprint 監査を目視から機械検査へ格上げする。プロンプトテンプレートに対する静的リントとして、(1) 動名詞・不定詞が主語の文(`Approaching X is ...` / `〜することは〜だ`)、(2) 命令形・勧誘形(`〜してください` `〜しよう` `〜すべき`)、(3) 評価形容詞(`快適` `混雑` `望ましい` `おすすめ`)を検出して CI で落とす。許可するのは名詞句・状態記述・数値のみ。既存のゴールデンテストに `test_no_fingerprint_lint` を足し、プロンプトテンプレートの diff で必ず走らせる。屋内 SFM の場所説明・イベント説明・organization の説明文が主な対象。

**web リサーチ知見**
実在の Happy to Chat Bench の掲示文は "The 'Happy to Chat' Bench: Sit Here If You Don't Mind Someone Stopping To Say Hello."(Avon & Somerset 警察, 2019)で、**現実の装置自体が状態記述形**になっている。学術的裏付けは Cities & Health 誌の phatic communication 研究。 https://www.cnn.com/2019/07/08/europe/elderly-chat-bench-trnd/index.html / https://www.tandfonline.com/doi/abs/10.1080/23748834.2025.2544095

**重要度**: ★★★

### IDEA: 観測系と提示系を分離する(realism_contract)

**出典**: hackathon-singulab-inu(GOOD ECHO)`domain_packs/iss_benevolence/domain.yaml:218-223` と A 7.0 の減点理由 / `scripts/generate_habitat_conversations.py`
**分類**: 可視化 | 実験・評価

**内容**
GOOD ECHO はコアエンジンのプロンプト設計が「満点級」と講評に認められながら A7.0 に留まった。原因はシミュレーション本体ではなく、**UI 用の会話再生成スクリプト**に tone 許容集合と語彙禁止リスト(`rule_only_no_nudge_objects` の時は「ナッジ」「持ち寄り棚」と言うな)が入っていたこと。講評の提言は「ポストプロセスをオプション化するか、**『観測のみ』と『再生成』で記録を二系統に分ける**」。同リポは対策として `realism_contract` を YAML に持ち、「会話しない・沈黙する・相手を避ける状態も有効な観測として表示する」「**Run B の改善は万能にせず、短い摩擦・遅れた修復・ナッジの押しつけ感も残す**」と契約化している。

**shibuya-simulation への適用案**
`make_viewer` / `make_endo_report.py` / 2D・3Dビューアが生ログの写像に徹しているか監査する。語の言い換え・トーン整形・欠測の穴埋めをしていたら `raw/` と `presented/` の二系統に分け、presented 側には必ず変換規則を同梱する。さらに実験 YAML(`conf/experiments/*.yaml`)に `realism_contract:` セクションを新設し、「treatment 条件を良く見せない」「効かなかった系列を落とさない」「日次の位置・所属は連続性を保ちランダムに描き直さない」を項目として書き、ゴールデンテストで契約項目の存在と充足を検査する。

**web リサーチ知見**
生成的社会シミュレーションの中心課題は妥当性検証であるというレビュー(Artificial Intelligence Review 2025)。可視化が結論を先取りする問題はこの検証課題の一部として位置づけられる。 https://link.springer.com/article/10.1007/s10462-025-11412-6

**重要度**: ★★★

### IDEA: 知覚カバレッジ率をスケール不変量にする

**出典**: singulab スライド 4.5節 / 6.2.1節(100体ラン v1 の 8時間34分の完全失敗と幾何分析による復旧)
**分類**: 規模化・性能 | 世界設計

**内容**
5体ランで成功した `visible_radius=18m` を100体ランへそのまま流用したところ、office が 20×20m から 80×80m に拡大していたためカバレッジが 52% → **約3%** に縮小し、**30 step 中 UFO 言及0件**(発話3,705件すべて日常会話)という完全失敗を8時間34分かけて生産した。原因は幾何分析で特定 — office 角 (-40,40) と UFO 着地点 (-55,45) の距離 ≈ 15.81m に対し `visible_radius=18` では角の数体だけが辛うじて Mid 圏、しかも `communication_radius=5` で伝播できない。v2 で `visible_radius` を 60m にしてカバレッジを 41% に揃えたところピーク39体まで回復した。教訓は「**通信半径・知覚距離の絶対値は空間スケールで意味が変わる。カバレッジ率(%)で揃えるのが筋**」。

**shibuya-simulation への適用案**
realism-first-scale(人数 > 時間)で人数と空間を拡大するとき、通信半径・視界・聴取範囲・SNS リーチを**絶対値のまま持ち越さない**。ランチャに事前チェックを入れ、`coverage = (知覚円の面積 × 期待到達人数) / (空間面積 × 総人数)` に相当する指標を計算し、基準ランとの乖離が閾値を超えたら**ランを開始せずに警告で止める**。特にイベント(事故・キャンペーン・選挙告示)の発火位置と到達半径は、100体較正のまま1000体・広域渋谷に持ち込むと「誰にも届かないイベント」を数時間分生産する。この事前チェックは LLM を1回も呼ばずに実行できるので、コスト対効果が極めて高い。

**web リサーチ知見**
情報拡散のS字カーブ(段階的拡散 → ピーク → 慣れによる漸減)は Rogers のイノベーション普及理論および Bass 拡散モデルの形と一致し、singulab の v2 ランではこれが指示なしで再現された。カバレッジが不足すると拡散カーブそのものが立ち上がらない。 https://en.wikipedia.org/wiki/Diffusion_of_innovations

**重要度**: ★★★

### IDEA: プロンプト冒頭に「何を固定し、何を固定しないか」の3層宣言を置く

**出典**: hackathon-singulab `scripts/run_civilization_os_llm_demo.py:917-920`(A 8.0 の主因)
**分類**: LLM統合 | 創発設計

**内容**
プロンプトが自分自身の構造をプロンプト内で自己申告する:
```
- 出力契約: JSON形式、観測項目、分類語彙、短さは実装上の制約として固定する。
- 世界条件: エージェント属性、世界状態、日本社会状態、制度シナリオ、前ステップ記憶は観測条件として固定する。
- 人間反応: その条件で本人がどう知覚し、どう感じ、どう動くかは固定しない。
```
続けて「`event.direction` は『こう変化させろ』という指示ではなく、**社会状態の説明ラベル**です」と、誤読しやすい入力に個別の注意書きを付けている。

**shibuya-simulation への適用案**
全プロンプトテンプレートの冒頭に同型の3層宣言を必須ブロックとして置く。効果は二重で、(1) LLM 側の誤読(=渡した状態を命令と解釈する)を減らす、(2) **宣言部の diff を見るだけで原則違反が検出できる**ためゴールデンテストの検査対象が明確になる。特に relations 内生化で渡す「前日発話の明示キュー」「予定帳簿の衝突」は命令と誤読されやすい入力なので、`event.direction` 同様に個別の注意書きを付ける。

**web リサーチ知見**
LLM 社会シミュレーションから科学的主張を引くにはロバストネス監査が必須という提起(arXiv 2605.18890)。プロンプトの自己記述は監査可能性を上げる最も安価な手段。 https://arxiv.org/pdf/2605.18890

**重要度**: ★★★

### IDEA: 「効かないことを許可する」観測原則節(sycophancy 対策のプロンプト側実装)

**出典**: hackathon-singulab の「観測原則」/ hackathon-singulab-inu の neutral_v2「観測優先順位」
**分類**: LLM統合 | 実験・評価

**内容**
両リポとも、介入が効かない・悪化する・分裂することを**明示的に許可する節**をプロンプトに置いている。
- ksl: 「望ましい発表ストーリーに合わせる必要はありません」「全員が同じ方向に動くとは限りません」「大きな事件が起きても、本人に届かなければ反応は小さくてよいです」「支援が届いた層と届かない層…平均値だけに寄せず、**二極化や対象外反発を自然に出してください**」
- inu: 「1) 指示の最適化ではなく、自然な反応分布を優先する 2) **全員を協力方向へ誘導しない** 3) 不安・撤退・沈黙などの反応も、条件に整合するなら正当な観測値として扱う」+「高強度では、**防衛反応・相談遅延・短期志向の増加を許容してください**」

決定的に巧いのは ksl が**両方向に釘を刺している**点 —「不安が少し残るだけで自動的に注意へ固定しないでください」と楽観方向にも同じ分量で歯止めを書く。一方向だけの是正はそれ自体が誘導になるという理解。

**shibuya-simulation への適用案**
第62バッチの `hedge_markers`(婉曲拒否の誤マッチ棄却)は**出力側**の対策だが、これは**入力側**の先回り対策で相補的。REALITY 較正・承諾判定・組織参加のプロンプトに「参加しない/断る/関心を持たないことも正当な観測値である」と明記し、同時に「常に断る必要もない」と逆方向にも歯止めを書く。効果は較正乖離(`calib_gap`)で測れるはずなので、この節の有無を CRN 同一 seed で A/B すれば**プロンプト1節の因果効果**が測定できる(第63バッチの実験プロトコルにそのまま乗る)。

**web リサーチ知見**
生成的 ABM の検証指標として "believability" が 35論文中22本で主要指標に使われているという批判(Mechanism Plausibility in Generative Agent-Based Modeling)。「もっともらしさ」を目指すと LLM は必ず期待に迎合するので、**期待からの逸脱を明示的に許可する**プロンプト節はこの批判への直接の対策になる。 https://arxiv.org/pdf/2605.12824

**重要度**: ★★★

### IDEA: 対照条件のログを介入条件と同じ厚さで解析する

**出典**: happy-to-chat-bench-simulation `COMPARISON_REPORT.md` 3.2節(Ordinary 条件の「4-7-8 呼吸法」創発)
**分類**: 実験・評価 | 創発設計

**内容**
介入なしの Ordinary 条件で予想外の内生的秩序が立ち上がった。Step 11 に犬の散歩中の女性が面接前の学生に深呼吸を勧め、**Step 14 にミュージシャンとカウンセラーが同じ step で同時に**「4秒吸って7秒止めて8秒で吐く」と命名・体系化、Step 90 までに全メッセージの **49%(2,831/5,831通)が「呼吸」に言及、「4-7-8」を含む発話 1,366通**。Happy 条件では呼吸言及2%、「4-7-8」は**0通**。レポートはこれを「装置依存型集約 vs **テーマ依存型集約**」という別メカニズムとして解釈した。対照条件は「何も起きない条件」ではなく、**介入が占めていた場所を別の何かが埋める条件**だった。

**shibuya-simulation への適用案**
ラベル伝播研究にとってこれは直接の前例 — **介入なしでも語が自然発生し、命名され、集団の半分を覆う**。sham/null 対照のログを介入条件と同じ深さで解析するパイプラインを常設し、少なくとも (a) 語彙の新規出現時刻とその後の占有率カーブ、(b) 命名(coin_label)の発生と話者、(c) 同 step 同時発生(独立に同じ語が2人から出る事象)を定型集計する。natural-coinage-observation の方針(促さず観測する)にとって、**対照側こそ最も純粋な自然発生の観測場**になる。

**web リサーチ知見**
本件は「介入群の効果」を測る A/B が、対照群における別メカニズムの創発を見落としうるという一般的リスクの実例。LLM 社会シミュレーションの妥当性検証レビューでも、比較設計の解釈可能性が中心論点として扱われている。 https://link.springer.com/article/10.1007/s10462-025-11412-6

**重要度**: ★★★

### IDEA: A評価(創発設計)の3条件チェックリスト

**出典**: singulabo-hackathon の A3.5 減点理由3点(講評 + `_eval_review` で確定)との対比
**分類**: 提出物・審査対策 | 創発設計

**内容**
B9.0(世界設定)を取りながら A3.5 に沈んだ作品の減点理由は、忠実さでも作り込みでもなく次の3点だった。
1. **行動の選択肢が実質的に開いているか** — 固定行動(`assigned_machine` を50 step 打ち続け、`maybe_switch` は削除)は自由度ゼロと判定される
2. **LLM 出力がシミュレーション状態を変えるか** — sidecar(ログ/JSON への保存のみ)は「LLM as formatter」寄りと判定される
3. **エージェント同士が相互作用するか** — 1,000体の並列実行でも相互作用ゼロなら創発ポテンシャルは実質ゼロ

つまり **B と A は別軸**で、忠実に作り込むほど A が上がるという素朴な期待は成立しない。むしろ確率モデルで世界を固めきると A の余地が消える。

**shibuya-simulation への適用案**
本選提出前に、上記3点それぞれについて「**どのファイルのどの関数が担保しているか**」を1行で言えるようにし、README とスライドに明記する。特に2点目は第62バッチの合成 p(`w·較正 + (1−w)·内生`)が該当するが、mock 実測で `fallback 97.2%` だったことを踏まえると、実 LLM ランでの「**内生化率**」を A 評価の主張根拠として前面に出す必要がある(第62バッチで L2 に既に列がある)。3点目は joint_invite / gossip / ラベル伝播が該当するので、「相互作用が実際に何回起きたか」の実測値を提出物に載せる。realism-first-scale の方針は B を伸ばす施策であって A を伸ばす施策ではない、と切り分けて配分を決める。

**web リサーチ知見**
"Should LLM Agents Decide in Social Simulations? Comparing Finite-State and LLM-Based Decision Policies"(arXiv 2606.12369)。有限状態機械 vs LLM の決定方式を比較する論文で、**分業自体は学術的に正当な選択肢**。singulabo は学術的に妥当な設計を選んだがルーブリックとミスマッチした、という読み方ができる。 https://arxiv.org/html/2606.12369v1

**重要度**: ★★★

### IDEA: 「率」ではなく「経路」を測る — 媒介物語彙カウント

**出典**: hackathon-singulab-inu(GOOD ECHO)README「何が見えたか」2節 / D vs E 条件比較
**分類**: 実験・評価

**内容**
修復イベントなし条件で、修復的 status の**率**は A(ナッジなし)約60% / E(ナッジあり)約61% とほぼ同じだった。率だけ見れば「ナッジは効いていない」。差が出たのは**媒介物語彙の行数**(D=0 vs E=**164**、A/E 補助軸では E=57)。
- A(ナッジなし): 「ごめん」「言いすぎた」「短く確認しよう」= **相手の人格に直接踏み込む**修復
- E/B(ナッジあり): 「持ち寄り棚で」「OKサインの下で」「スコアボードを見ながら」= **第三項を介した**修復

結論の再フレーミングは「**ナッジは仲直りを作ったのではない。仲直りしなくても戻れる道を作った**」。率が動かない条件間でも、経路を数えれば差が検出できる。

**shibuya-simulation への適用案**
関係内生化の KPI が率(承諾率 0.601 / 履行率 0.337 / 内生化率)中心なので、「**何を介して**その関係が成立したか」の分布を足す。第64バッチの `joint_invite.source`(closeness / weak_tie / 内生経路)はまさに経路指標の芽なので、さらに**発話中の媒介語カウント**まで伸ばす — 誘い/承諾の発話に含まれる場所名・イベント名・組織名・共有物の語を数え、条件間で分布を比較する。ラベル伝播でも「語が伝わった率」ではなく「**どの媒介を経て伝わったか**」(直接会話 / SNS / 組織 / 選挙)の経路分布が主指標になりうる。

**web リサーチ知見**
南極越冬隊のウェアラブルセンサー研究(PNAS 2026)は、孤独感と対立が進行的に増加し、**近距離接触が対立と被害妄想的思考に結びつく**ことを示した。「接触量(率)を増やせばよい」わけではないという点で、経路指標の必要性を裏づける。 https://www.pnas.org/doi/full/10.1073/pnas.2533420123

**重要度**: ★★★

### IDEA: LLM 由来の方向バイアス監査と選択肢シャッフル null 対照

**出典**: singulab スライド 観察11「方向選択の右偏り(LLM 特性が集団行動に流出した例)」
**分類**: 実験・評価 | LLM統合

**内容**
プロンプトにも config にも「右に動け」は一切書かれていないのに、方向語の集計で右 ≫ 左が全ランで確認された: alien_5 = 56 vs 32(1.75倍)、**zero_gravity_5 = 203 vs 8(25.4倍)**、alien_100_v2 = 1,181 vs 177(6.7倍)。上下も上1,567 vs 下221(約7倍)。作者の考察は「英語圏の左→右読み・座標系の慣習が default として出やすい LLM の性質が、そのまま行動選択に流出した」。決定的に重要なのは、**外的目印(UFO)が無いシナリオで偏りが最も極端(25倍)になる**こと。作者自身が「prompt で防いでいないだけで、本来は気付いて対策する箇所だった」と正直に書いている。

**shibuya-simulation への適用案**

### IDEA: ダンバー数 LRU による忘却と再会イベント

**分類**: メモリ | 創発設計

**内容**
`AgentMemory(k)` は他者ごとに `last_interaction_step` を持ち、認知上限 k(5体ラン=10、100体ラン=30)を超えると **LRU で最古を追い出して `memory_evicted` イベントを発火**する。さらに `_evicted_history` に退避先を保持しておき、**一度忘れた相手と再接触したら `memory_re_encountered` を `gap_steps` 付きで発火**する。「忘却 → 再会」を型を持ったイベントとして観測可能にした点が、単なるログ上限管理と決定的に違う。

### IDEA: thought / private_talk / social_post の3層発話を同時観測する

**出典**: hackathon-singulab の観測項目定義(`run_civilization_os_llm_demo.py`)
**分類**: 世界設計 | LLM統合

**内容**
同じエージェントの同じ step について、**3つの異なる文脈の発話を別フィールドとして同時生成**する。
- `thought`(内心。本音で、まだ言語化しきれていない不安や怒りも含める)— 90字以内
- `private_talk`(友達や近い人との会話。砕けた口調で、弱音・相談・共感が出る)— 80字以内
- `social_post`(SNS発信。短く、社会向け・見られる前提の言い方)— 60字以内

字数上限を段階的に短くしているのも設計で、「公になるほど短く整えられる」という現実の非対称性をスキーマに埋め込んでいる。プロンプトは「発言はきれいに整理しすぎず、現実の人が言いそうな**迷い・矛盾・言い切れなさ**を残します」と明記。

**web リサーチ知見**
関連する古典理論として「沈黙の螺旋」(Noelle-Neumann 1974)。少数派だと知覚した個人が公的発言を控えることで、公的言説と私的意見が乖離する。3層発話スキーマはこの現象をシミュレーション内で直接観測可能にする。 https://en.wikipedia.org/wiki/Spiral_of_silence

**重要度**: ★★

### IDEA: エコー指標(echo_max / self_similarity)を常設 KPI にする

**内容**

## 付録: グループ2 から読み取れる A 評価(創発設計)の構造
