## 0. 要旨(結論先出し)

1. **RVO2 の Python バインディングは本機で導入できなかった**(PyPI に配布物なし・C++ ビルドツールチェーン
   未導入)。そのため ORCA 候補は **RVO2 参照実装(`Agent.cpp`)の式をそのまま移植した自前最小実装**で
   評価した。移植の忠実さと省略点は `reference/physics_bench/orca_min.py` の docstring に明記。
2. **決定論は両候補とも達成**。同一入力 2 回走で軌跡(位置・速度の float64 全バイト)が
   SHA-256 一致。3 シナリオ × 2 候補 = 6 件すべて `byte_identical: true`。
   **決定論は選定の決め手にならない**(評価軸①で差がつかなかった)。
3. **速度も両候補とも十分**。200 体・dt=0.1 s で実時間の 19〜34 倍速く回る
   (SFM 3.8万 / ORCA 5.7〜6.7万 agent·step/s)。**200 体 × 1 時間相当の物理が 2〜3 分**。
   **速度も決め手にならない**。CPU で足りたので JAX/GPU 案は再浮上させない。
4. **差がついたのは較正可能性(軸③)と、群衆現象の再現の質**。
   - **どちらの候補も既定パラメータでは歩行者の基本図(Weidmann 1993)を再現しない。**
     自前 SFM は既定 = Helbing2000 の *escape-panic* パラメータ(A=2000 N, B=0.08 m)で、
     実質「接触したら弾く」だけの短距離斥力。ρ=1.5 /m² では再スケール Weidmann と 1% 以内で一致するが、
     **ρ を上げると速度が再び上がる**(0.70 @1.5 → 0.77 @2.0 → 0.98 @3.0 m/s)= **基本図が非単調**。
     ORCA は一方向流では速度が互いに矛盾しないため **ρ=2 まで自由速度のまま**(1.14 m/s)流れ、
     ρ=3 で段差的に 0.44 へ落ちる。
   - **SFM はパラメータが基本図を 1.2 m/s 幅で動かす**(較正のレバーがある)のに対し、
     **ORCA は τ を 2→8 に 4 倍しても 1.19→1.09 しか動かず、唯一効く半径は動かすと一気に
     デッドロックへ落ちる**(ρ=2 で 1.14 → −0.27)。**連続的な合わせ込みができない。**
5. **自前 SFM には前進 Euler の剛性問題がある**。
   - **高密度の初期過渡**: ρ ≥ 2 /m² で最初の数秒、群れ全体が**平均 −1.0〜−1.4 m/s で後退**する
     (dt を 0.02 まで落としても消えない)。
   - **churn(かき混ぜ)**: ρ=3 /m²・dt=0.1 s では前進速度 0.083 m/s に対し速さ |v| = 1.09 m/s。
     進んでいないだけで激しく揺れている。**dt ≤ 0.05 s で v ≈ |v| に戻る**。
   → 指示書が想定する「物理 dt 0.1〜0.5 秒」は、既定パラメータの SFM では**低密度でしか成立しない**。
     P3 の dt 決定に直結する。
6. **推奨(承認待ち)**: **自前 SFM を主候補**とし、P4 で (a) 積分 dt を 0.02–0.05 s に落とす、
   (b) 斥力パラメータを通常歩行域へ振り直す、(c) それでも基本図が合わなければ
   **密度依存の希望速度 v₀(ρ) を較正テーブルとして外付けする**、の 3 段で合わせ込む。
   決め手は **軸③(較正可能性)と軸⑤(単純さ・既にある)** であって、軸①④ではない。
   ORCA は**採らないが捨てない**——**交差流(スクランブルそのもの)では ORCA が圧倒的**
   (速度効率 0.92 vs 0.53、方向反転 1/5)なので、P3 で破綻したときの第一代替として残す。
7. **どちらの候補も、完全混合の対向流では ρ ≈ 1 /m² を超えると事実上詰まる**
   (幅3m・200体で効率 0.02〜0.07)。一方 **ρ ≤ 0.44 /m² では SFM が教科書どおりのレーンを作る**
   (秩序変数 φ=0.86、帰無値 0.15 の 5.7 倍)。スクランブル交差点のピーク密度は詰まる側に入るので、
   **P3 の受入基準に「密度に対する平均速度が Weidmann 曲線の許容帯に入ること」を数値で入れるべき**。

## 2. 実装前リサーチ

### 2.1 RVO2 / ORCA の Python 実装の現状

**(a) PyPI 配布はない。** 本機(Windows 11 Home 26200 / Python 3.12.10)で 2026-08-01 に実測:

```
$ python -m pip install rvo2         → ERROR: Could not find a version that satisfies
                                        the requirement rvo2 (from versions: none)
$ python -m pip install pyrvo2       → 同上
$ python -m pip install python-rvo2  → 同上
$ python -m pip install rvo2-python  → 同上
```

**(b) 既知のバインディングはすべてソースビルド前提。**
`sybrenstuvel/Python-RVO2`(旧 `mit-acl/Python-RVO2` の後継)は RVO2 の C++ 本体を同梱した
Cython バインディングで、README が **「building requires CMake and Cython to be installed」** と明記し、
`python setup.py build` → `install` を要求する。動作確認済み環境として挙がっているのは
Python 2.7 / 3.4 / 3.6 on Ubuntu Linux(3D 版 `Python-RVO2-3D` は Windows 10 Pro でのテスト報告あり)。
本機は **cl.exe / gcc / cmake いずれも未検出、Cython 未インストール**で、
Visual Studio Build Tools の新規導入は本タスクのスコープ(pip のみ)を超えるため実施していない。

**→ 結論:** 「pip 一発で入る ORCA」は 2026-08 時点で存在しない。ORCA を採るなら
**(i) ビルドツールチェーン導入 + バインディングのビルド**、**(ii) 自前移植**のどちらかになる。
本比較では (ii) を採り、RVO2 参照実装の式をそのまま Python へ移植した(§4.2)。

**(c) ORCA の決定論性は良好。** ORCA の速度計算は「近傍ごとに半平面(ORCA 線)を作り、
3 段の低次元線形計画で希望速度に最も近い実行可能速度を選ぶ」だけで、**乱数を一切使わない**。
参照実装 `RVOSimulator.cc` の `doStep()` は

```cpp
kdTree_->buildAgentTree();
#pragma omp parallel for
for (i…) { agents_[i]->computeNeighbors(kdTree_); agents_[i]->computeNewVelocity(timeStep_); }
#pragma omp parallel for
for (i…) { agents_[i]->update(timeStep_); }
```

という **「全員の新速度を計算 → 全員を一斉更新」の二相構造**で、各エージェントは自分の
`newVelocity_` にしか書かない。したがって OpenMP のスレッド順が変わっても結果は変わらない
(集約の順序が結果に効く箇所がない)。**ORCA は決定論を取りやすい**という指示書の見立ては正しい。
ただし本体は `float`(32bit)なので、CPU/コンパイラを跨いだバイト一致は別途検証が要る。

### 2.2 SFM の較正の標準

**(a) パラメータの標準値は 2 系統ある。** これは選定に直結するので分けて書く。

| 系統 | 用途 | 代表値 |
|---|---|---|
| Helbing & Molnár (1995) | **通常歩行**。指数ポテンシャル `U(b)=V₀exp(−b/σ)` | V₀ ≈ 2.1 m²/s²、σ ≈ 0.3 m、τ = 0.5 s、異方性 c ≈ 0.5 |
| Helbing, Farkas & Vicsek (2000, Nature) | **避難パニック**。接触時の body force / friction を追加 | A = 2000 N、B = 0.08 m、k = 1.2×10⁵、κ = 2.4×10⁵、τ = 0.5 s、m = 80 kg、r ∈ [0.25,0.35] m、v_max = 1.3 v₀ |

(この 2 系統の対比は既存調査 `docs/research/social-force-crowd.md` §1.1–1.2 に整理済み。)
**本リポジトリの `sfm_core.py` は 2000 年版(パニック側)の A・B を採用している**。
B = 0.08 m は「接触してはじめて効く」超短距離斥力で、**通常歩行の先読み回避を表現しない**。
§5.6 の基本図のずれはここに起因する。

**(b) 基本図の参照曲線は Weidmann (1993) が事実上の標準。** Kladek 式のワイドマン係数:

```
v(ρ) = v_f · [ 1 − exp( −γ · (1/ρ − 1/ρ_max) ) ]
v_f = 1.34 m/s,  γ = 1.913 m⁻²,  ρ_max = 5.4 m⁻²
```

(数値は Kretz "The Social Force Model and its Relation to the Kladek Formula", arXiv:1512.01426 が
Weidmann のパラメトリゼーションとして引用しているもの。**原典 Weidmann 1993 の独語レポートは未確認**、
二次引用である旨を明記する。)
`ρ_max = 5.4 /m²`・自由速度 1.34 m/s は Fruin (1971) 系の LOS 文献が挙げる
「自由流速度 65–85 m/min(= 1.08–1.42 m/s)、ジャム密度 3.5–5.3 /m²」ともおおむね整合する。

**(c) 較正用の実測データは公開されている。** Forschungszentrum Jülich の
**Pedestrian Dynamics Data Archive**(`ped.fz-juelich.de/da`)が、廊下の一方向流・双方向流・
ボトルネックの**軌跡データ**を公開している。P4 の「合わせ込み用 CSV」はここから作るのが早い。
双方向流の基本図が一方向流より必ず下に来ること(specific flow の最大値が有意に小さいこと)は
Zhang, Klingsch, Schadschneider & Seyfried (2012) が Voronoi 法で定量化している。

### 2.3 歩行者シミュレーション検証の定番シナリオと定量指標

文献で繰り返し使われる検証シナリオは 4 つに収束している:

1. **基本図(fundamental diagram)** — 密度-速度/密度-流量。**最重要**。一方向流で測る。
2. **ボトルネック流** — 開口幅と流量(specific flow)の関係、開口手前のアーチ形成。
3. **対向流のレーン形成** — 双方向流での自発的なレーン(帯)の生成。
4. **交差流** — 直交する流れの相互作用(ストライプ形成)。

定量指標は **流量(人/s)・specific flow(人/s/m)・密度(頭数/面積 または Voronoi 密度)・
速度分布**。密度は古典的な「測定矩形内の頭数 ÷ 面積」と、Steffen & Seyfried (2010) の
**Voronoi 法**(低密度でのばらつきを抑える)がある。本ベンチは古典法のみ実装した(限界は §8)。

**RiMEA**(Richtlinien für mikroskopische Entfluchtungsanalysen)は避難シミュレータ向けに
**15 個のテストケース**を附属書1に定め、附属書2に検証・妥当性確認の指針を置いている。
避難(egress)寄りなので今回の「常態の群衆流」には部分的にしか当たらないが、

## 3. 自前資産の実査(変更なし・読み取りのみ)

### 3.1 `src/society/world/sfm_core.py` — 開放領域の最小 SFM

- `Crowd`: 位置・速度・目標・希望速度を numpy 配列で保持し、**駆動項 + 対人斥力(全ペア O(N²)+カットオフ)**
  を前進 Euler で積分する。異方性重み `w = λ + (1−λ)(1+cosφ)/2` あり。
- パラメータは **Helbing2000(パニック版)の確定値**: `A=2000 N, B=0.08 m, τ=0.5 s, m=80 kg,
  r∈[0.25,0.35] m, v_max=1.3v₀`。
- **意図的に省いている項がコメントで明記されている**: (1) 対壁斥力、(2) 物理接触項(body force /
  sliding friction)。したがって超高密度の圧潰・faster-is-slower は対象外。
- 揺らぎ項 ξ は `noise=0.0` 既定で無効。`rng` は引数で受け取り内部 seed しない = **決定論の作りは正しい**。
- `SignalGate`: 歩行者信号の決定論ゲート(周期関数・乱数ゼロ)。`active=False` で赤待ち滞留 →
  青で一斉解放。**スクランブルの一斉横断はこの機構でそのまま作れる**(P3 で再利用可能)。

### 3.2 `src/society/world/indoor_flow.py` — 屋内拡張 `WallCrowd`

- `Crowd` を継承し、**壁斥力 `f_iW = A·exp((r_i − d_iW)/B)·n_iW`**(壁線分への最近点距離と法線・
  ベクトル化)、**近傍 cap(既定 12・距離昇順+index 昇順で決定論選択)**、
  **frozen(斥力源だが動かない静止者)** を追加する。
- 個体パラメータは `agent_id` の blake2b 安定ハッシュ由来
  (`desired_speed` → v₀∈[1.0,1.4) m/s、`body_radius` → r∈[0.25,0.35) m)。
  **run.seed 非依存でプロセスを跨いで同値** = 乱数 stream に無風。これは P3 でもそのまま使える。
- 経路は waypoint 連鎖 + 0.5 m グリッド BFS フォールバック。
- **屋外群衆流にそのまま使えるか → 使える。** 必要なのは
  「壁線分の配列」「目標点」「dt」だけで、屋内固有の前提(間取り・ドア)は
  `route_waypoints` / `integrate_transition` 側に閉じている。本ベンチは `WallCrowd` を
  そのまま(継承もモンキーパッチもせず)構築して屋外の通路・交差点に使えている。

### 3.3 実査で見つかった注意点(実測で示す・src は未変更)

**`WallCrowd.forces()` は `Crowd.forces()` を上書きしており、揺らぎ項 ξ を含まない。**
そのため **壁を使う経路では `noise` パラメータが完全に無効**になる。
ベンチで `noise=0` と `noise=2.0` を与えた 2 ランの軌跡ハッシュが**一致する**ことで実測確認した
(`results.json` の `engine_notes.wallcrowd_drops_fluctuation_xi`)。

これは「レーン形成の標準的な対称性の破れ機構(Helbing&Molnár1995 の ξ)が壁ありでは使えない」
ことを意味する。**バグと断定はしない**(屋内 10 分粒度の遷移では決定論優先の設計判断でありうる)。
ただし P3 で屋外の対向流を扱うなら、この点は設計判断として明示的に決め直す必要がある。

## 4. プロトタイプと実験設計

コードは `reference/physics_bench/`(再現手順は同ディレクトリの README)。

### 4.1 候補 (a) 自前 SFM

`indoor_flow.WallCrowd` を薄いラッパ(`engines.SfmEngine`)で包むだけ。**src は import のみ**。
較正感度を測るため、`WallCrowd`/`Crowd` のコンストラクタ引数(`a`, `b`, `tau`, `noise`, …)を
外から差し替えられる口(`solver_kw`)を**ベンチ側に**設けた。

### 4.2 候補 (b) 自前最小 ORCA

`reference/physics_bench/orca_min.py`。RVO2 `Agent.cpp` の
`computeNewVelocity` / `linearProgram1` / `linearProgram2` / `linearProgram3` の
数式・分岐条件・タイブレークをそのまま Python へ移植した(cut-off circle / left leg / right leg /
collision の 4 分岐、3 段 LP、`RVO_EPSILON=1e-5`)。

**意図的に変えた点(正直に):**
1. `float`(32bit)ではなく float64。決定論には無影響だが RVO2 C++ とのバイト一致は主張しない。
2. **静的障害物(壁)の扱いを簡略化**した。RVO2 の障害物 ORCA(線分の速度障害物・左右足・隣接障害物の
   凸性処理)は移植せず、「壁最近点までの距離 d と法線 n による半平面制約 `n·v ≥ (r−d)/τ_obst`」で代用。
   直線壁の通路ではほぼ等価だが、鋭角コーナー・薄い障害物では RVO2 と挙動が変わりうる。
3. kd-tree ではなく全ペア距離 + 上位 k 近傍(距離昇順・index 昇順タイブレーク)。N ≤ 200 では十分。

**移植の健全性チェック(実測):**
- 正面すれ違い(横オフセット 0.3 m)で最小中心間距離 **0.611 m ≥ 2r = 0.6 m** = 接触なしですれ違う。
- 壁に正対して歩かせると **y = 0.304 m**(= 半径 0.3 m + 数 mm)で静止する。
- **円周デッドロック試験(RVO2 定番のサークルデモ相当)**: 半径 10 m の円周に 16 体を等間隔に置き、
  全員が対蹠点を目指す(完全対称=最悪ケース)。結果:

  | `pref_noise` [m/s] | 到達数 (残距離<0.5m) | 最大残距離 | 最小中心間距離 |
  |---|---|---|---|
  | 0(揺らぎなし) | **0 / 16** | 11.54 m | 0.600(= 2r ちょうど) |
  | 0.0001 | 0 / 16 | 11.54 m | 0.600 |
  | 0.01 | 0 / 16 | 11.77 m | 0.600 |
  | **0.05** | **16 / 16** | 0.11 m | 0.576 |

  **衝突は一度も起きない**(最小中心間距離がちょうど 2r=0.6 m に張り付く = ORCA の制約が正しく効いている)
  が、**完全対称ではリング状にデッドロックして誰も進まない**。
  これは移植のバグではなく **ORCA の性質**で、**保証しているのは「衝突回避」であって「進捗」ではない**。
  RVO2 本家の例題 `examples/Blocks.cc` も希望速度に微小乱数を足しており、コメントに
  **"Perturb a little to avoid deadlocks due to perfect symmetry."** と明記されている。
  → **ORCA を採るなら symmetry-breaking の乱数は必須**(そして §5.1 のとおり seed 固定なら決定論は保てる)。

### 4.3 公平性のために揃えた条件

初期配置・希望速度 v₀∈[1.0,1.4) m/s・半径 r∈[0.25,0.35) m(いずれも `indoor_flow` の安定ハッシュ由来)、
近傍上限 12 体、最高速度 1.3·v₀、壁の線分集合、物理 dt、記録方法、指標の計算コード。

### 4.4 シナリオ

| ID | 内容 |
|---|---|
| A `fd_periodic` | **周期境界の一方向通路 20 m × 3 m**。周期像(ゴースト)を毎ステップ生成して厳密な周期性を作る。密度 0.2〜3.0 /m² を掃引 |
| B `counterflow` | **幅員違い通路の対向流 200 体**。幅 3 m × 長 60 m と 幅 6 m × 長 30 m(**面密度を 1.11 /m² に揃えた**)。加えて幅 3 m で密度掃引(40/80/120/200 体) |

**確率項と決定論は両立する。** `orca_min` の `pref_noise`(希望速度への微小ゆらぎ)を

必要はない(R1 の「乱数は用途別専用 stream」の枠内で扱える)。

### 5.2 評価軸④ 速度 — **両候補とも十分。差はつかない**

200 体・dt=0.1 s の実測(単一コア・純 Python/numpy):

| シナリオ | 候補 | agent·step/s | 実時間倍率(sim秒/実秒) | 200体×1時間の実時間 @dt=0.1 | 同 @dt=0.05 | 同 @dt=0.02(換算) |
|---|---|---|---|---|---|---|
| 対向流 幅3m | SFM | 38,112 | 19.1× | 189 s | 378 s | 945 s |
| 対向流 幅3m | ORCA | 57,344 | 28.7× | 126 s | 251 s | 628 s |
| 交差流 | SFM | 37,586 | 18.8× | 192 s | 383 s | 958 s |
| 交差流 | ORCA | 66,999 | 33.5× | 108 s | 215 s | 537 s |

ORCA が SFM より 1.5〜1.8 倍速い(SFM 側は毎ステップ `WallCrowd` を作り直すベンチ実装のオーバーヘッドを
含むので、本番実装ではもう少し詰まる)。

**逆算した目標倍率との突合**: 現行ランは 1 step = 10 分(600 sim 秒)。
1 日分(144 step = 86,400 sim 秒)の物理を **200 体・1 領域で通しで回す**と:

| | dt=0.1 | dt=0.05 | dt=0.02 |
|---|---|---|---|
| SFM | 約 76 分 | 約 2.5 時間 | 約 6.3 時間 |
| ORCA | 約 50 分 | 約 1.7 時間 | 約 4.2 時間 |

**物理は常時ではなく「領域内に人がいる時間帯だけ」回す設計(P3 の空間 LOD)なら十分間に合う**
(スクランブル交差点が終日 200 体で埋まっているわけではない)。ただし
**§5.6 のとおり SFM は dt ≤ 0.05 s が要る**ので、上表の中列以降が現実的な見積りになります。
10 日ランで物理 ON にするなら、領域内滞在の実測分布から**先に総サブステップ数を見積もるべき**です。

→ **CPU で足りているので、JAX/GPU 案は再浮上させない**(「速度より決定論」の既定方針どおり)。

### 5.3 評価軸② 境界の縫いやすさ — **guarded ゲートが両候補で有効。ORCA の方が穏やか**

流入/流出ゲートを 2 方式で作り、幅 3 m 通路・200 体で比較した(dt=0.1、40 s)。

| 方式・候補 | ゲート帯 加速度 p99 [m/s²] | 内部 加速度 p99 | ゲート帯 立往生率 | 進行方向反転 [回/体/s] | ゲート帯 反転 | 最小体表間距離 [m] | 重なりペア率 | 1step 最大変位 [m] |
|---|---|---|---|---|---|---|---|---|
| blind · SFM | **14.25** | 5.63 | 0.018 | 0.613 | 0.749 | +0.024 | 0.000 | 0.182 |
| guarded · SFM | **9.34** | 5.72 | 0.076 | 0.654 | 0.695 | **+0.050** | 0.000 | 0.182 |
| blind · ORCA | **7.17** | 2.12 | 0.094 | 0.120 | 0.246 | **−0.207** | 0.0055 | 0.180 |
| guarded · ORCA | **5.15** | 2.18 | 0.011 | 0.122 | **0.123** | −0.074 | 0.0056 | 0.177 |

読み取れること:

1. **瞬間移動は起きていない**(1 step 最大変位 ≤ 0.182 m = v_max·dt = 1.82×0.1。全条件で理論上限どおり)。
   ゲートを跨ぐ step を除外して測っているので、**境界通過そのものが位置の不連続を生んでいない**。
2. **guarded(占有チェック + 退場速度の復元)は両候補でゲート帯の急加速を 1/3〜1/4 減らす**
   (SFM 14.25 → 9.34、ORCA 7.17 → 5.15)。ORCA では**ゲート帯の振動(方向反転)が半減**し
   (0.246 → 0.123)、**重なりの深さも 1/3 に改善**する(−0.207 m → −0.074 m)。
   → **P3 の境界プロトコルは「空いているときだけ入れる + 速度を引き継ぐ」で正しい。** 実測で裏づいた。
3. **SFM はゲート帯・内部を問わず加速度が ORCA の 2〜3 倍、方向反転が 5 倍**。
   これは A=2000 N・B=0.08 m の接触斥力が「ぶつかって弾かれる」動きを作るためで、
   **P3 の受入基準「境界で急停止・振動が出ないこと」に対して SFM の既定パラメータは不利**。
4. **重なり(体のめり込み)は逆転する**。SFM は硬い接触斥力のおかげで**重なりゼロ**(最小体表間 +0.05 m)、
   ORCA は離散時間 LP のため**わずかに重なる**(重なりペア率 0.55%、最深 −0.21 m)。
   ORCA は「連続時間では衝突しない」保証であって、離散 step + ゲート再投入では破れうる。

### 5.4 対向流(200 体・幅員違い)— **SFM はレーンを作る。ORCA はほぼ作らない**

幅 3 m × 長 60 m と 幅 6 m × 長 30 m。**面密度はどちらも 1.11 /m² に揃えた**(200 体)。
レーン秩序 φ は横断ビンの方向分離度(0=完全混合, 1=完全分離)で、**方向ラベルを無作為化した帰無値**を併記する。

| 条件 | 前進速度/v₀ | 前進速度 [m/s] | レーン秩序 φ | φ の帰無値 | 見かけの帯数 | 反転 [回/体/s] |
|---|---|---|---|---|---|---|
| 幅3m · SFM | 0.020 | 0.024 | 0.049 | 0.052 | 3.81 | 0.463 |
| 幅3m · ORCA | 0.073 | 0.086 | 0.026 | 0.030 | 3.29 | 0.129 |
| 幅6m · SFM | 0.264 | 0.313 | **0.323** | 0.093 | 2.39 | 0.761 |
| 幅6m · ORCA | 0.365 | 0.433 | 0.116 | 0.094 | 6.32 | 0.096 |

**幅 6 m では SFM だけが有意なレーン形成を示す**(φ=0.323 ≫ 帰無値 0.093、帯数 2.4 ≒ 2 レーン)。
ORCA は φ=0.116 ≒ 帰無値 0.094 で、**帯数 6.3 = 細切れ**=レーンではない。
一方 **流量は ORCA が上**(0.365 vs 0.264)。
つまり **「群衆らしい自己組織化」は SFM、「詰まらずに捌く」は ORCA** という綺麗な役割分担が出た。

**密度掃引(幅 3 m 固定)** — どこで詰まるかが実用上の分かれ目:

| 密度 [1/m²] | SFM 前進/v₀ | SFM φ (帰無値) | ORCA 前進/v₀ | ORCA φ (帰無値) |
|---|---|---|---|---|
| 0.22 (40体) | 0.875 | **0.860** (0.152) | 0.865 | 0.425 (0.200) |
| 0.44 (80体) | 0.483 | **0.465** (0.098) | **0.826** | 0.373 (0.115) |
| 0.67 (120体) | 0.370 | 0.269 (0.100) | **0.552** | 0.237 (0.123) |
| 1.11 (200体) | 0.020 | 0.049 (0.052) | 0.073 | 0.026 (0.030) |

- **低密度(0.22 /m²)では SFM が教科書どおりのレーンを作る**(φ=0.86、帰無値の 5.7 倍)。SFM を採る根拠として重い。
- **ORCA は詰まりにくい**(0.44 /m² で効率 0.83 を維持。SFM は 0.48 まで落ちる)が、レーンは弱い。
- **ρ ≈ 1.1 /m² の完全混合対向流ではどちらも事実上ゲート近傍から詰まる**(効率 0.02〜0.07)。
  **これは較正前の既定パラメータでの話**で、初期条件も「両方向が均一に混ざった状態」という
  実験室設定(両端に分けて置く)より厳しい条件である点は割り引いて読む必要がある。
  ただし**スクランブル交差点のピーク密度はこの領域**なので、P3/P4 の受入基準に直結する。

### 5.5 交差流(スクランブル風・200 体・壁なし)— **ORCA が明確に優位**

| 候補 | 平均速さ [m/s] | 速さ/v₀ | 最小体表間距離 [m] | 重なりペア率 | 反転 [回/体/s] | 内部 立往生率 |
|---|---|---|---|---|---|---|
| SFM | 0.628 | 0.530 | +0.004 | 0.000 | 0.681 | 0.165 |
| ORCA | **1.095** | **0.924** | −0.045 | 0.0005 | **0.139** | 0.003 |

4 方向交差では **ORCA がほぼ自由速度(効率 0.92)で滑らかに捌く**のに対し、
**SFM は効率 0.53・立往生 16.5%・方向反転 0.68 回/体/s** と振動しながら詰まる。
交差点(= P3 の主目標地形)では ORCA の速度障害物ベースの先読みが効いている。
軌跡プロット(`out/traj_crossing_orca.png` / `_sfm.png`)でも差は明瞭で、
ORCA は 4 方向がほぼ直進のまま互いをすり抜けるのに対し、**SFM は領域中央に渦状の滞留が生じ、
そこに巻き込まれた個体が長時間まわり続ける**(SFM の内部立往生率 16.5% の実体)。
これは既知の SFM の「回転する詰まり」で、接触斥力しか持たない(先読み回避がない)ことの帰結です。

### 5.6 評価軸③ 較正可能性 — **両候補とも既定では基本図に乗らない。動かせるのは SFM だけ**

#### (a) 基本図(周期一方向通路 20 m × 3 m・測定はランの後半 30〜60 秒)

シミュの平均希望速度は **v₀ = 1.133 m/s**(`indoor_flow.desired_speed` の一様分布 [1.0,1.4) の平均)。
Weidmann は自由速度 1.34 m/s なので、**自由速度を揃えた再スケール版**も併記する
(`v(ρ) = 1.133·[1−exp(−1.913(1/ρ − 1/5.4))]`)。

| ρ [1/m²] | SFM (dt=0.02) | ORCA (dt=0.02) | SFM (dt=0.1) | ORCA (dt=0.1) | Weidmann v_f=1.34 | Weidmann 再スケール |
|---|---|---|---|---|---|---|
| 0.2 | 1.124 | 1.133 | 1.124 | 1.133 | 1.340 | 1.133 |
| 0.5 | 1.131 | 1.165 | 1.130 | 1.165 | 1.298 | 1.129 |
| 1.0 | 1.077 | 1.186 | 1.073 | 1.189 | 1.058 | 0.936 |
| 1.5 | **0.698** | 1.161 | 0.648 | 1.157 | 0.807 | **0.704** |
| 2.0 | 0.766 | 1.141 | 0.382 | 1.154 | 0.606 | 0.534 |
| 3.0 | **0.976** | 0.444 | 0.083 | 0.878 | 0.331 | 0.293 |

読み取れること:

1. **SFM(dt=0.02)は ρ=1.5 で再スケール Weidmann と 1% 以内で一致する**(0.698 vs 0.704)。
   しかし **ρ を上げると速度が再び上がる**(0.766 @2.0 → 0.976 @3.0)。
   **基本図が非単調** = 「混むほど速くなる」という非物理。原因は B=0.08 m の接触斥力が
   異方性重み付きで**前方から押し返すより後方から押し出す方が強く効く**ためで、
   高密度では結晶状に詰まった群れが一体で流れてしまう。
   **これは較正で直せる種類のずれではない**(パラメータではなくモデル項の不足)。
2. **ORCA は ρ=2 まで自由速度のまま**(1.14〜1.19)。一方向流では速度が互いに矛盾しないので
   ORCA には「混んだら遅くする」機構が原理的に無い。ρ=3 で急に 0.444 に落ちる(段差特性)。
3. **dt=0.1 の SFM が一見 Weidmann に近い(ρ=3 で 0.083)のは見かけだけ**。
   同条件の速さ |v| は 1.092 m/s(§5.6(c))で、**前進していないだけで激しく横揺れしている**。
   「遅い」のではなく「churn(かき混ぜ)している」。**数値の一致を較正の成功と誤読してはいけない。**

#### (b) 高密度の初期過渡(SFM 固有の問題)

1 秒窓ごとの平均前進速度の**最小値**(負なら群れが平均として後退している):

| ρ | SFM dt=0.02 | SFM dt=0.05 | SFM dt=0.1 | ORCA dt=0.02 | ORCA dt=0.1 |
|---|---|---|---|---|---|
| 1.0 | +1.018 | +1.018 | +1.015 | +1.183 | +1.180 |
| 1.5 | +0.473 | — | +0.393 | +0.986 | +1.119 |
| 2.0 | **−1.043** | — | **−0.688** | +0.073 | +0.980 |
| 3.0 | **−1.416** | −1.402 | −0.359 | −0.004 | +0.745 |

**ρ ≥ 2 /m² で SFM は初期数秒間、群れ全体を毎秒 1 m 以上「後方へ吹き飛ばす」**。
これは初期配置(重なりなし・希望速度で発進)から指数斥力 A=2000 N が一斉に爆発するためで、
**dt を小さくしても消えない**(dt=0.02 でも −1.42)。P3 で流入ゲートから人を入れ続ける運用では
この過渡が**毎回のゲート通過ごとに小さく再発する**恐れがあり、§5.3 の「SFM のゲート帯加速度が
ORCA の 2 倍」はその現れです。

#### (c) 積分 dt の感度(同じ密度で dt だけ振る・測定はラン後半)

前進速度 v と速さ |v| が乖離していたら「進まずにかき混ぜている」= 数値的破綻のサイン。

| 条件 | dt=0.02 | dt=0.05 | dt=0.1 | dt=0.2 | dt=0.5 |
|---|---|---|---|---|---|
| SFM ρ=1.0 (v / \|v\|) | 1.077 / 1.077 | 1.074 / 1.074 | 1.073 / 1.073 | **0.662 / 1.182** | **1.130 / 1.186** |
| SFM ρ=3.0 (v / \|v\|) | 0.976 / 0.977 | 0.938 / 0.938 | **0.083 / 1.092** | **0.602 / 1.288** | **0.918 / 1.254** |
| ORCA ρ=1.0 | 1.186 / 1.186 | 1.178 / 1.178 | 1.189 / 1.189 | 1.183 / 1.183 | 1.174 / 1.174 |
| ORCA ρ=3.0 | 0.444 / 0.531 | 0.255 / 0.300 | 0.878 / 0.881 | 1.067 / 1.067 | 1.200 / 1.200 |

- **SFM は ρ=1 なら dt ≤ 0.1 で収束**するが、**ρ=3 では dt=0.1 で破綻**(v≪|v|)。
  **スクランブル相当密度で使うなら dt ≤ 0.05 s が必要**。
  → 指示書の「物理 dt 0.1〜0.5 秒」は、既定パラメータの SFM では**低密度でしか成立しない**。
- **ORCA は数値的には壊れない**(常に v ≈ |v|)が、**混雑時の速度が dt に強く依存する**
  (ρ=3 で dt=0.5 の 1.200 から dt=0.05 の 0.255 まで 5 倍の幅)。
  つまり ORCA では **dt が事実上の較正パラメータになってしまう** = 物理量による較正ができない。

#### (d) パラメータ感度(較正のレバーがあるか。dt=0.02・測定はラン後半)

| パラメータ集合 | ρ=1.0 | ρ=2.0 | ρ=3.0 |
|---|---|---|---|
| **Weidmann (v_f=1.34)** | **1.058** | **0.606** | **0.331** |
| SFM 既定 (A=2000, B=0.08) | 1.080 | 0.745 | 0.971 |
| SFM Helbing&Molnár1995 相当 (A=560, B=0.3) | 0.584 | 0.410 | 0.778 |
| SFM B だけ 0.3 に伸ばす | 0.500 | 0.917 | 0.925 |
| SFM A=500, B=0.6 | **−0.106** | 0.760 | 0.794 |
| SFM τ=1.0(反応を鈍く) | 1.035 | 0.688 | 0.922 |
| ORCA 既定 (τ=2) | 1.187 | 1.139 | 0.289 |
| ORCA τ=4 | 1.193 | 1.127 | **−0.012** |
| ORCA τ=8 | 1.184 | 1.090 | 0.626 |
| ORCA τ=4 + 半径 ×1.3 | 1.156 | **−0.274** | −0.011 |

- **SFM のノブは効く**。ρ=1 で 1.080 → 0.584 → 0.500 → −0.106 と、**1.2 m/s 幅で動く**。
  「較正できる構造か」という問いには **Yes** と答えられる。
  ただし**どの集合も高密度で単調にならない**ので、A・B の探索だけでは Weidmann に乗らない
  → §7.2 の条件 C(密度依存 v₀)が要る。
- **ORCA のノブはほとんど効かない**。ρ=1〜2 で τ を 2→8 に 4 倍しても 1.19→1.09 しか動かない。
  唯一効く半径は、動かすと**一気にデッドロック側へ落ちる**(ρ=2 で 1.139 → −0.274)。
  **連続的な合わせ込みができない** → 較正可能性は **No**。

## 7. 推奨案(**ユーザー承認事項**・断定ではありません)

### 7.1 推奨: 自前 SFM を主候補とする

理由を重み順に:

1. **評価軸①(最重視)で差がつかなかった。** ORCA の「決定論を取りやすい」という優位は、
   実測してみると SFM でも同等に達成できていた(既に strict 等級で作られているため)。
   したがって**軸①は選定根拠にならない**。
2. **評価軸④でも差がつかなかった。** ORCA が 1.5〜1.8 倍速いが、物理領域を空間 LOD で限定する P3 の設計では
   本質的な差ではない。**「GPU は vLLM 専用」の方針を変える理由も生じなかった**(JAX 案は再浮上させない)。
3. **評価軸③(較正可能性)で SFM が優位。** P4 は「物理層を私の手癖ではなく外部の実測に釘付けする」
   工程であり、**パラメータが基本図を動かさないエンジンは P4 を実行できない**。
   ORCA の τ・半径は基本図をほとんど動かさず、動くときは段差的にデッドロックへ落ちる。
   SFM は A・B・τ・v₀ が効き、しかも物理量として解釈できる。
4. **評価軸⑤で SFM が圧倒的。** SFM は**既にリポジトリにあり、屋内フローで実運用され、テストがある**。
   ORCA を採るなら (i) ビルドツールチェーン導入 + RVO2 バインディングのビルド(Windows での
   動作報告は限定的)か、(ii) 本ベンチの 400 行移植を本番品質へ引き上げて**自分たちで保守する**か。
   **8/9 の P3 完了ゲートまでの日数を考えると、後者は現実的な追加リスク**です。
5. **レーン形成という「見せ場」を作れるのは SFM の方**(φ=0.86 vs 0.43、軌跡図でも一目瞭然)。

### 7.2 ただし採用には 3 つの前提条件がつく(これが本書の実質的な提案)

**条件 A: 物理 dt を 0.02〜0.05 s にする。** 指示書の「dt 0.1〜0.5 s」は既定パラメータの SFM では
スクランブル相当密度で成立しません(§5.6(c))。ρ=3 /m²・dt=0.1 s では前進 0.083 m/s に対し |v|=1.09 m/s、
すなわち**進まずにかき混ぜているだけ**の状態になります。dt ≤ 0.05 s で v ≈ |v| に戻ります。
**世界 tick との比は整数に固定**(P3 の時間整合)したまま、比を大きく取る必要があります。
コストは §5.2 の表のとおり(dt=0.02 なら 200 体×1 時間で 約 10〜16 分、1 日通しで 4〜6 時間)。

**条件 B: 斥力パラメータを通常歩行域へ振り直す。**
現行は Helbing2000 の *escape-panic* 値(A=2000 N, B=0.08 m)で、**接触するまで何も起きない**
超短距離斥力です。通常歩行の先読み回避には Helbing&Molnár1995 系(σ≈0.3 m)の長い相互作用距離が要ります。
**ただし本ベンチの実測では、単純な振り直しでは合いませんでした**(§5.6(d))。
A=560/B=0.3 は ρ=1 で 0.584 m/s(Weidmann 1.058 に対し遅すぎ)、ρ=3 で 0.778 m/s(0.331 に対し速すぎ)と、
**低密度で遅すぎ・高密度で速すぎ**という逆傾斜になります。A・B の 2 次元探索 + dt の 3 変数最適化が P4 の主作業です。

**条件 C: それでも基本図が合わなければ、密度依存の希望速度 v₀(ρ) を外付けする。**
「近傍密度が上がったら希望速度そのものを下げる」項を較正テーブルとして持つ方式です。
これは SFM の純度を落としますが、**P4 の目的(外部実測への釘付け)には最短**で、
指示書 P3(4) の「写像テーブルを外部化しハッシュを manifest に載せる」枠にそのまま乗ります。

### 7.3 ORCA は採らないが捨てない

- **交差流(スクランブルそのもの)では ORCA が明確に上**(効率 0.92 vs 0.53、方向反転 1/5)。
- **境界縫合も ORCA の方が穏やか**(ゲート帯加速度が約半分)。
- したがって、もし P3 の実装後に「スクランブル領域だけ挙動が破綻する」となった場合の
  **第一の代替案は ORCA**です。本ベンチのコードはそのために残してあります。
- **将来のハイブリッド案**: 駆動項と較正は SFM のまま、対人回避だけ ORCA の速度制約に差し替える
  (= 力ではなく速度で避ける)。基本図の較正しやすさと交差流の滑らかさを両取りできる可能性がある。
  ただし**これは新規研究に近く、本選(8/15)までにやることではありません**。

### 7.4 P3 へ持ち越す実装上の指針(実測で裏づいたもの)

1. **境界プロトコルは guarded にする**(空いているときだけ入場・退場時の速度を復元)。
   実測でゲート帯の急加速が 1/3〜1/4、振動が半減しました。
2. **symmetry-breaking の揺らぎを「専用 stream の乱数」として入れる**。
   決定論とは両立します(§5.1・§4.2 の円周試験)。
   **注意**: 現行の `WallCrowd` は `Crowd.forces()` を上書きしていて揺らぎ項 ξ を落としているため、
   壁ありでは `noise` が効きません(§3.3 で実測)。P3 で明示的に決め直してください。
3. **物理領域の受入基準に「密度 ρ に対する平均速度が Weidmann 曲線の ±X% に入ること」を入れる**。
   「詰まらないこと」を目視でなく数値で縛らないと、較正前の既定パラメータでは ρ≈1 /m² で詰まります。
4. **1 step 変位の上限(v_max·dt)を不変条件としてテストに固定する**。本ベンチでは全条件で
   理論上限どおりで、瞬間移動が起きていないことの機械的な証明になっています。

## 8. 既知の限界(この比較で言えないこと)

1. **ORCA 候補は RVO2 本体ではなく自前移植**。式は忠実に写したが、
   障害物処理は半平面近似で、RVO2 の `float` 演算とのバイト一致も主張していない。
   **「RVO2 を入れたらこうなる」の証拠にはならない**(「ORCA というアルゴリズムはこうなる」の証拠まで)。
2. **ボトルネック(定番シナリオ②)を実装していない。** 開口幅 vs specific flow の検証は未実施。
   P4 で追加すべき(RiMEA 的な要素試験としても価値が高い)。
3. **密度は古典法(測定矩形内の頭数/面積)**。Voronoi 法(Steffen & Seyfried 2010)を使っていないため、
   低密度・小面積での散らばりは大きい。基本図の絶対値は ±10% 程度の幅で読むべき。
4. **対向流の初期条件は「両方向が均一に混ざった状態」**。実験室の標準設定(両端に分けて置く)より
   厳しく、レーン形成には不利。**実験値との直接比較には使えない**(候補間の相対比較には使える)。
5. **実データとの突合をしていない。** Weidmann の解析曲線と重ねただけで、
   Jülich のデータアーカイブの生軌跡とは比較していない。これは P4 の仕事。
6. **交差流のストライプ形成を定量化していない**(速度効率・重なり・振動のみ)。
7. **スループットは同一マシンで並行して別のテストスイートが走っている状態でも測った**。
   2 回の実行で SFM 35.8k → 38.1k、ORCA 46.2k → 57.3k agent·step/s と 6〜24% ぶれており、
   **絶対値は ±25% 程度の幅で読むべき**。候補間の比較は同条件なので有効。
8. **本ベンチは物理層単体**。LLM 呼び出し・認知イベント・グラフ世界との実結合(P3)は一切含まない。
