## 1. 経緯 — 何を問い、何が返ってきたか

### 1.1 出発点の疑問(設計者)

世界2.0の生態系論(立ち上げ手順・熱中させる仕掛け・出入りによる新陳代謝)は、
**参加者が自由に出入りできる開かれたコミュニティ**を前提にしている。
しかし本シミュレーションは:

- エージェントは**半ば強制的に参加**しており、退出も新規参入もない閉じた世界である
- 各エージェントには**ペルソナ(職業・性格・所属など)を最初から与えている**

この前提の違いから二つの問いを立てた:

- **Q1**: 閉じた世界でも「生態系の立ち上げ」「熱狂」は成立するか。この前提で足りないものは何か。
- **Q2**: 設計を世界2.0の前提(出入り自由・ペルソナ最小化・素のLLMの思考を反映)に
  寄せるべきか。役割は本来コミュニティ参加の中で自然獲得されるものであり、
  最初から役を演じさせるペルソナは創発を潰すのではないか。

### 1.2 外部アドバイス(AI佐藤)の回答要旨

- 閉じた世界でも立ち上げ・熱狂は**成立する**。開かれた世界の原動力が「選択の自由による
  流動性」であるのに対し、閉じた世界の原動力は「逃げ場のない濃密な相互作用」
  (衝突・依存・合意形成の不可避性)。
- 足りないのは、関係性の固定化を防ぐ「環境の揺らぎ」「外部的な共通の危機」など、
  **内部のパワーバランスを強制的に変化させるトリガー(火種)**。
- Q2への回答: **現在の「閉じた世界+ペルソナ」の方が本質に近い**。現実の人間も
  与えられた配役を背負い、リセットできない閉じた社会を生きている。役割があるからこそ
  葛藤と合意が生まれ、調整役としてのリーダーが自然発生する。開かれた世界の実験は
  コミュニティの「マーケティング」のシミュレーションであり、泥臭い「組織形成」の再現には
  閉じた設計が適する。**切り分け不要、今の設計を研ぎ澄ますべき**。

### 1.3 検討の結果、設計者が採った立場

- **設計は維持**: 閉じた世界+ペルソナを維持する。組織形成・リーダー創発の観察という
  目的に対して、この設計は妥協ではなく積極的に適している(佐藤回答に同意)。
- **危機トリガーは入れない**: アドバイスのうち「パワーバランスを強制変化させるトリガー」は
  **採用しない**。理由: (a) それはコミュニティ運営者のレシピであり、本研究の課題は
  「盛り上げること」ではなく「日常から何が生まれるかを観ること」。強制トリガーを入れると
  観測された社会変動が日常からの創発か運営者の地震の余波か区別できなくなる=指紋になる。
  (b) 日常はすでに揺らぎに満ちている(欠品波及・交通遅延・天候・寄り道・中断修復・
  関係の風化)。現実のパワーバランスも大事件ではなく小さな日常の積み重ねで変わる。
  「強制トリガーなしで社会構造は変化するのか、固着するのか」自体が一級の研究課題。
- **日常スケールの観察**: 現実の日常の世界の中でのシミュレーションを軸にする。
  観察日数の目安は下記タスクC参照。
- **ペルソナへの疑いは観測項目として保持**: 設計は維持するが、「注入されたペルソナへの
  従順さが逸脱(world-changerの芽)を抑制していないか」は手放さず、観測レンズとして
  実装する(下記タスクA)。人間の配役は成育過程で獲得されたもの、LLMのペルソナは
  注入されたもの、という差異は正直に認識しておく。

## 2. 前回実装指示への修正

### 2.1 タスク5(spark treatment)の縮退

前回指示のタスク5(火種介入の実験条件化)は、**本方針では優先度を下げ、既定の実験
プロトコルから外す**。実装済み・実装中の場合もconf既定OFFのまま凍結し、削除はしない
(将来「介入あり/なし比較」を回す選択肢として保持)。plans/finals-day1-decisions.md の
D項目に「spark系条件は既定で回さない。日常ベースライン優先」と追記すること。

危機ショックの追加treatment化(共通の危機の注入)も**行わない**。既存の外生ショック
機構(shock_closure等)はそのまま残すが、社会実験の道具として強度・頻度を上げる
方向の拡張はしない。

### 2.2 タスク1〜4・6は継続

価値3分類の観測レンズ、3M観測ビュー、不確実性監査、自助affordance、信用可視化は
本方針と矛盾しない(すべて観測系または受動的affordance)ため、そのまま進める。

## 3. 新規実装タスク

全タスク、R1ドクトリン(既定OFF=ゴールデンL1バイト一致・専用RNG stream・
LLM呼数k非依存・no-fingerprint・正直さ)を厳守すること。

### タスクA: ペルソナ逸脱率のobservable

**目的**: エージェントが与えられたペルソナにどれだけ従順か/逸脱するかを測る。
逸脱がゼロに近いなら、それ自体が本シミュレーションの限界を語るデータになる。
world-changer検出(k\*測定)の感度に関わる補助指標。

**実装内容**:

1. observer層に、ペルソナ記述(職業・性格タグ・趣味・価値タグ)と実際の行動列の
   乖離を測る指標を追加する。例: 職業と滞在POIカテゴリの不一致率、性格タグ
   (内向/外向等)と社交イベント頻度の乖離、趣味タグと余暇行動の不一致。
   分類はconf側の静的マッピング表で定義し、engine層にペルソナ語を書かない。
2. L2に住民ごとの「逸脱スコア」と全体分布(平均・分散・上位逸脱者)を載せる。
3. 逸脱スコアと自由度kの関係(kを上げると逸脱が増えるか)を集計できるようにする。
   これはR²(k)の解釈材料になる。
4. ダッシュボードに逸脱分布と「最も逸脱した住民」のドリルダウンを追加する。

**やらないこと**: 逸脱を促進・抑制する介入。観測のみ。

### タスクB: 日常内生変動のobservable(社会構造の自然変化の検出)

**目的**: 「強制トリガーなしで社会構造は変化するのか、固着するのか」を正面から測る。
佐藤アドバイスの「関係性の固定化」が実際に起きるかを、介入せずに観測する。

**実装内容**:

1. 関係グラフの時系列変化指標をL2に追加: edge組み替え率(日次の新規形成/断絶/
   風化の割合)、コミュニティ検出(既存関係台帳へのLouvain等の決定論適用)の
   クラスタ構成の日次変化、中心性ランキングの入れ替わり率。
2. 地位・評判ランキングの順位相関(前日比・前週比のKendall τ等)をL2に追加し、
   「ヒエラルキーの固着度」を定量化する。
3. 固着検知: 上記指標が閾値以下で連続N日推移したら「構造固着」フラグをL2に記録
   (アラートではなく観測記録。介入はしない)。
4. ダッシュボードに「社会構造の変化」タブ: 組み替え率の時系列、固着期間の可視化、
   順位入れ替わりのレースチャート。

### タスクC: 長期日常ラン(30日級)のプロトコル整備

**目的**: 日常観察に必要な時間スケールを確保する実行プロトコルを用意する。
観察スケールの目安: 7日=日常の最小単位(平日/週末1周)、14〜30日=関係性の変化
(深化・風化・常連化・語彙定着)、60〜90日=組織形成・リーダー成立などの構造変化。
方針「人数>時間」との折衷として、**k\*測定は7〜14日、構造創発観察は1条件のみ
30日以上の長期ラン(人数は絞ってよい)**の二段構えとする。

**実装内容**:

1. 長期ラン用profileをconfに追加(例: profiles/longrun-30d): 人数を数百規模に絞り、
   30日(4,320step)を回す構成。checkpoint/resume前提で分割実行できること
   (既存のresume=バイト一致保証を利用)。
2. 30日ランに耐える観測の間引き設定: L1は全量保持しつつ、ダッシュボード向け
   集計の日次ロールアップが30日分でも軽く読めることを確認する(必要なら
   L2の週次集計を追加)。
3. タスクBの指標が30日ランで意味を持つことを合成データまたは短縮ランで検証する。
4. 実行時間・ストレージの見積もりをresearch配下に記録し、本選GPU予算のD判断
   材料に加える(plans/finals-day1-decisions.mdに「長期日常ラン1条件を確保するか」を
   D項目として追記)。
